# v0.7.96.0 — Live Map: Players and Bases Work Out of the Box

## Context

Reported: "i did supply the world maps ... there should be functionality to show where the user is on the
map and bases." The functionality existed (live player dots since v0.6.16.0, base markers and click-to-
select since v0.7.92.0), but a user could not find it and, once found, it was wrong:

- The World Map card was collapsed on the Players page, there was no background until a preset was picked,
  and real positions plus base markers sat behind an opt-in "Experimental" checkbox that only appeared with
  the Palpagos preset selected. Without it the map spreads dots relative to whoever is online, which says
  nothing about real geography.
- The world-to-image conversion assumed the pre-expansion frame (a +/-1000 square centred on the image).
  The bundled image is the expanded map including Feybreak, so even with the box ticked the dots would have
  been drawn in the wrong place.

## What changed

- **Calibrated the image mapping** (`PalworldMapCoordinates`). Stage 1, world to in-game map units, is
  unchanged (its own gate still recomputes the source project's worked example). Stage 2 now maps map
  units to a pixel of the 1024x1024 image: about 3.08 units per pixel, in-game origin (0, 0) near pixel
  (625, 335), north up. See "How it was calibrated".
- **On by default**: real-world positions and base markers are on whenever the Palpagos map is the
  background; the checkbox stays as an off switch (relabelled, no longer "Experimental").
- **Discoverable**: the card is expanded by default and a first run starts on the bundled Palpagos map. A
  saved choice is respected, including a deliberate Clear Background (a saved empty preference).
- **Bases without a second request**: the Players page's own explorer read already carries base locations,
  so they are applied from it (`ApplyBaseLocations`); Refresh Bases still re-reads on demand.
- **Says what it shows**: a status line under the map, e.g. "No players are online, or the server is
  stopped, so there are no player dots. 2 base(s) shown from the world save." Bases come from the world
  save, so they draw even while the server is stopped.

## How it was calibrated

The first attempt (checking positions against a land/ocean mask of the image) proved nothing: with free
offsets every axis arrangement finds somewhere to land, and the natural north-up orientation put every
real point in open ocean under both the old constants and the published expanded bounds. That was
reported as unverified rather than shipped as verified. The missing piece was one real anchor:

- The default starting location (the Plateau of Beginnings) is documented at in-game (240, -513). The
  world's first base converts, with the existing formula, to (248, -495), and the user confirmed the base
  is right by the start location. That confirms stage 1 and the north-up, east-right reading.
- Feybreak's documented extent (map X -1456..-608, Y -1743..-798) spans about 276 x 307 image pixels,
  which fixes the scale near 3.08 units per pixel and roughly fixes the origin.
- A fine search near that origin (all 53 real character positions, bases inland) settled the origin at
  about (625, 335): 100% of the positions land on land and the bases sit roughly 7 px inland.
- Overlay check: with this mapping the start location falls on the same peninsula as the first base, the
  second base is on the neighbouring southern island, and the recorded travel trail runs from the start
  toward the Small Settlement ruins.

Accuracy is a few pixels of the 1024 frame (a few hundred metres in-world): "the right spot on the map",
not survey grade. Only one settlement was available to check against. If a game update moves the map,
only the constants at the top of `PalworldMapCoordinates` change.

## Scope notes

- Only the Palpagos preset is calibrated. The World Tree preset and user-browsed images keep the
  relative-spread view, with a hint telling the user how to get real positions.
- Player dots still come from the running server's REST API (nobody online or server stopped means no
  dots). Showing last-known positions of offline players would need the player save decoded further and is
  not part of this version. Pal positions are still not shown.
- Palworld's vanilla RCON has no teleport-to-coordinates command, so clicking the map can still only
  select a player for the existing Teleport To Me / Teleport To Player actions.

## Verification

- Solution and Desktop builds clean, 0 warnings/errors.
- Logic harness: 3 new scenarios pass. The conversion scenario asserts the real base converts to (248, -495),
  the start plateau maps to about (0.686, 0.490) of the image with the base within 1% of it, north is drawn
  up and east right, and Feybreak's corner lands in the south-west; plus clamping and the status text.
  `PalworldMapCoordinates.cs` and `MapContentsText.cs` are compiled directly into the harness.
- **NOT verified:** the rendered card. There is no GUI automation here, so what the map looks like on
  screen (dots over the image, the expanded card, the status line) was checked through the overlay of the
  same mapping on the same image and through code and binding review, not by looking at the running app.
