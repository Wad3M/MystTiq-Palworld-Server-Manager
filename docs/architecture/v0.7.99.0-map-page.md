# v0.7.99.0 — Dedicated Map Page Under World

## Context

Reported twice: the user supplied the world maps, could not find where players and bases are shown, and
asked "is it under World?" The answer was no: there was no Map page. The live map was a card on the Players
page (moved there in v0.6.16.0 and only ever expanded by default from v0.7.96.0), so it was easy to miss.

## What changed

- **A Map page in the World group**, after Inspector, Players, Bases and Guilds, with its own icon (a map pin
  in the same glossy-sphere style as its neighbours). The map card moved off the Players page, which now shows
  a pointer with an Open Map button, so there is one place for the map rather than two copies to keep in step.
- **Map first, controls beside it.** The first layout put the long controls card above the map and pushed the
  map below the fold, on a page whose whole job is the map. The map is on the left at 560 px (fits a 1100 px
  window without scrolling); presets, background choice, the real-world-positions switch and status lines are
  on the right, then the players list (click a name to select, with Teleport To Me / Teleport To Player) and a
  Guild bases list.
- **In-game coordinates** in the lists and tooltips ("MystTik (248, -495)"), as the game's own map shows them
  (`PalworldMapCoordinates.Describe`, which also avoids printing negative zero as "-0").
- The page loads the same live players and base locations as the Players page (`RefreshPlayersPageAsync`),
  and reloads when switching tabs while it is open. `Map` is appended to the end of the page enum rather than
  inserted, so a page remembered by number keeps its meaning.

## Bugs found by looking at the running app

This version is the first where the UI was actually looked at instead of only reviewed as code, by capturing
the app's window and driving it with synthetic clicks (see Verification). Two long-standing bugs surfaced:

1. **Every map marker was drawn in the top-left corner** since base markers and player dots were first built
   (v0.6.16.0 / v0.7.92.0). `Canvas.Left` and `Canvas.Top` on a template root, and a container style targeting
   the presenter, did not position them. Markers now sit in a Grid layer and are positioned by a margin taken
   from their data (`MarkerMargin`). This also means the v0.7.96.0 map calibration had never been seen on
   screen until now.
2. **Marker shapes were centred in the wider label under them**, which put a base marker about 9 canvas units
   (15 screen pixels) east of its point. The shape is now left-aligned so its centre lands on the point.

The calibration itself held up: with both fixed, the Default Server's first base sits on the east end of the
start peninsula and the second on the neighbouring southern island, as the overlay in v0.7.96.0 predicted.

## Deliberately not done

- No click-to-teleport-to-a-spot: Palworld's vanilla RCON has no teleport-to-coordinates command, so the map can
  still only select a player.
- No last-known positions for offline players and no Pal positions.
- The World Tree preset and user-browsed images stay on the relative-spread view (only Palpagos is calibrated).

## Verification

- Solution and Desktop builds clean, 0 warnings/errors (compiled bindings validate every new binding).
- Logic harness: 1 new scenario (coordinate description, including the origin and negative-zero cases).
- **Rendered and driven live.** The published app was launched, its window captured, and clicked through
  World, Map, and (for real data) a tab on the "Palworld Server 2 (Clone)" profile, which holds a copy of the
  real world. Confirmed on screen: the Map entry and icon in the World group; the page title and ribbon
  group; the Palpagos map loading by default; the status lines (including "2 base(s) shown from the world
  save"); the base list reading (248, -495) and (144, -569); both bases drawn on land at the start peninsula
  and the southern island after the two fixes above; the map fitting the window; the Players page pointer.
  Also confirmed on screen for the first time: the v0.7.98.0 Doctor findings (disk, memory, backup freshness,
  admin access, recent crashes) and the v0.7.97.0 Crash Analyzer page's empty state.
- **NOT verified on screen:** player dots. No player was online (the server was stopped), so only base markers
  were seen. Player dots use the identical Grid-and-margin mechanism and the same left-aligned shape, but
  were not observed. The Crash Analyzer's finding detail pane was not seen with data either.
