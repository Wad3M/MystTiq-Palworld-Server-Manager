# v1.0.8.7 — Notifications, Alert Center, Automation and Activity (internal)

Roadmap C-7, with the mover from C-2.

## AlertsViewModel (`vm.Alerts`)

**What moved:**
- the Notifications page: the list, filters, read, pin, dismiss, self-test and export;
- the Alert Center: rules, disk-space prediction, mute, the delivery pause, the test notification, and the send queue;
- delivery health: the Dashboard's warning and the Delivery card (the former `MainWindowViewModel.Delivery.cs`);
- the Automation page: rules, runs, create, delete, enable and run now;
- the Activity page: the lines, filters and export;
- the Discord bot settings and role mappings.

The page's own name, Alerts, avoids a clash with its `Notifications` list.

**What stays with the window:** a notification's repair link (`OpenNotificationLink`), which focuses Server Doctor on the
finding before it navigates.

**The Players page** reaches the activity refresh through `() => Alerts!.RefreshActivityAsync()`, because it is created
before the Alerts page.

## Found while moving

**String literals.** The mover rewrote a moved name inside a string: the Ribbon group titled "Notifications" became
"Alerts.Notifications", which the ArtworkHarness caught. An audit of every window file found no other case
(interpolation holes such as `{Workspace.WorldSizeText}` are code and correct). The mover now leaves plain string
literals alone.

**XAML paths of another page.** The Alerts page has its own `ActivityLines`, and the mover turned the Dashboard's
`Dashboard.ActivityLines` binding into `Dashboard.Alerts.ActivityLines`; the compiled bindings rejected it. The XAML
rewrite now follows a `.` only after `DataContext`.

**`ActiveTab`** in moved code now goes through the session.
