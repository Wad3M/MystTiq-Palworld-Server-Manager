# v0.8.26.0 — Repository clean-up and live acceptance scripts

## Why

The repository still carried the legacy WPF app (`src/PalworldManager`), its Inno Setup installer and the scripts
that built and packaged it, although the product has been `MystTiq.Desktop` + `MystTiq.HeadlessHost` +
`MystTiq.Core` for many versions. It also carried about 360 old per-version tests the release gate no longer ran,
565 pre-0.8 change lists and test plans, and working-tree leftovers. Some of this broke the GitHub build (a stale
`LinuxHeadlessSupervisor.cs` in git that the checkpoints no longer had), and the rest made it hard to see what the
product is. The user asked for every file to be checked and brought to v0.8.26.0, for old files to be removed, and for
publishing instructions. Separately, the checks that needed a person (a real Linux desktop, a player in the game,
real alert channels, Windows contrast themes) were still manual.

## What was removed, and how it was chosen

A clean-up script (kept with the v0.8.26.0 checkpoint archive, not in the repository) chose the removals; the full list with a reason per
entry is in [`docs/release/FILE_AUDIT_v0.8.26.0.md`](../release/FILE_AUDIT_v0.8.26.0.md). Everything removed stays in
the git history and in the v0.8.25.0 checkpoint archive.

- **The legacy app and what only served it:** `src/PalworldManager`, `installer/`, `Build-Installer.ps1`,
  `Install-InnoSetup.ps1`, `Package-Portable.ps1`, the v0.3 one-off clean-up scripts, the two "install the full source
  from Downloads" scripts (git replaced them), the WPF-to-Avalonia parity notes (`docs/GUI_*.md`,
  `docs/reconstruction`) and superseded artwork screenshots.
- **Old tests:** a test stays if the release gate, the build and release scripts or a workflow runs it, followed
  transitively (a kept test's own references keep theirs), plus its same-named companions (`.sh`, setup, teardown).
  Of the logic gates only the previous one (v0.8.25.0) stays; older gates run from the frozen checkpoint archives as
  before.
- **Release notes:** every version's `vX.md` stays; the separate change lists and test plans before v0.8.0.0 went
  (the notes and `CHANGELOG.md` keep the history).
- **Leftovers:** a compiled object, stray `.webp` copies, old manifests and change lists at the root, a Python
  bytecode cache and an unreferenced old wordmark image.

User images that nothing references yet (the older banner, the numbered screenshots) were **kept** and are listed in
the audit as unreferenced, since they are the user's to place or drop.

## What was rewired

- `PalworldServerManager.slnx` holds exactly Core, HeadlessHost and Desktop, so `dotnet build` of the solution builds
  the product (before, the Desktop was outside it).
- The Desktop has its own Windows manifest (`src/MystTiq.Desktop/app.manifest`: asInvoker, Windows 10 and later),
  which carries the release version the legacy app's manifest used to carry. The version bump and
  `Validate-Release.ps1` read it.
- `scripts/Build.ps1` builds the solution; `scripts/Build-Release.ps1` validates, builds, runs the release gate and
  packages both platforms with `Package-GitHubRelease.ps1`; the root `Build.ps1` lost its installer targets and its
  `Package` target now makes the Windows and Linux ZIPs and checksums.
- `Validate-Release.ps1` requires the product's files (not the legacy app's) and dropped the WPF-only checks.
- `.gitattributes` keeps `.sh` and `.py` files LF on every checkout (a CRLF shebang fails on Linux);
  `.gitignore` ignores Python caches and no longer mentions the installer output.

## The review stamp

`scripts/Set-MystTiqFileStamp.ps1` puts one comment line in every text file, in the file's own syntax:
`MystTiq v<version>: file reviewed for this release (<date>).` It goes first, or after a shebang, XML declaration
or doctype; encoding and line endings are kept; running it again updates the version and date in place. JSON (no
comment syntax), `LICENSE` (GitHub reads it verbatim to detect the licence) and binaries are reviewed but not stamped,
and the audit says so per file. The release gate checks every stampable file carries the current version's stamp, so a
later release re-runs the script as part of its bump.

## Live acceptance scripts

| Script | Needs | Checks |
| --- | --- | --- |
| `Test-v0.8.26.0-LinuxDesktopSession.ps1` | the Linux VM with its desktop logged in | the real X11 window (WM_STATE, maximize to the work area and restore), a clipboard round trip, the tray icon registered with the StatusNotifier watcher, all four sign-in roles |
| `Test-v0.8.26.0-InGame.ps1` | a player on the clone server (`second-local`) | live map position, Give Item (1 Wood), PalDefender position capture, teleport to a temporary point at it, teleport settings restored exactly; records the REST/PalDefender pair for map calibration |
| `Test-v0.8.26.0-Alerts.ps1` | outside channels switched on | sends a real test notification per server with a channel, then reads the Activity log for a failed send; paused or channel-less servers are skipped |
| `Test-v0.8.26.0-ContrastTheme.ps1` | a Windows contrast theme on, MystTiq open in High contrast or Follow the system | reads the theme from Windows (`SPI_GETHIGHCONTRAST`, `GetSysColor`), captures the window with `PrintWindow`, checks the most common colour is the theme's window colour and its text and highlight colours are used |

The in-game and alerts scripts change real state, so the release gate rehearses them
(`Test-v0.8.26.0-LiveScriptsRehearsal.ps1`): the published headless exe as a sidecar, stand-in RCON and REST servers
(`scripts/Testing/FakePalServerEndpoints.ps1`) and a local webhook. The rehearsal checks RCON received exactly
`giveitems steam_1 Wood:1`, `getpos steam_1` and the `tp` to the captured position, that the teleport settings are
byte-for-byte as before, that the webhook received the test, and that a closed webhook port makes the alerts script
fail and name the failed send.

## Not changed

No product code changed behaviour. The only source edits outside scripts are comments (the stamp, and one comment that
described the removed WPF settings model).
