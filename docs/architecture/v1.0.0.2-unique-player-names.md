# v1.0.0.2 — Unique Player Names (internal)

Asked 2026-10-04: "is there a way to ensure player names are unique and that duplicates can not be used?" The owner chose
the rules offered: the first account seen with a name owns it, names can be reserved by hand, and matching ignores case
(look-alike characters such as `W4de` or a Cyrillic "а" were offered and not chosen; they count as different names).

## Why MystTiq does it

Palworld keys players by account (user ID `steam_…`, character ID from it) and lets any number of them use the same name;
there is no server setting for unique names. MystTiq already sees every online player on the `/status/poll` cadence (the
player registry, the whitelist, the identity guard), so the name guard runs there too.

## Rules (`NameGuard`, pure, covered by the logic harness)

- **Key:** the name with spaces trimmed and runs of spaces collapsed, upper-cased (invariant).
- **Account:** the user ID; a bare 17-digit SteamID64 gains `steam_`; without a user ID, the character ID.
- **Judge:** for each online player with a name and an account: a claim with the same key owned by another account (or by
  nobody: a blocked name) is a clash; a claim owned by the player's account, or by their character ID (a claim made from a
  record without a user ID), is theirs; no claim makes one for them. Two players arriving in one poll with one unclaimed
  name: the first listed gets it.
- **Seed:** when `name-guard.json` does not exist yet, the player registry's records give the claims, oldest first-seen
  first; a name two accounts share goes to the earlier, and the activity log names both.
- **Normalize (on save):** one claim per key (the first), empty names dropped, an empty owner made a reserved block,
  owner IDs as accounts.

## Enforcement (`HeadlessNameGuardService`)

On a clash, once per online session of that account: a Warning notification (not pinned), an activity entry, an event in
`players/name-guard-events.json` (last 200), and, by default, a kick through `PlayerModerationCoordinator` (REST first, RCON
fallback) with a message telling the player the name is taken. The config is `Enabled` and `KickDuplicates` (both on by
default) plus the claims. New claims from the poll are added to the current config under the lock, so a save made meanwhile
is not overwritten.

Limits, stated in the public notes: Palworld reports a name only once the player is in the world, so the duplicate
character exists by the time of the kick; deleting it on Players lets the player choose another name. Like the whitelist,
nothing is checked while nothing polls.

## Owner's data on this machine (2026-10-04)

The desktop helper's registry (`%LOCALAPPDATA%\MystTiq\runtime\players\player-registry.json`) holds five records, all
with user IDs: Wade, WadeeRROR and Wade (pid None) for Wade's account; Melly and M3llyM for Melly's. First use gives each
name to its account; no conflicts.

## Fixed on the way: gated Save buttons stuck disabled

Seen live on 2026-10-05 while checking the card: **Save names** and **Save Whitelist** were greyed out and did nothing.
`RaiseCommandRoleGatesChanged` (sign-in, connect) asks every role-gated command again; when that happens while the app is
busy, `AsyncCommand.CanExecute` is false (`!IsBusy`) and the button is disabled. `RaiseIsBusyDependents` re-asks only a
hand-kept list of commands when the busy state ends, and most gated Save commands were not on it, so they stayed disabled
until a restart. Ungated commands (Refresh, Reserve) were never re-asked while busy, which is why they looked fine. Now
every `AsyncCommand` of the view model is re-asked when the busy state changes (`RaiseAllAsyncCommandStates`, collected
once all commands exist). The ArtworkHarness reproduces the sequence; it fails without the fix.

## Desktop

The Players page's Unique player names card (admins): on/off, kick or report only, reserve a name for a Steam ID or block
it, release, save, and the last 20 players turned away. Names and IDs are shown as typed; the status, kinds and outcomes
are translated, as are the service's notification sentences.
