# v1.0.8.0 — The ViewModel Split Begins (internal)

Roadmap C-0, plus two fixes found by the v1.0.7.5 long set.

## C-0 — Foundation and the Console pilot

**`SessionContext`** (`ViewModels/SessionContext.cs`) is what a page's ViewModel shares with the window:
- the API client, the active tab's connection (`Profile`, null when it has none) and `BearerToken`;
- `IsBusy` and the page shown (`Page`);
- `RunUi`, the window's error-recording runner;
- `Tr`, the text lookup.

The window owns the state and the context reads it through delegates. A page never reaches into `MainWindowViewModel`.

**`PageViewModel`** is a page's base class. It holds the session and its `NavigationPage`, gives `IsShown`, and has
`OnShown()`, which the window calls from the `SelectedPage` setter for every page in `_pages`.

**`Commands.cs`**: `RelayCommand`, `RelayCommand<T>` and `IRoleGatedCommand`, moved out unchanged. They are shared by
every ViewModel.

**The pilot, `ConsoleLogViewModel`** (exposed as `vm.Logs`; `Console` would clash with `System.Console`):
- **It owns:** the log lines, the filtered view, the filters, pause and clear, the first-seen stamps (v1.0.7.3), the
  stale flag, and the commands.
- **The window keeps:** the Dashboard's part. `ApplyLogs` sets `LogFileText`, hands the tail to `Logs.Apply` (false when
  unchanged), then fills `DashboardActivityLines` from `Logs.LogLines`. The Dashboard moves in C-1.
- **Bindings:** `MainWindow.axaml` binds `Logs.LogLines`, `Logs.FilteredLogLines`, `Logs.SeverityFilter` and the rest;
  `TrText` takes the nested path. The ribbon uses `Logs.PauseCommand` and `Logs.ClearCommand`. The export calls
  `Logs.EnsureFilterCurrent()`.
- **The role audit** (`Get-MystTiqCommandRoles.ps1`) now reads every ViewModel file and follows `Session.Api` calls as
  well as `_api`, so a page moved out stays audited.

**Exit gate:**
- The full gate passes; the v1.0.7.3 console contract now reads `ConsoleLogViewModel.cs`.
- The ArtworkHarness passes, with the console checks (an unchanged poll touches nothing, 10,000 lines, stable times,
  the hidden filter) and rapid tab switching reading `vm.Logs`.
- The moved code is gone from `MainWindowViewModel.cs`. Its size: 619,028 bytes and 10,801 lines before; 609,714 bytes
  and 10,604 lines after.

## Fixed: Ctrl+C on the service's console

**1. PalServer shared the service's console.** With the default launch (no `UseShellExecute`, no `createNoWindow`), a
Ctrl+C on that console reached PalServer as well. Running `api-run` in a terminal and pressing Ctrl+C stopped the game.
- PalServer now starts with `CreateNewProcessGroup` (.NET 10), so Windows does not deliver Ctrl+C to it.
- MystTiq never stops PalServer with a console signal (REST/RCON, `CloseMainWindow`, then a kill), so nothing else
  changes.
- Linux already started it with `setsid -f`.

**2. An inherited "ignore Ctrl+C".** A process started by a parent that ignores Ctrl+C (Git Bash, some launchers)
inherits that, so `api-run` there could not be stopped with Ctrl+C at all. `ConsoleCtrlC.Restore()`
(`SetConsoleCtrlHandler(NULL, FALSE)`) turns normal handling back on at start-up, and `CancelKeyPress` then shuts the
service down cleanly.

**Evidence:** the long set's new check starts the stand-in with the default launch, sends Ctrl+C to the service's
console (`Send-MystTiqConsoleStop.ps1 -Signal CtrlC`), and requires the service to stop with the stand-in still running.
Before the fix, the same sequence stopped the stand-in (reproduced 2026-10-11).
