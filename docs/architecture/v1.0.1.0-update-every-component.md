# v1.0.1.0 — Update on Every Update Center Row (internal)

Asked 2026-10-05: "the update page should have a button to update every option. It can be greyed out if it is self
updating, but should always have the option to update." Then, with a screenshot of the Update Center: "all of these
options should have an update option".

## Before

Only pip had Update (`CanUpdateInPlace`, shown when an update was available). The other rows had at most Open, and
PalDefender's detail told the owner to replace its DLLs by hand.

## Each row

`ComponentVersionDto.UpdateMethod` decides by component (desktop-side, so it works with any v1.x service):

| Row | Method | Path |
|---|---|---|
| MystTiq Server Manager | DownloadRelease when the service reports an update, else NothingNewer (greyed) | `MystTiqSelfUpdate` |
| SteamCMD | SelfUpdating (greyed); ServerFiles when it is missing | `UpdatePalworldServerAsync` (provisions SteamCMD) |
| Palworld Dedicated Server | ServerFiles | `UpdatePalworldServerAsync` |
| UE4SS Runtime | Ue4ssInstall | the UE4SS page, newest release selected, preview run; the owner applies |
| PalDefender | PalDefender (OfficialPage when not installed) | `POST update-center/components/paldefender/update` |
| pip | Pip | existing `pip/update` |
| Palworld Save Tools | SaveTools | `POST update-center/components/save-tools/update` |
| Python, .NET, VC++, Build Tools, PlM/Oodle | OfficialPage | opens `SourceUrl` |
| anything NotApplicable | NotApplicable (greyed) | — |

A greyed-out button shows `UpdateHint` beside it; every button has it as its tip (`ToolTip.ShowOnDisabled`). The
command is `UpdateComponentCommand` (`RelayCommand<ComponentVersionDto>`); its role is derived as Admin (the highest
route it reaches), and pip's own command is folded into it.

## PalDefender

`PalDefenderUpdater` reads `releases/latest` from `Ultimeit/PalDefender`, whose assets include `PalDefender.dll` and
`d3d9.dll` separately. It:

1. plans the targets from Win64: `PalDefender.dll`, or its switched-off name (NativeModCatalog's suffixes), and
   `d3d9.dll` or its switched-off name; a `version.dll` loader is left alone; no PalDefender means nothing to update;
2. downloads into a staging folder and refuses anything that is not a PE file ("MZ") or whose `PalDefender.dll` product
   version differs from the tag;
3. copies the files it replaces to `<runtime>\backups\paldefender\<time>-v<old>` and only then replaces them.

`d3d9_config.json` and the `PalDefender\` folder are never touched. The route refuses while PalServer runs. Checked on
a copy of the live Win64 files against the real release: 1.9.2 to 1.9.3, config unchanged.

## MystTiq

A running program cannot replace itself, and the upgrade notes already say to extract each version into a new folder.
`MystTiqSelfUpdate` reads `releases/tags/v<latest>`, downloads `SHA256SUMS.txt` and the ZIP for this system, refuses
the ZIP unless the list names it with the same SHA-256, checks it holds the desktop, and moves its top folder beside the
current application folder (`-2`, `-3` … when taken; `%LOCALAPPDATA%\MystTiq\versions` when the parent may not be
written). It then opens that folder. The owner exits from the tray and starts the new one. Only published stable releases
are offered (the service's `ReleaseChannel`); drafts are not reachable without a token.

## Save Tools

`convert.py` imports the pip-installed `palworld_save_tools` package, so `pip install --upgrade palworld-save-tools` is
its update; a copy without pip metadata is refused rather than guessed at.
