# v0.6.6.0 — Player Registry, Activity Intelligence & World Explorer 2

## Goal

Per the roadmap: "Create persistent player intelligence and a performant spatial/world administration surface." This milestone ships a real, working slice — a persistent Player Registry and a small World Explorer 2 addition — rather than the full surface, matching the roadmap's own "real foundation per named area, explicit deferrals" discipline.

## What shipped

### Persistent Player Registry

- `MystTiq.HeadlessHost.HeadlessPlayerRegistryService` (new) — a per-player identity/session record: `PlayerId`, `LastKnownName`, `SteamId`, `UserId`, `FirstSeenUtc`, `LastSeenUtc`, `TotalSessions`, `TotalPlaytimeMinutes`, `CurrentlyOnline`, `CurrentSessionStartUtc`. `SteamId`/`UserId` come directly from live Palworld REST player data (`HeadlessMonitoringService.GetPlayersAsync`) — the app already received both fields on every poll, but nothing persisted them until now, so real Steam ID/Player UID mapping is a genuinely new capability, not new plumbing.
- **Sampling pattern**: `Observe(HeadlessPlayersSnapshot, DateTimeOffset)` is called from the existing `GET /status/poll` route, right alongside `HeadlessHistoricalMetricsService.Record(...)` — the exact same "sample on the existing polling cadence, no new background timer" pattern v0.6.1.0 established for CPU/RAM/player-count history. This means observation only happens while something is actively polling (a Desktop client, or any other API consumer) — the same accepted limitation the CPU/RAM history already has, not a new one.
- **Join/leave detection**: comparing the previous online set to the current one on each observation. A newly-online player logs a `"Join"` event and increments `TotalSessions`; a previously-online player no longer present logs a `"Leave"` event. Events are a bounded (2000-entry), persisted `PlayerPresenceEvent` history at `GET /api/v1/players/registry/events`.
- **Playtime accrual is capped per observation tick** (`MaximumPerTickAccrual`, 10 minutes) — without this, a large gap between observations (nobody polling for a while, or a MystTiq process restart) followed by a fresh observation finding the same player still online would add the entire gap as playtime. This mirrors the same class of correctness safeguard `HeadlessHistoricalMetricsService.FindGaps` already applies to chart rendering, applied here to a cumulative counter instead.
- `GET /api/v1/players/registry` returns the full per-player snapshot. Surfaced on the Desktop Players page as a compact summary line for the selected player (first/last seen, session count, tracked playtime), fetched alongside the existing player-metadata load.
- **Player-count history needed no new work.** `HeadlessHistoricalMetricsService` (v0.6.1.0) already samples `OnlinePlayers`/`KnownPlayers` on the same poll cadence — the roadmap's "join/leave history and player-count history" bullet was already half-shipped; this milestone completes the join/leave half.

### World Explorer 2 — abandoned-base detection

- `HeadlessPlayerGuildExplorerService.ExploreAsync` now also derives `AbandonedBaseIds`: every `BaseId` belonging to a guild already flagged `"Orphaned / Needs Review"` (no present leader — logic that already existed). This is a cheap, real addition to `HeadlessPlayerGuildSnapshot`, not a new detection pass; the Desktop's existing Bases page already showed each base's owning guild's health per row, so this mainly makes the signal directly queryable at the API level for other consumers.

## Explicit deferrals (not silently dropped)

- The high-performance Canvas world map and every overlay named in the roadmap: Pals, bosses, NPCs, fast travel, dungeons, relics, guild bases, base-radius visualization, pan/zoom/fullscreen/clustering/layers.
- Activity heatmap, peak analysis, and maintenance-window recommendations.
- Searchable chat/activity history and queued offline moderation — confirmed via research that no chat-capture source exists anywhere in the codebase (Palworld's REST API and RCON expose no chat feed); this needs a genuinely new capture mechanism before it can be built at all.
- Multi-source presence reconciliation with confidence scoring (today's registry trusts REST player data directly; reconciling against save-file evidence with a confidence score is a real, separate piece of work).
- Global item search and storage/container inspection — needs save-decode infrastructure that doesn't exist (the same gap already documented for full character/inventory migration in v0.6.3.0's architecture doc).

## Verification

Live, against a real isolated instance, using a small mock Palworld REST endpoint (a `System.Net.HttpListener` script standing in for a real dedicated server's `/v1/api/players` response, since standing up an actual running PalServer was out of scope per the standing "never touch/never risk production" constraint):

- Poll with no players online: `GET /players/registry` and `/players/registry/events` both correctly empty.
- Flip the mock to report one online player, poll: registry gained exactly one record with `CurrentlyOnline=true`, `TotalSessions=1`, correct `SteamId`/`UserId` captured from the mock REST payload, and exactly one `"Join"` event recorded.
- Poll again with the same player still online (~9 seconds later): no duplicate Join, `TotalSessions` unchanged at 1, `LastSeenUtc` updated, `TotalPlaytimeMinutes` correctly accrued (~0.154 min, matching the real elapsed gap).
- Flip the mock back to empty, poll: `CurrentlyOnline` flipped to `false`, `CurrentSessionStartUtc` cleared, and a `"Leave"` event recorded — event list correctly ordered newest-first.
- Flip the mock back online, poll: `TotalSessions` correctly incremented to 2 on rejoin, while `FirstSeenUtc` and cumulative `TotalPlaytimeMinutes` were preserved from the prior session.
- Confirmed `GET /world/players-guilds` still serializes cleanly with the new `AbandonedBaseIds` field present (empty in this scratch environment, since no active world/Level.sav exists there — expected).

Not performed this session: a real end-to-end test against an actually-running PalServer instance (the mock REST endpoint reproduces the exact JSON contract `HeadlessMonitoringService.GetPlayersAsync` consumes, making this a faithful test of the registry's own logic, but not of Palworld's real REST behavior under load); Desktop GUI click-through of the new Players-page registry summary line (verified via clean compile and the same binding pattern already proven for the v0.6.5.0 provider-health line, not separately click-tested in the running GUI).
