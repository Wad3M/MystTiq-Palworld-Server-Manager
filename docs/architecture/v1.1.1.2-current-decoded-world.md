# v1.1.1.2 — Pages read the newest decoded save; new icons (internal)

Roadmap F-16 and F-17. Owner, 2026-10-19: "lets fix that" (F-16, found while taking the v1.1.1.1 README screenshots), then
two images: "Here is the new image for MOD Sources" and "here is the new icon for Launcher".

## F-16

- Before: `HeadlessWorldClockService.Read` took the newest of the decoded copy beside `Level.sav` and MystTiq's own
  (`runtime\world-clock\decoded\<world id>.Level.sav.json`), but `HeadlessPlayerGuildExplorerService` (Players, Guilds,
  Bases, Map) and `HeadlessGameIdCatalogService` (Give Item) read only the copy beside `Level.sav`. The refresh writes
  beside `Level.sav` only when `SaveFolderAccess.CanWrite` allows; on the owner's server it does not, so the copy beside it
  stayed at 2026-10-01 (before the 10-13 ID moves) and the pages showed Wade under 67D8D355 ("Missing save") and his
  current character as "Unknown Player".
- After: `DecodedWorld.Newest(worldPath, cacheRoot)` (the newest non-empty of the three names beside `Level.sav` and
  MystTiq's own copy) is used by all three readers. `DecodedWorld.Describe` gives the source line ("MystTiq's own decoded
  copy, decoded <time> UTC", and "older than the world save, a newer one is being made" when stale).

## F-17

The owner's two images had a dark gradient backdrop (24-bit). The backdrop was fitted from the border (quadratic per
channel); pixels joined to the border through backdrop-like colour became transparent in proportion to their difference
(the soft outer glow, un-blended so it keeps its colour), the rest stayed opaque; then cropped and centred on 1254x1254
like the other icons. `icon-mod_sources.png` is new (MOD Sources had reused `mod_dashboard`); `icon-launcher.png` is
replaced (it was 512x512).
