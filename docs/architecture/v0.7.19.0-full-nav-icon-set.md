# v0.7.19.0 — Full Navigation Icon Set

## Background

Requested directly, following a check for remaining backlog items. `docs/roadmap/PRODUCT_ROADMAP.md` calls for an "original Palworld-inspired MystTiq icon family for Dashboard, Doctor, Players, Guilds, Pals, Worlds/Saves, Backups, Mods, Updates, Automation, Network, Performance, Settings and lifecycle controls" plus "scalable/high-DPI icon assets." v0.7.0.0 shipped a first slice — 7 hand-authored `StreamGeometry` vector icons (Dashboard, Server Setup, Players, Bases, Backup Center, Security, Fleet) — and its own architecture doc says explicitly: "the remaining ~17 nav-sidebar destinations keep their existing Unicode-glyph icons." That gap was never revisited in any later release; this closes it.

The 25-icon replacement set itself (SVG source plus pre-rendered 240×240 PNGs) was designed and generated in a separate session on this machine, then handed off here to actually wire into the app.

## What shipped

### Every nav destination, one consistent icon language

All 25 nav-sidebar `ToggleButton`s in `MainWindow.axaml` (across all 7 categories — Home/Server/World/Backups/Mods/Tools/System) now render the same "glass orb" icon style: a glossy gradient sphere, per-destination accent color, drop shadow, and a white glyph silhouette matched to what the page actually does (a gauge for Dashboard, a wrench for Server Setup, a vault-and-checkmark for Backup Center, a shield-and-checkmark for Security, paw prints for Players, a tent for Bases, and so on for the other 18 that previously had no real icon at all — just a Unicode character concatenated into the label's own `Text`).

This replaces two previously-inconsistent things at once: the 7 old `StreamGeometry` vectors (single flat color, re-tinted via `{DynamicResource TextBrush}` so they followed the active theme) and the 18 old inline Unicode-glyph prefixes (plain text, not really an "icon" in any layout sense — no fixed width, no theme-independent color, prone to font-fallback rendering differently across Windows/Linux).

### Why PNG, not `StreamGeometry` or raw SVG

The new icon set is materially more complex than what `StreamGeometry` can express: each icon layers a radial or linear gradient sphere fill, a `clipPath`-bounded gloss highlight, a soft ambient-occlusion shade, a `feDropShadow`-blurred ground shadow, and a `feDropShadow`-blurred glyph — none of which map onto Avalonia's `StreamGeometry` (a single flat path, filled or stroked with one solid `Brush`, no gradients, no filters, no layering). Re-tinting per-theme (the whole reason the old icons were `StreamGeometry` in the first place) isn't relevant here either: each new icon is a fixed, deliberately-chosen accent color, not something that should shift with the user's selected theme.

Rendering the raw `.svg` files directly was considered and rejected: this codebase has no SVG-rendering package today (no `Avalonia.Svg`/`Svg.Skia` reference anywhere in any `.csproj`), and adding one as a new dependency for a single, one-time icon swap is a disproportionate footprint next to just using the PNG renders that were already generated alongside the SVG sources. The 240×240 PNGs are embedded as ordinary `<Image Source="/Assets/Icons/icon-*.png" Width="20" Height="20" Stretch="Uniform"/>` controls — the exact same mechanism this codebase already uses for every other raster asset (the app icon, the wordmark, the dashboard background image), so this introduces no new rendering path, just more files under `Assets/`.

### Cleanup

`Styles/IconGeometries.axaml`'s 7 now-unreferenced `StreamGeometry` resources were deleted rather than left as dead code (confirmed zero remaining `{StaticResource IconDashboard}`-style references anywhere in `MainWindow.axaml` before removing each one). `IconAddTab` (the tab bar's "+" button — unrelated to nav, added in v0.7.1.0) is untouched.

## Explicit non-goals

- **Re-theming the new icons per accent/light-dark theme.** The old vector icons re-tinted via `{DynamicResource TextBrush}` specifically because they were flat single-color shapes meant to blend into the chrome; these are deliberately saturated, colorful artwork in their own right (matching the "card flare" per-category accent-color language already established in v0.7.4.0), not meant to shift with theme selection the way plain UI chrome does.
- **Replacing the ribbon-toolbar icons** (Refresh/Start/Restart/Stop/Backup/Console/Doctor — plain Unicode glyphs inside `Border.iconTile`) or the tab bar's own icons (add-tab, close-tab). Out of scope: the request and the delivered icon set both target nav-sidebar destinations specifically, not every icon-shaped thing in the app.
- **Adding an SVG-rendering dependency** to use the vector source files directly instead of the pre-rendered PNGs — see "Why PNG" above.
