# v1.0.3.0 — Xbox Player Discovery (roadmap X-1, internal)

The owner's roadmap asks to establish, before anything is built, what the save and the REST API show for an Xbox player
(identity, name, Pal and item data), read-only, using the owner's Xbox test account (decision D-5).

## Status: Blocked on the owner's session (2026-10-05)

Discovery needs the owner's Xbox account in the clone's world; no Xbox player has joined any server on this machine. The
script and the procedure below are ready. Nothing for Xbox players is built until the capture is recorded here.

## What MystTiq assumes today (to be confirmed or corrected)

- REST `/v1/api/players` gives every online player `name`, `userId`, `steamId`, `playerId`, `ip`, `ping`, `level`,
  `buildingCount`, `location_x/_y`. MystTiq labels a player without a `steamId` "Xbox / Crossplay"
  (`HeadlessMonitoringService.DetectPlayerPlatform`). That is a guess: what an Xbox player's `userId` and `steamId` look
  like has never been recorded.
- The world save keys each player by `PlayerUId` (a 32-hex id; for Steam it is derived from the SteamID64,
  `SteamPlayerUid.cs`). How an Xbox account's PlayerUId is formed is unknown, so the identity guard, unique names and
  character migration can only key Xbox players by what the save itself says.
- Give Item and kits work through PalDefender, which addresses players by their id in the REST/RCON form.

## Procedure (read-only)

1. Start the clone (`second-local`) through MystTiq. The owner joins it from Xbox, creates or loads a character, picks
   up at least one item and catches or holds at least one Pal.
2. Run `scripts\Discover-v1.0.3.0-XboxPlayer.ps1 -Api http://127.0.0.1:8213 -ServerId second-local` (add `-Token` when
   authentication is on). It waits for a player without a Steam ID and records the REST entry with the IP address
   removed.
3. Save the world (in game or **Save Now**), press Enter. The script reads the explorer's decode of the save
   (`world/players-guilds`) and the player registry for that player, and writes a JSON capture.
4. Record here:
   - the `userId` and `playerId` forms;
   - whether `steamId` is empty;
   - the PlayerUId in the save and how it relates to `userId`;
   - the name as stored;
   - where the player's items and Pals sit (container ids), compared with a Steam player's.
5. Decide, with the owner, what Xbox support needs (labels, identity guard, unique names, Give Item, migration).

## Exit criterion

X-1 is `Done` when the capture and its findings are recorded in this file. It may be `Blocked` with the reason written
here, which is the state on 2026-10-05.
