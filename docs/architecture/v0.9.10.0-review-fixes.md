# v0.9.10.0 — Review Fixes

An external review of the v0.9.9.0 source (2026-09-30) reported six findings (F1–F6), a concern about NAT, and
translation notes. It reproduced F2, F5 and F6 by running the archive's own code; F1, F3 and F4 were found by reading
it. This version fixes each one and adds a check that fails if it comes back.

## F1: a slow helper was forgotten while still running

`LocalManagementBootstrapper` probed the recorded helper once with a 750 ms timeout. A helper that was starting or busy
did not answer in time, its record was deleted and a second helper started beside it; a failed stop was ignored too.

Now:

- `IsRecordedHelper` says whether the recorded process is still that helper: running, the same executable, and the same
  start time when the record has one (`SidecarState.StartedUtc`, new; an older record without it is matched by path).
- A live helper that does not answer is asked again for up to 8 s, allowing each answer 4 s (`WaitForAnswerAsync`), and
  reused if it answers.
- A live helper that cannot be used is stopped, and a replacement starts only once it has exited (`StopHelperProcess`
  returns whether it did). If it could not be stopped, the connection reports that, naming the process, and starts
  nothing.
- A helper is reused only while its recorded process is alive, so another program answering at a dead helper's port is
  never taken for it.

The ArtworkHarness starts itself again as stand-in helpers (`--slow-helper <port> <delay> <version>`) with a private
runtime folder: one answering after 2 s is reused; a record whose start time differs (a reused process id) is neither
reused nor stopped; one that never answers is stopped and has exited before anything else happens.

## F2: names were translated

`MessageCatalog` translates a message's values when they are themselves known messages ("Status: Stopped / Not ready").
A server named "Ready" in "Restarted. 'Ready' is now online." became "Bereit". A placeholder now holds a name, and its
value is kept, when it is in quotes (`'{0}'`, `"{0}"`, `“{0}”`, `«{0}»`, `„{0}“`, `「{0}」`) or follows a word that names a
thing: server, world, player, guild, profile, tab, kit, mod, rule, channel, account, user, member, named. Other values
are still translated. The Dashboard's server name and description are bound without translation (they are only ever
the user's text or "—").

Remaining: a name in an unquoted slot not after one of those words can still be translated if it equals a known message.
MystTiq's own messages quote names; the harness checks "Ready", "None" and "Backup".

## F3: an unknown MOD update state counted as "up to date"

`CheckModUpdateAsync` returns no answer (no known source) for a MOD without a Steam Workshop copy and on Linux, and a
"known source" without a comparison when the timestamps cannot be read. The inventory turned all of these into "no
update", and the Alert Center then resolved its MOD alert. Now:

- each inventory row carries `UpdateChecked` (a real comparison happened);
- `ComponentAlerts.ModsBehind` opens the alert when a MOD has an update, and resolves it only when every MOD the open
  alert named has been checked and is current, or is no longer installed (after a restart, when the names are not
  known, every MOD must be checked); otherwise nothing is decided;
- the resolved notice names what was checked: "Every MOD that had an update now matches Steam's local Workshop copy."

## F4: the update check missed MystTiq's own releases

GitHub's `releases/latest` returns the newest release that is neither a draft nor a prerelease, and the release
workflow publishes every 0.x version as a prerelease. The check now reads `releases?per_page=30` and `ReleaseChannel`
picks the newest by version number: prereleases count while the installed MystTiq is 0.x, only stable releases from 1.0
on, drafts never. The detail names the channel. PalDefender's check still uses its latest stable release.

## F5: join-crash evidence expired

The newest stopped session's end was taken as "now", and the finding required the session to end within 5 minutes of
the join. The same log gave a finding at one minute and none at ten. Neither "now" nor the next session's start is when
a session really ended, and a clean stop always logs the REST API stopping after the last join. So the window is gone: a
session that has ended (the server is not running, or a later session started) and whose log ends on a player joining
is reported with the same evidence line whenever it is read, recorded once, and kept in the crash history. The title
became "Server session ended on a player joining" (it no longer claims timing), and the evidence wording "session log
ends on a player joining"; lines recorded by v0.9.9.0 still match the signature.

## F6: the source archive failed its own gate

`CHECKPOINT_NOTES.md` was copied into the tree after `Set-MystTiqFileStamp`, so the archive's stamp check failed on it
(184/185). The notes now carry the stamp when written, a contract checks it, and the release steps extract the source
ZIP after checkpointing and run the gate there. The frozen-v0.9.9.0 regression run sets that one known failure aside
by its exact text; any other failure still counts.

## The port finding and NAT

`configuration-game-port` said players given the advertised port "cannot join". With a router that forwards another
outside port to the server's port, that difference is intentional. The finding and its recommendation now say so, and
Fix remains something the user chooses.

## Translation notes

Applied: Level, Gender and Nickname in the Pal edit preview in all 11 languages; a count-neutral MOD update message in
all 12; German "Stopp erzwingen" and "Änderungen zurücksetzen"; "this app" instead of "this desktop" in the helper
message (French, Spanish, Polish, Turkish and the rest). Not applied: a full native review, which the review itself says
it was not.

English keeps the system's regional number and date format by design (someone reading English may be anywhere); every
other language uses its own. The release notes of v0.9.9.0 said formats follow the chosen language without that
exception; this version's docs state it.
