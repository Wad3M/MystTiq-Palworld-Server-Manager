# v0.7.45.0 — Update Center Overhaul

## Goal

Item 51 from the original findings log: the full component-by-component version-tracking table
from the v0.2.16.4 reference build — Component / Installed Version / Latest Version / Status /
Source, grouped into "Save & Runtime Dependencies" and "Core Server" — not just the single
"Update Palworld Server" action Update Center had before this version.

## Scope decision (asked and answered mid-session)

Before implementation, two scope questions were asked and answered directly:

1. **Build all ~11 components in one pass**, not a smaller starter slice (Palworld/SteamCMD/UE4SS
   only). Chosen over researching-first-then-asking-again.
2. **Include MystTiq's own self-update awareness** — check its GitHub releases for a newer tag
   than the running version, surface it, but never auto-download or auto-install. Informational
   only.

## Grounding: what already existed

- `HeadlessServerDistributionService.GetStatus()` — SteamCMD/PalServer *existence* only
  (`File.Exists`), no version number, no "latest" concept at all.
- `HeadlessEnvironmentChecklistService.GetSnapshot()` — the Server Setup page's Environment Health
  table. Already does real *installed-path* detection for Python, Palworld Save Tools, PlM/Oodle
  Decoder, and the C++ Build Tools compiler — useful groundwork reused directly (the same
  `FindOnPath`/`FindFirstExisting`/`DetectCppToolchain` logic patterns), but still existence-only,
  never a version string.
- `HeadlessModManagementService.GetInventoryAsync().Ue4ss.InstalledVersion` — UE4SS *does* already
  have real installed-version detection (fixed in v0.7.30.0, the "0.0.0.0" placeholder bug). Reused
  directly rather than duplicated.

None of the above ever compared an installed version against a "latest available" value for
anything — confirmed by search before writing any new code, matching this project's established
habit of grounding against primary sources rather than assuming a gap or a fix.

## Research performed before committing to any external source

Every "latest version" source below was verified as real and genuinely queryable unattended before
being wired into code — not guessed:

- **Steam Web API `ISteamApps/UpToDateCheck/v1`**: confirmed unauthenticated (no API key), takes
  `appid` + the caller's installed `version` (an integer buildid), returns `up_to_date` and, if not,
  `required_version` — exactly what's needed to compare Palworld Dedicated Server's installed
  SteamCMD build against the latest one, with zero credentials.
- **`dotnet/core` `releases-index.json`** (`raw.githubusercontent.com/dotnet/core/main/release-notes/releases-index.json`):
  the official, well-known public feed listing the latest runtime per support channel.
- **PyPI's per-package JSON API** (`pypi.org/pypi/<package>/json`): confirmed `pip` and
  `palworld-save-tools` (the real upstream project behind this project's vendored
  `Tools/palworld-save-tools/convert.py`, maintained at `cheahjs/palworld-save-tools`) are both
  real, actively-published PyPI packages with clean `info.version` fields.
- **GitHub releases API**: confirmed `Wad3M/MystTiq-Palworld-Server-Manager` (this project's own
  repo) and `Okaetsu/RE-UE4SS` (the actual upstream behind the Palworld UE4SS fork this project
  targets, tag `experimental-palworld`) both have real, queryable release data.
- **What does NOT have a clean source, confirmed by research, not assumed**: Python.org publishes
  no simple JSON feed for "latest Python version" suitable for unattended comparison. Microsoft
  publishes no equivalent for the VC++ Redistributable or MSVC Build Tools version numbers either —
  their download pages have no stable machine-readable version endpoint. "PlM/Oodle Decoder" (this
  project's own internal `Tools/palworld-plm-tools` folder naming) has no single canonical upstream
  project at all — several different community projects touch PlM/Oodle decoding, none of them the
  one specific thing this folder name refers to.

## What shipped

**Headless host (`MystTiq.HeadlessHost`)**:
- `HeadlessComponentUpdateService.GetSnapshotAsync()` — one method per component, each returning a
  `ComponentVersionInfo(Group, Component, InstalledVersion, LatestVersion, Status, Source,
  LastChecked, Detail)`. Every external call (HTTP, subprocess) is wrapped to never throw — a
  network failure or missing tool degrades that one row to an honest "Unavailable" detail, it never
  fails the whole snapshot.
- `Compare(...)` helper: numeric `Version.TryParse` comparison when both sides parse cleanly (most
  rows), falling back to exact-string-equality for `UpToDate` and a disclosed "ordering inferred
  from inequality" caveat otherwise — never silently claims a numeric ordering it can't actually
  verify.
- New route `GET /update-center/components` — read-only, no `RequireRole` beyond default
  authentication (matches every other read-only status route), not run through
  `IOperationCoordinator` since it mutates nothing.
- Wired into `ServerProfileHost`/`LocalManagementApiHost.Create` exactly like every other
  per-profile service (`HeadlessServerDistributionService`, `HeadlessDiagnosticsService`, etc.).

**Desktop (`MystTiq.Desktop`)**:
- `ComponentVersionDto`/`ComponentVersionSnapshotDto` (new, `Models/ComponentVersionDto.cs`) mirror
  the Core/HeadlessHost records; `StatusText` is a client-side display helper mapping the raw wire
  `Status` value to a readable label.
- `IMystTiqApiClient.GetComponentVersionsAsync` + `MystTiqApiClient` implementation.
- New `ComponentStatusColorConverter` (`Converters/`, matching the existing
  `ConsoleLineColorConverter` pattern exactly) colors each row's status text.
- Update Center page gains a new component table, split into the same two labeled sections as the
  reference, each row showing Component / Installed / Latest / Status / Source plus a wrapped
  Detail line explaining exactly what was or wasn't checked and why.
- The existing "Refresh" ribbon button (already wired to `RefreshDistributionCommand`) now also
  refreshes this table as a side effect — same page, same "what's actually installed and current"
  concern, matching the pattern already used this session for Doctor/Run Doctor and the new
  instance list (v0.7.44.0).

## Explicit non-goals

- **No new update actions.** Every row besides Palworld Dedicated Server already lacked a safe,
  general-purpose automated installer before this version (confirmed via the Environment
  Checklist's own pre-existing "BACKEND REQUIRED" disclosures for Python/Save Tools/PlM-Oodle/C++
  Build Tools) — this version reports what's outdated, it does not add new ways to update any of
  them. The one component that already had a real update action (Palworld Dedicated Server via
  SteamCMD) keeps using it unchanged.
- **No MystTiq self-update mechanism.** Per the scope decision, self-update awareness means
  surfacing "a newer version exists" with a link, nothing more — no download, no relaunch, no
  in-place replacement.
- **No fabricated "latest version" data.** Every row without a real, verified source says so
  plainly (`Status: Unknown`/`NotApplicable`, `LatestVersion: "Unavailable"`, and a `Detail`
  explaining the real reason) rather than presenting a guess as fact.
