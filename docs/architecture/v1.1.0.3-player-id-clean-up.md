# v1.1.0.3 — The player ID clean-up (internal)

Roadmap F-3. Owner, 2026-10-13 (after the two moves): "it should cleanup the old files so as to not cause possible
issues".

## What was left after v1.1.0.2's moves

- `runtime\character-migration\archive`: four character files (the two old characters, the two empty ones they
  replaced). Outside the world, so the game never read them.
- The player list (`players\player-registry.json`): records under 67D8D355, A3835C7B and 014308E2 (IDs with no
  character file any more) and one shared "None" record: every join seen before a character existed (loading, or the
  new-character screen) was filed under the player ID "None", for all accounts.
- The world file: checked read-only; none of the empty characters' 16 storage containers exist in it, so nothing there.

## What changed

- The move removes the old character file once `Level.sav` and the moved file are in place, instead of archiving it;
  a working copy restores it if anything after that fails, and the fresh safety backup holds it for good.
- The player list never records "None"; `MergeInto` moves a record (sessions and play time added, earliest first seen,
  latest last seen, its presence events) to the new ID after each move; `CleanUp` folds records naming no character into
  the account's current ID and drops a "None" record of an account with no known ID.
- `CleanUpOldEntries`, run once at start: removes each archived file whose character file a MystTiq backup ZIP holds
  (the four on the owner's PC are held by the two pre-move safety backups), then cleans the player list.

## Evidence

- LogicHarness: no "None" record; a move's merge (2 sessions, 8 minutes, first seen on the old ID, last seen on the new);
  stale records merged and an unknown account's "None" removed; an archived file a backup holds removed, one it does not
  kept; the real-world move (the owner's world, the real converter) leaves no archive folder and merges the list record.
- Live: the owner's PC after the upgrade (the start-up clean-up).
