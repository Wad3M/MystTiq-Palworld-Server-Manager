# v0.7.40.0 — MOD Library Layout & Details Panel

## Goal

Sixteenth version in the GUI/workflow/UX overhaul roadmap. Roadmap items 40 (the layout/details-panel half) and 42, plus item 43's "move Install Validated ZIP to the top" note, all folded into this version per the roadmap's own scoping — grounded against a v0.2.16.4 reference screenshot showing "INSTALLED SERVER MODS" left, "AVAILABLE LOCAL STEAM MODS" middle, "MOD INFORMATION" details panel right.

## What shipped

### Side-by-side 3-column layout (item 42)

MOD Library previously stacked three full-width cards vertically: Installed MODs, Install Validated ZIP, Available Local Steam Workshop Mods. Restructured into a `Grid ColumnDefinitions="1.3*,1.3*,*"`: Installed MODs (left), Available Workshop Mods (middle), and the new MOD DETAILS panel (right, narrower — a label/value list needs less width than a data table).

Each list's row `DataTemplate` was trimmed to fit its now-halved width:
- Installed MODs: dropped the separate RuntimeState/Evidence columns from the row (`90,2*,*,*,2*` → `60,2*,*`) — RuntimeState and Evidence now live in the new details panel instead of being duplicated in a cramped row.
- Available Workshop Mods: dropped the separate ContentKind column (`2*,*,*,Auto` → `2*,*,Auto`), keeping Name/ID, SuggestedPackage, and the status badge.
- Both lists' action-button rows changed from a `StackPanel Orientation="Horizontal"` to a `WrapPanel`, so the (now more numerous relative to available width) buttons wrap onto a second line instead of overflowing or forcing a wider column.

### New MOD DETAILS panel (item 40, layout half)

Confirmed during the original walkthrough: `SelectedMod` was already wired for the Installed MODs list but only ever used to target the Enable/Disable/Delete/Rollback action buttons — nothing rendered its actual details anywhere in the app. Built entirely from data `ModItemDto` already carries (no new backend work needed):

- **Overall Health** — `Health`
- **Installation** — `Type`, `Package`, `InstallPath`, `EnabledText`
- **Runtime** — `RuntimeState`
- **Compatibility** — `RuntimeConfirmed`
- **Evidence** — `Evidence`

A new `MainWindowViewModel.HasSelectedMod` computed property (`SelectedMod is not null`, raised alongside `SelectedMod`'s own `SetField` call) gates the panel: its full content when a MOD is selected, a "Select a MOD from the Installed MODs list to see its details here" placeholder otherwise. Both live inside one `Grid` (a `Border` can only have a single child; wrapping both `IsVisible`-toggled elements in a `Grid` — Avalonia's usual pattern for two elements occupying the same cell — was needed to fix an `AVLN3000` build error hit during implementation).

### Install Validated ZIP moved to the top

Relocated from between Installed MODs and Available Workshop Mods to above the new 3-column `Grid`, so it's the first thing on the page — matching the specific relocation the roadmap folded into this version.

## Explicit non-goals

- **The website-sourced MOD description** (the other half of item 40) — confirmed during the original walkthrough as genuinely new, unbuilt work: mods come from different sources (a numeric suffix suggesting Steam Workshop for some, likely Nexus Mods/GitHub for UE4SS/Lua mods) with no single uniform place to fetch a description from, and an outbound web fetch from an admin tool deserves its own deliberate scope/caching/rate-limiting design pass rather than a quick add-on to this layout work. The details panel's Evidence field surfaces MystTiq's own existing runtime evidence string instead — real data already available, not a placeholder.
- No change to `ModItemDto`/`WorkshopItemDto` or any backend route — purely a client-side layout and data-presentation change.
