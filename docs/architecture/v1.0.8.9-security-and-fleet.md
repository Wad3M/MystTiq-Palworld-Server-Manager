# v1.0.8.9 — Security and Fleet; the window shell (internal)

Roadmap C-9, the last step of the split, with the mover from C-2.

## SecurityViewModel (`vm.Security`)

**What moved:** API principals (list, create with the one-time token, revoke), named user accounts (create, reset the
password, enable or disable, delete), the role list, and the browser view's address (the former
`MainWindowViewModel.BrowserView.cs`).

**What stays with the window:** signing in and out, who is signed in (`CurrentPrincipal`, `ApplyCurrentPrincipal`) and
the role gates (`CanOperate`, `CanManageAdmin`, `CanManagePrincipals`): every page, the Ribbon and the command gates
follow them. The page is handed `ApplyCurrentPrincipal` (Refresh reads who is signed in) and `() => CanManagePrincipals`
(user accounts are listed for Owners only).

## FleetViewModel (`vm.Fleet`)

**What moved:** the server list, Clone World with its confirmation, port offset and the restart afterwards, and the fleet
actions (Backup All, Doctor All, Update All) with their results. The page is handed the local discovery and the
sidecar bootstrapper (the restart).

**The setup wizard's clone step** stays with the window and reads `Fleet.CloneWorldPortOffset`.

## What the window keeps

The window shell and tab coordination, as the roadmap set: tabs and their switching, connecting, the profile editor,
signing in, the setup wizard, the per-tab theme, navigation, the Ribbon, the role gates, the console and RCON on the
Console page, the server's start and stop, and the orchestrators that span pages. **The Settings page stays** because it
is exactly these: the connection and profile editor, sign-in, the wizard and the tab's theme. Moving its fields out would
have split one flow across two places.

## Fixed while moving

**A window raise of a page property reached no binding.** `RaisePropertyChanged(nameof(Alerts.HasNoAutomationRules))`
from the window raised the name on the window, where nothing binds it; the Automation page's "no rules" card did not
follow the rule list (since v1.0.8.7). The same held for `Workspace.WorkspaceDiscoveryText` after an environment check
(since v1.0.8.4) and would have for the browser view's address. `PageViewModel.Raise` lets the window raise on the page;
the mover now rewrites such raises, the gate refuses any left in the window files, and the ArtworkHarness checks the rule
list and a tab change reach the pages.
