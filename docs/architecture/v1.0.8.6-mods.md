# v1.0.8.6 — The MOD Pages (internal)

Roadmap C-6, with the mover from C-2 plus a short pre- and post-step.

## ModsViewModel (`vm.Mods`)

**What moved:**
- the MOD dashboard and library: the list, health, enable, disable, delete, roll back, repair, verify and ZIP install;
- UE4SS: detection, the release catalog, preview and install, roll back;
- Safe Start;
- the Workshop scan;
- Nexus Mods: the account, list, lookup, files, download and the nxm:// handoff;
- the MOD browser (the former `MainWindowViewModel.ModBrowser.cs`).

**What the page is handed:** the window's Nexus client, its credential store (the Nexus API key) and `Navigate`.

**The window keeps:**
- **The Dashboard's stuck-start panel.** It follows Safe Start: the page raises `SafeStartStatusChanged`, and the
  window refreshes the panel.
- **The Update Center.** It reaches UE4SS through `Mods.SelectAndPreviewLatestUe4ssAsync`.

**Shared:** `FormatTime` is now an internal static the page uses.

## Found while moving

**The constructor order.** The pages were created before the window assigned its services, so the MOD page would have
received a null Nexus client. The service assignments now come first.

**Overloads.** `BeginModSafeStartAsync` has two overloads. The mover took only the first and renamed the other's
declaration; it now moves every declaration of a name.

**A too-broad name filter.** "mod" also matched "mode" (`IsLightMode`, a theme property). Excluding "mode" then dropped
`SetSelectedModEnabledAsync`, which was added back by hand.

**Harness reflection.** Four reflective calls now target `vm.Mods`, and `PackageNameFor` is reached through its new
class.

**One carried check had to be narrowed.** It asserted that the browser's file never calls `NexusInstallFromNxmAsync`.
With the Nexus code in the same file, it now checks the specific rule: a received link fills the field and is not
installed by itself.
