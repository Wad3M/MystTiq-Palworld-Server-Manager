# v1.0.5.0 — MOD Browser (internal)

The owner's roadmap milestone v1.0.5.0 (M-1).

**Repositories (decision D-8, 2026-10-06):**
- the owner's Downloads folder, or other folders they name;
- Nexus Mods (the owner's account is free);
- Thunderstore;
- CurseForge;
- GitHub releases.

## Where things run

Every source is called from the desktop on the owner's PC, never through the MystTiq server. Nexus's API policy already
requires this for its key, and the CurseForge key is handled the same way: DPAPI-encrypted through `CredentialStore`,
sent only to CurseForge.

The downloaded file is sent to the service's existing `install-zip` route (Admin). The service applies the same archive
check again, so the desktop is a convenience, not the gate.

## Sources (`IModSource`, `Services/ModSources.cs`)

| Source | Search | Files | Download hosts |
| --- | --- | --- | --- |
| Downloads and folders | ZIPs (to one level down, newest 400 per folder) whose archive check finds a MOD; programs and unrelated ZIPs hidden; .7z/.rar counted | the archive itself | none (local) |
| Thunderstore | its Palworld package list (`/c/palworld/api/v1/package/`, 16 packages on 2026-10-06), cached 10 minutes, searched here; deprecated and NSFW hidden; shimloader dependencies and tools marked | each version | thunderstore.io and subdomains (`ccdn.`) |
| CurseForge | `/v1/mods/search` with the owner's key; Palworld's game id found by the slug `palworld` | `/v1/mods/{id}/files`; `downloadUrl` null means "only on CurseForge's site" | forgecdn.net, curseforge.com |
| GitHub releases | only repositories the owner adds | release ZIP assets (drafts and checksum files excluded, pre-releases marked) | github.com, githubusercontent.com |
| Nexus Mods | its three lists searched here, or a MOD by id or page address | the existing client | Nexus's own (`NexusModsLinks.IsAllowedDownloadHost`) |

An open GitHub search was rejected. On 2026-10-06 the top results for Palworld MODs, and most of the `palworld-mod`
topic, were cheat and "free download" lure repositories, several pushed that day.

`ModSourceHttp.DownloadAsync` refuses:
- a link outside the source's hosts;
- a redirect that ends outside them;
- anything over 512 MB, the service's limit.

## The archive check (`ModArchivePlanner`, Core)

The rules, in order:
1. Unsafe paths.
2. Programs (`.exe`, `.bat`, `.ps1`, `.js`, `.sh` and similar).
3. Loader DLLs (PalDefender, UE4SS, `d3d9`, `dwmapi`, `dxgi`, `winmm`, `version`, `xinput`).
4. unreal_shimloader layout: `manifest.json` with root `mod/`, `pak/` or `cfg/`.
5. PAKs:
   - PAKs together with a UE4SS script root are refused (mixed);
   - a PAK under `LogicMods` is refused;
   - several PAK base names are refused;
   - otherwise one PAK MOD.
6. UE4SS: the folder holding `Scripts/main.lua` or `dlls/main.dll`. Two or more such folders are refused; one is a UE4SS
   MOD installed from that folder.
7. Otherwise: no MOD.

PalDefender keeps its own earlier message. The service logs each refusal as "MOD archive refused".

Before v1.0.5.0:
- a mixed archive installed its PAK only;
- a LogicMods PAK went to `~mods`;
- several PAKs overwrote one another;
- a UE4SS MOD packed in a folder installed one level too deep.

The browser names a UE4SS MOD after its own folder. The live run showed that a GitHub MOD otherwise took the
repository's name.

## nxm:// links (free Nexus accounts)

`NxmProtocolRegistration` writes the per-user handler `HKCU\Software\Classes\nxm` only when the owner presses the button.
If another program holds it, MainWindow names it and asks first. Stop removes it only when it is MystTiq's.

The browser starts `MystTiq.Desktop.exe "nxm://…"`. `Program.Main` drops the link into
`%LOCALAPPDATA%\MystTiq\nxm-inbox`. A second instance then exits quietly; the running one picks the link up within two
seconds. Links older than 15 minutes or malformed are dropped.

The link fills the Nexus card's box and opens the MOD Library. The install still waits for the owner's click and
confirmation.
