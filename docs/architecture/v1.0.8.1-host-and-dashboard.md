# v1.0.8.1 — The HOST Page and the Dashboard (internal)

Roadmap C-1, on the C-0 pattern (`SessionContext`, `PageViewModel`).

## HostPageViewModel (`vm.Host`)

**What moved:** the three HOST partial files, merged unchanged into one class:
- `MainWindowViewModel.Host.cs`: the machine and the resource policy;
- `MainWindowViewModel.HostHistory.cs`: the readings history;
- `MainWindowViewModel.Bandwidth.cs`: the network limits.

**How it reaches the window:**
- `SelectedProfile`, `_api`, `BearerToken` and `IsBusy` are read through the session. The session gained
  `SelectedProfile` (the active tab's saved profile, which these commands always sent with).
- The window calls `Host.RefreshHostAsync` when the page opens and on the 5-second tick while it is open.
- The window calls `Host.RaiseHostCommandStates` when the busy state changes.
- `IsHostPage` and `IsV5HostCategory` stay with the window (navigation).
- **Names:** the member names are unchanged, so the XAML only gained `Host.` (53 bindings). The role table names
  `Host.SaveNetworkPolicyCommand` and `Host.SaveResourcePolicyCommand`. The role audit (since C-0) finds them in the new
  file and follows `Session.Api`.

## DashboardViewModel (`vm.Dashboard`)

**What moved:**
- the Dashboard's 20 card texts, each `Dashboard*` property becoming `Dashboard.*` with an `internal set`;
- the recent console activity (`ActivityLines`);
- the addresses line and its refresh (from `MainWindowViewModel.Addresses.cs`; its stuck-start part stays for C-4).

**What stays with the window, and why:**
- The status and world readings feed several pages, so the window still produces the texts and writes them into
  `Dashboard`.
- The health state (`DashboardHealthText`) stays because its glow follows the server's start and stop.

**The addresses refresh** drops a late reply for another tab by comparing with `Session.ActiveTab`, which the session
gained.

## Exit gate

- The full gate passes. The v0.8.17.0, v0.8.18.0, v0.8.20.0 and v0.8.24.0 HOST contracts, the v0.9.10.0 server-name
  binding and the v1.0.0.1 addresses binding now read the new files and paths.
- The ArtworkHarness passes, with the HOST checks reading `vm.Host`: the readings, the unsaved-edit guards, the
  validation, the bandwidth suggestion and the history summary.
- The moved code lives only in the new files.
- **Sizes:**
  - `MainWindowViewModel.cs`: 609,714 bytes before, 606,140 after (10,569 lines).
  - All `MainWindowViewModel*.cs` files together: 732,039 before, 704,238 after.
