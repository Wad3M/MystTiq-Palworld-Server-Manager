# v1.0.7.4 — Secrets and Archives (internal)

## Q-14 — Secrets encrypted at rest

**What is protected:** `notifications/channels.json` (each channel's `TargetUrl` and `SmtpPassword`) and
`notifications/discord-bot.json` (`BotToken`).

**How (`SecretProtector`, HeadlessHost):**
- On Windows, a value is stored as `protected:v1:` plus base64 of DPAPI `LocalMachine` with a fixed entropy. Machine scope
  because the service may run as LocalSystem or as the signed-in user, and both must read it.
- A value that cannot be decrypted (a file copied from another computer) reads as empty rather than failing the load.
- On Linux there is no DPAPI. The files are set to 0600 (`RestrictToOwner`), and this is documented as such.

**Moving over:** `LoadChannels` and the bot's load unprotect each value. If any value is still plain, the service:
1. copies the file to `<file>.before-encryption` (once: an existing copy is not overwritten);
2. persists the file protected;
3. records "Secrets encrypted" in the activity log.

Every save protects again.

**The plain copy:** `HeadlessDiagnosticsService.BuildPlainSecretCopyFindings` names any `*.before-encryption` file
(finding `security-plain-secrets-copy`, Warning). Its Fix (`delete-plain-secrets-copy`, Admin) deletes them. The Desktop
labels it "Delete Plain Copy" with a typed confirmation.

**Already safe, unchanged:**
- The Desktop's saved sign-in token: `CredentialStore`, DPAPI `CurrentUser`.
- Service sessions and API tokens: only SHA-256 hashes are stored (`sessions.json`, `HeadlessPrincipalRecord.TokenSha256`).

**Evidence (LogicHarness "Secrets at rest (Q-14)"):** a plain channels file is moved over, reads back the same, is
encrypted on disk, keeps one plain copy, stays encrypted on a save, and reads back after a restart. The bot token round
trip; an undecryptable value reads as empty. On Linux the file mode is checked. **Owed:** the owner's own channels still
send after the move.

## Q-15 — Every archive MystTiq opens has limits

**`ArchiveLimits` (Core):** the same limits as world import (20,000 entries, 8 GiB expanded), plus free space on the
destination drive (expanded size + 256 MB). `Check(ZipArchive, destination)` returns the reason, or null.
`CheckFile(path, destination)` also turns an unreadable archive into a reason.

**Applied before anything is written:**
- `HeadlessModManagementService`: the MOD install, the flat and folder snapshot restores, the UE4SS release zip (returns
  `Ue4ssInstallResult.Failure`) and the UE4SS engine snapshot.
- `HeadlessBackupService`: the restore extraction.
- `MystTiqSelfUpdate`: before unpacking, after the checksum check.

**Evidence (LogicHarness "Archive limits (Q-15)"):** too many entries and too much expanded size are refused with the
reason; a normal archive passes; a broken one says so.

## Q-9 — Secrets out of logs, a role on every change

**`SecretRedaction` (Core):**
- `Url()` keeps scheme, host and port.
- `Arguments()` hides the value of pass/password/token/secret/apikey/key arguments (`-k=v`, `k:v`, or a flag followed by
  its value), leaving `@mysttiq:` options alone.
- `Text()` replaces known values.

**Used in:**
- the failed webhook and Discord send logs (they wrote the full URL, token included);
- the console's "Arguments:" line (and therefore its exports);
- the identity guard's launch advice.

**The channels route:** `GET /notifications/channels` defaulted to Viewer and returned every webhook URL and the SMTP
password.
- It now needs Admin, like the Discord bot's route, and returns `GetChannelsView()`, which has no SMTP password.
- `SaveChannels` keeps the stored password when a save carries none, and clears it on an empty one.
- No Desktop page reads this route; the scripts only write it.

**Roles:**
- Per-server routes default to Viewer for reads and Admin for changes (`RequireRoleByDefault`).
- Every fleet route that changes something declares a role, except the four sign-in routes (`auth/login`, `logout`,
  `browser-login`, `password`), which act on the caller's own session.
- The v1.0.7.4 gate parses `LocalManagementApiHost.cs` and fails on any other fleet change route without a role.

**Evidence (LogicHarness "Secrets in logs (Q-9)"):**
- A failed send to a closed port leaves no token in the activity log, only `http://127.0.0.1:<port>/****`.
- Password-style arguments are hidden.
- The channels view has no SMTP password; saving it back keeps the password, and an empty one clears it.

There is no diagnostics export bundle to scrub.
