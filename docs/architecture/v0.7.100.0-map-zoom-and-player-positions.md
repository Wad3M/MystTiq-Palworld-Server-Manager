# v0.7.100.0 — Map: Zoom, Click-to-Zoom, and Last-Known Player Positions

## Context

Two requests on the Map page (v0.7.99.0):

1. "We need to enable a zoom with the scroll wheel. Clicking on a marker should zoom it in."
2. "Can it show the last location or current location of people and identify if online or offline?"

The second one was already on the follow-up list. The map only drew players the server was currently reporting,
so with the server stopped there was nothing to see for anyone. The decoded save turned out to hold what was needed:
each player character has a `LastJumpedLocation`. On the real world all five players' last positions convert to
within a few map units of the game's start plateau (240, -513): M3llyM (245, -519), Wade (245, -494), Spiral
(244, -499), Melly (246, -499). That is also an independent check on the v0.7.96.0 calibration.

## What changed

- **Scroll to zoom**, toward the cursor (the point under the cursor stays put), 1.25x per notch up to 10x; the page
  no longer scrolls while the wheel is over the map. **Drag to pan**, clamped so the map never slides out of frame.
  Zooming all the way out returns to the exact whole-map view. A zoom readout, a Reset View button, and the hint
  "Scroll to zoom, drag to pan, click a marker or a name to zoom in on it" sit above the controls.
- **Click a marker or a name to zoom in on it**: player dots, base squares, the players list and the bases list.
  It zooms to 4x centred on the marker (never out from a closer view; near a map edge the marker stays in frame
  rather than showing empty space). A player click also still selects that player for Teleport To Me / To Player.
- **Online and offline players on the map.** Online players are solid green dots at their live REST position.
  Players who are not online are hollow grey rings at the last position the save recorded, with a grey name.
  Anyone the server lists as online is never also drawn offline. The lists say `● name (x, y) online` or
  `○ name (x, y) offline`; tooltips add "save written <time>" for offline players. A switch turns offline players
  off. The status line says how many are drawn ("5 offline player(s) shown at their last known position from the
  save").
- **Backend:** `SavePlayerLocationReader` reads each player character's `LastJumpedLocation` from the decoded
  Level.sav.json the explorer already parses, and the explorer snapshot carries `playerLocations`. It ignores
  characters with no player id (pals), 0,0 and placeholder altitudes, and a failure to read them degrades to none
  without touching the guild and base data.

## Design notes

- The zoom maths is a pure `MapViewport` (no UI dependency): `view = canvas * scale + offset`, offset clamped to
  `[size * (1 - scale), 0]`. Markers are recomputed at the current zoom rather than scaled, so they keep their
  size and stay clickable; only the background image is scaled (`MapImageTransform`).
- The map surface is now 482 px wide so the 1 px border leaves exactly the 480 map units the maths assumes.
- Wheel and drag are handled on the map surface. A press on a marker is handled by the marker's own button and
  never starts a pan, so clicking and dragging do not fight.
- `Map` viewport resets when the tab (server) changes.
- **Found while checking the final build:** opening a page while the app was still busy (start-up work, another
  refresh) skipped that page's load silently, because `RefreshPageForNavigationAsync` began with
  `if (IsBusy) return;`. Opened right after launch, the Map page stayed empty until Refresh was pressed (the
  Players page had the same gap). The Map and Players pages now wait for the busy state to clear (up to a
  minute) and load if the user is still on the page. Every other page keeps the old behaviour.

## Honest limits

- **Last known is approximate.** `LastJumpedLocation` is where the game last recorded the character, not a live
  position and not necessarily the exact logout spot. It is labelled "last known position" everywhere, with the
  time the player's save was written.
- Players who were all standing together (as in the test world) draw on top of each other even at 10x; their
  labels overlap. The list beside the map picks one by name. Label de-overlap is not done.
- The 1024 px map image gets soft beyond about 2x. It is a bundled screenshot, not vector.
- Only the calibrated Palpagos map shows offline players (saved positions only mean something there).

## Verification

- Solution and Desktop builds clean, 0 warnings/errors.
- Logic harness, 4 new or changed scenarios: viewport (cursor-fixed zoom, clamps, exact return to the whole map;
  pan clamp, centring, corner handling, never zoom out on click, reset), the save reader (real player, pal with no
  id, 0,0, placeholder altitude, string-typed numbers, id normalised like the player list's, empty save), and the
  offline status text.
- New live route smoke `Test-v0.7.100.0-RouteSmoke.ps1` (isolated sidecar, fixture Level.sav.json): the route
  returns exactly the two players with real locations, in the player list's id format; the placeholder and the
  pal are left out; every location id matches a player in the same snapshot.
- **Driven and seen live** (window rendered with PrintWindow, input sent as window messages, on a tab for the
  "Palworld Server 2 (Clone)" profile which holds a copy of the real world): the offline rings at the start
  peninsula and the status line; six wheel notches gave "Zoom 3.8x" with the map under the cursor and the page
  not scrolling; further zoom reached the maximum; Reset View returned to the exact whole map; clicking the base
  square, the base label and a player ring each gave "Zoom 4.0x" centred on it; drag moved the map by exactly
  the drag distance and stopped at the map edge; the players list showed "○ Wade (245, -494) offline" and the
  rest, and "Selected: Melly" after a ring click.
- **NOT verified:** online (solid green) dots, since the server was stopped and nobody was online; that path is
  unchanged in behaviour from v0.7.99.0 apart from zoom and the offline filter. Clicking the World Tree map or a
  browsed image (no saved-position mapping there).
