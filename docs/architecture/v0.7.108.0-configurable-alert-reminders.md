# v0.7.108.0 — Alert Center: Configurable Reminder Interval

## Context

Direct follow-up to v0.7.107.0's reminder re-alerts: the interval was an env-var-only live-testing knob
(`MYSTTIQ_ALERT_REMINDER_MINUTES`), the same tier of control `MYSTTIQ_ALERT_EVAL_SECONDS` already has, and its
own checkpoint named "a Desktop UI setting for the reminder interval" as a follow-up not yet built. This
version makes it a real, persisted setting on the Alert Center page.

## What changed

- `AlertRuleSet` (`HeadlessAlertCenterService.cs`) gained `ReminderMinutes` (`int`, default 1440 = 24 hours).
  It persists in the same `rules.json` every other rule field already does, through the same
  `GetRules()`/`SaveRules()` round-trip and the same `/api/v1/alerts/rules` GET/PUT route — no new route was
  needed. `System.Text.Json` gives a rules file saved before this version (with no `reminderMinutes` key at
  all) the same 1440 default on load, not `0`/disabled, confirmed with a literal pre-v0.7.108.0-shaped JSON
  string in the harness.
- `HeadlessAlertCenterService.GetReminderInterval()` replaces the old static, env-var-only
  `ReminderInterval`/`ReadReminderInterval()`. `MYSTTIQ_ALERT_REMINDER_MINUTES` still overrides everything when
  set (exactly as in v0.7.107.0, so that version's own live smoke needed no changes); when unset, it reads
  `GetRules().ReminderMinutes` instead of a fixed constant.
- `AlertRuleSetDto` (Desktop) gained the matching `ReminderMinutes` (`int`, default 1440).
- `MainWindow.axaml`: a new row on the existing "Threshold Rules" card, "Reminder every (minutes, 0 = off)",
  a `NumericUpDown` (0 to 10080/one week) bound to `AlertRules.ReminderMinutes`, saved by the same existing
  "Save Rules" button — no new command, no new card.

## Deliberately not done

- Still one global cadence for every rule, not a per-rule field. Rejected for the same reason v0.7.107.0's own
  doc gave: it matches `EvaluationInterval`'s existing global-not-per-rule design and avoids widening all four
  `AlertRuleSet` rule-record shapes for one setting.
- No change to what a reminder looks like or when it's pinned (still never pinned) — this version only makes
  the cadence itself configurable.

## Verification

- Solution and Desktop builds clean, 0 warnings/errors.
- Logic harness, 1 new scenario: a fresh `AlertRuleSet` defaults to 1440; a configured value round-trips
  through `JsonSerializer` like every other field; a literal JSON string shaped like a rules file saved before
  this version (no `reminderMinutes` key) still loads with the 1440 default, not `0`.
- New live smoke `Test-v0.7.108.0-RouteSmoke.ps1` on a real sidecar, deliberately **without** setting
  `MYSTTIQ_ALERT_REMINDER_MINUTES` (proving the configured value drives behavior on its own, not just the env
  override v0.7.107.0's smoke already covers): the default is 1440 and survives an unrelated save; setting
  `reminderMinutes` to 1 through the API alone makes a still-active condition remind within about a minute;
  setting it to 0 disables reminders even though the condition stays active. 3/3 passing under strict mode and
  on the final published binary.
- Live UI check (window rendered with PrintWindow; helper `ui-capture-helper.ps1`): opened Alert Center on the
  clone, confirmed the new "Reminder every (minutes, 0 = off)" row renders with the tooltip and the default
  1440 value, alongside the existing rules and Save Rules button.
