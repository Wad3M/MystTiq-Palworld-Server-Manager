# v1.0.0.5 — Distinct Bases and Guilds Pages (internal)

Asked 2026-10-05, with screenshots: "the bases and guilds sections look too similar and have redundant data. Can we make
them look unique?"

## What was the same

Both pages were one view (`IsPlayerGuildExplorerPage`). Under a one-line description they shared:

- the state line;
- three count cards (base references, guilds, semantic evidence with the decoded file's path);
- the "Evidence Model" card, two paragraphs about how identities are derived;
- the warnings card.

Below that, each list repeated the guild's name, guild ID and leader (Bases showed the guild for every base; Guilds
showed the leader as "name · 32-hex ID"). The Bases detail card was mostly the guild again.

## What each page is now

- **Bases (places):** cards with the decoded location (`BaseLocationDto`, shown in map units like the Map page), the Pals
  working there (`PalLocationDto` with `Placement == BaseWorker` and the base's ID; most common kinds first, "+N" past
  three), and the owning guild. The detail lists every worker (name or nickname, level, owner). **Show on map** opens the
  Map with base markers and the map expanded, then calls the existing `ZoomToBase` once the page has laid out. **Open
  guild** selects the guild and switches page.
- **Guilds (people):** cards with the name, the leader (♛), member and base counts, and how many are online. The detail
  has the roster from the guild's member IDs matched to the explorer's players: the leader first, then who is online,
  then by name; unknown names show the start of the ID. Each row shows "Online", "Last saved …" (the player save's time)
  or "Offline". The guild's bases are listed with their locations and **Open base**.
- **Shared:** one summary line per page ("2 bases · 1 on the map · 14 Pals working" / "2 guilds · 4 members · 0 online"),
  the explorer's detail line in small text, and the warnings card only when there are warnings. The context menus and
  the transfer, recovery and guild-operation cards are unchanged.

Found live while checking it: Show on map did nothing. `NavigateCommand` takes the page's name (the XAML passes
`CommandParameter="Bases"`), and the new commands passed the `NavigationPage` value, which a `RelayCommand<string>`
ignores. They now call `Navigate(nameof(NavigationPage.Map))`. The ArtworkHarness runs all three links and checks the
page they land on; it failed with the first version. (Older harness code that passes the enum to `NavigateCommand`
silently stays on the current page; the harness switches pages through `SelectedPage` instead.)

The explorer read now also gives the map its base locations (`ApplyBaseLocations`), so Show on map works without
visiting the Map first.
