# v0.7.42.0 — Cross-Page Consistency Sweep

## Goal

Eighteenth version in the GUI/workflow/UX overhaul roadmap. Unlike every other version so far, this one didn't come from the original 57-item findings log — it's a direct mid-session request: *"apply the logic of the updates we have made from the updated pages to check the other pages and apply them there to, such as moving specific buttons to the ribbon."*

## Numbering

The request asked for this to be shipped as "v0.7.43.0." Every version this session has been strictly sequential with no gaps, so it's shipped as **v0.7.42.0** instead — the immediate next slot after v0.7.41.0. The originally-planned v0.7.42.0 (**Update Center Overhaul**, item 51 — already flagged as the largest single item in the roadmap, expected to need its own sub-plan) is deferred to **v0.7.43.0+**, and everything after it in the roadmap shifts down one slot: UE4SS Release Catalog Backend → v0.7.44.0+, Per-Tab Color Coding → v0.7.45.0, "+" Flow Restructure → v0.7.46.0, Dashboard Layout Density → v0.7.47.0. The plan file's roadmap was updated to reflect this before implementation started.

## Investigation

`MainWindowViewModel.BuildRibbonGroupsForActivePage()` already had per-page ribbon groups for exactly 8 pages, all added during v0.7.26.0-v0.7.28.0's three original ribbon-consolidation passes: Server Setup, Configuration (Server), Console, Workspace, Backups, MOD Dashboard/Library (shared), UE4SS, Server Doctor. Every other page's `Is*Page` computed property in the ViewModel (confirmed by grep: `IsActivityAuditPage`, `IsAlertCenterPage`, `IsAutomationPage`, `IsBasesPage`, `IsCrashAnalyzerPage`, `IsDashboardPage`, `IsDiagnosticsPage`, `IsFleetPage`, `IsGuildsPage`, `IsNotificationsPage`, `IsPlayersPage`, `IsSaveToolsPage`, `IsSecurityPage`, `IsSettingsPage`, `IsUpdateCenterPage`, `IsWorldExplorerPage`, `IsWorldTransactionsPage`) had never been touched by ribbon relocation.

Read through every one of those pages' XAML to find which still had page-header action buttons in-page (the same shape the original passes relocated: a `Grid ColumnDefinitions="*,Auto"` with primary actions in the `Auto` column, distinct from workflow-embedded buttons inside a labeled feature card). Confirmed Dashboard, Activity & Audit, and Settings had nothing left to relocate (Dashboard's own header already says "Server actions are in the ribbon above"; Activity & Audit and Settings have no header-row buttons at all). 13 pages did.

## What stayed in-page, deliberately

Matching the precedent already set by Backups' Retention Cleanup apply button (kept in-page in the original roadmap, not relocated, because it's a confirm-gated destructive action embedded in a specific workflow card, not a page-level primary action):

- **Fleet Actions** card (Backup All/Doctor All/Update All) — a labeled cross-fleet feature block, not the page header.
- **World Transactions' Repair Center** (Analyze ZIP Archive, Apply With Fresh Safety Backup) — a multi-step confirm-gated workflow with its own checkbox right there.
- **Alert Center's Discord Bot / Anti-Cheat** refresh buttons — each tied to its own collapsible section (`IsDiscordBotExpanded`/`IsAntiCheatExpanded`), not always visible, not a page-level action.
- **World Explorer's "Validator & Recovery"** button — an in-page cross-navigation link to the World Transactions page, not an action, left as-is (Console/Doctor in the global Quick Actions ribbon group are the only precedent for ribbon-hosted navigation, and those are page-agnostic shortcuts, not a link specific to one page's own content).

## Two real bugs fixed along the way

While reading Network Diagnostics' header row, found two things that weren't just candidates for relocation:

1. **"Re-run Network Tests" was a literal duplicate of "Run Diagnostics"** — both bound to the identical `RunNetworkDiagnosticsCommand`, sitting side by side. Removed rather than relocated; only one button reached the ribbon.
2. **"Open Server Log"** (`NavigateCommand` → `Console`) was redundant with the always-present global ribbon Quick Actions group's own "Console" button, reachable from every page regardless of which one is active. Removed rather than relocated.
