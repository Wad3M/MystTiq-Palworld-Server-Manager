# v1.0.8.2 — The Players Page (internal)

Roadmap C-2, on the C-0 pattern.

## PlayersViewModel (`vm.Players`)

**What moved:**
- the player directory: records, filters, the duplicate-name option, search;
- the selected player's notes, warnings and metadata;
- the moderation actions: kick, ban, unban, promote, whisper, delete;
- the moderation lists: temporary bans, the ban list, the whitelist, and their cards' expanded state;
- the moderation providers line;
- the starter kits and Give Item sections, with the picker;
- the former `NameGuard`, `PalBox` and `Inventory` partial files.

**How it was done:** a reusable mover (`move_members.py`, kept with the release tooling) extracts the listed members by
declaration with their leading comments, the marked sections and the partial files. It routes the window state through
the session, moves the constructor's command assignments and initializer calls, makes members the window still uses
`internal`, and rewrites the window, the XAML (sub-paths included) and the harnesses.

## What stays with the window, and why

- **`RefreshPlayersPageAsync`** is one part of the whole status refresh (status, metrics, logs, base locations, the
  connection state), so it stays and fills `Players.*`.
- **The page calls back into the window** through two delegates its constructor takes: `refreshActivity` (awaited after
  a moderation action, as before) and `refreshPage`.
- **The teleport commands** use the map's teleport code, so they stay with the window. The page raises
  `CommandStatesChanged`, and the window re-evaluates them, so they still follow the selected player.
- **The session gained `BuildProfile()`.** It builds the connection from the active tab exactly as
  `BuildProfileFromEditor` did, throwing the same reasons.

## Found while moving

**The busy-state refresh.** `RaiseAllAsyncCommandStates` collected only the window's own commands, so after a busy spell
Save names and Save Whitelist stayed disabled (the v1.0.0.2 ArtworkHarness check caught it). It now collects every
page's commands too.

**The language-change reload** (a loaded Give Item catalog is read again in the new language) is now
`Players.OnLanguageChanged()`, not the window reaching into the page's fields.

## The gate

The carried contracts' window-code variables now read `Get-MystTiqWindowCode`, which is `MainWindowViewModel.cs` and
the page ViewModels together, so a check follows the code to its new file. The split's own contracts (v1.0.8.0 on) keep
checking the main file alone. Pins on text that changed with the move (`Players.*` bindings, the code-behind's
`vm.Players.*`, the language reload) were swapped.
