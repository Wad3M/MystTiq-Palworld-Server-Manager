# v0.9.3.0 — the service's own messages

## What changed

The MystTiq service (`mysttiq-server`, projects `MystTiq.HeadlessHost` and `MystTiq.Core`) keeps building its messages
in English: Doctor findings, operation results, crash explanations and remedies, network and router checks, recovery
steps, validation errors. They reach the Desktop over the API and are shown through the same path as the Desktop's own
messages since v0.9.1.0: `{services:TrText}` bindings and `Localizer.T` look each text up in `MessageCatalog`.

v0.9.3.0 adds those texts to the catalog: 1,339 more `msg.*` keys in `Assets/i18n/en.json` and in each of the other 11
languages (3,490 keys per language, 2,492 of them messages). The service itself did not change. The catalog already
handles exact texts, templates with values (`{0}`), texts that begin a longer one ("Configuration did not validate: " +
details), multi-line texts and texts composed of sentences.

One matching rule changed in `MessageCatalog.TranslateLine`. Since v0.9.2.0, a line made of sentences that each
matched something was translated sentence by sentence, before a template for the whole line was tried. That stops
"{0} base(s) shown…" from swallowing the sentence before it as its value. But one of the service's messages is a
two-sentence template: "Ready: base {0} will transfer from {1} to {2}. Every structure … updated to match." It was
being split into "Ready: …" and "Every {0}". Now a whole-line template is tried first, and it is accepted only when
none of its values spans a sentence break. A template that would swallow a sentence still loses to the sentences, as
before.

## Why the service does not translate

- One service can serve several Desktops, each in its own language; the Desktop knows the viewer's language, the
  service does not.
- The service's logs, history, alerts and API stay in one language, so they can be searched and compared.
- The Desktop's logic already compares English values; translating only on the way to the screen keeps that working.

## What stays English, on purpose

- Commands sent to the game server (`KickPlayer {0}`, `TeleportToMe {0}`, the shutdown notice) — they are what the
  game receives.
- Log patterns the crash analysis matches (`Killed process \d+`, `Trying to resize TArray to an invalid size`,
  `The code execution cannot proceed`).
- Protocol and file text (the UPnP search request, systemd unit lines, `LoadState=…`).
- Names Windows or the router keep: the Windows service's display name and description, the firewall rules' and the
  UPnP mapping's names, so what the Desktop shows matches what Windows and the router show.
- Product names (Palworld RCON, Palworld REST API, Steam Web API, Visual Studio).

A text the Desktop already had (the same English) keeps its existing key and translation.

## How the texts were gathered

Every string literal in the service's C# that reads as prose (starts with a capital, has lower-case words and a space
or a final full stop), with interpolations turned into `{0}`, `{1}`…, and C# escapes (`\\`, `\"`) resolved. Texts
that are only data (URLs, routes, file names, JSON names, log calls) were left out.

## Translation review

The translations are drafts. `scripts/Export-MystTiqTranslationReview.ps1` writes a CSV per language with every text,
its English, its kind and where it is used, plus Correction and Notes columns; `docs/i18n/TRANSLATION_REVIEW.md` is the
reviewers' checklist (terminology, plurals, dates and numbers, length, accessibility names). The review needs native
speakers and stays open on the roadmap.

## Verification

- The release gate checks that at least 2,400 messages exist and each is present in all 11 languages, that the
  service's messages are among them, and that commands and Windows names are not.
- The ArtworkHarness shows a service message in Japanese, keeps a value inside one, leaves a server command alone,
  and round-trips every template in every language. The round trip fills the English with sample values, and the
  result must come back as the language's text with the same values. A message that begins a longer text is now
  tried with a rest after it, as the service sends it.
- Live: Doctor's findings in Japanese on the running Desktop.
