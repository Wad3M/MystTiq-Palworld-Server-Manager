# v0.8.5.0 — Display Language (first slice)

This is the start of the roadmap's multi-language UI, which was scoped to v0.8.x. It builds the whole mechanism and
translates the first visible layer: the 7 category tabs, the 26 navigation items, and every page's title and
subtitle, into German and Spanish. Everything else stays English for now, and the Settings page says so.

## Mechanism

- **Translation files.** Strings live in `src/MystTiq.Desktop/Assets/i18n/<code>.json`, as flat `"key": "text"` pairs
  embedded as Avalonia resources. There are 89 keys: `category.*`, `nav.<Page>`, `page.<Page>.title|subtitle`, and
  `settings.language.*`.
- **English is the reference and the fallback.** `en.json` was generated from the strings the app hardcoded in
  v0.8.4.0, so English reads exactly as before, and a gate contract spot-checks this. A key missing or blank in the
  chosen language falls back to English (`Localizer.Lookup`). The key itself only appears if English lacks it too,
  and the gate prevents that.
- **`Localizer`** is the one instance of the current language. XAML uses `{services:Tr key}`, a binding to
  `Localizer.Instance.Strings[key]`. `Strings` is replaced by a new object on every language change and announced as
  an ordinary property change, so every bound text updates at once, without a restart.

  The first attempt raised Avalonia's indexer notification (`Item[]`) instead. The headless harness showed the page
  header switching while the bound tabs and navigation stayed English, so it was replaced.
- **View-model strings.** Page titles and subtitles read `Localizer.Instance[...]` and are re-raised on
  `LanguageChanged`.
- **The choice.** Settings → Appearance → Language applies at once and is saved in `language.json`, beside the other
  Desktop-local preference files. The saved language is applied in the view model's constructor, before anything is
  shown.
- **Adding a language** means adding one JSON file plus one line in `Localizer.Languages`. The gate fails if any
  language is missing a key English has.

## Choices made

- **German and Spanish first.** Both use Latin script, so there is no font-fallback risk in this slice; CJK needs a
  font check first.
- **Translated here.** These translations were written for this release and have not been reviewed by a native
  speaker. Product and technical names (MOD, UE4SS, PalServer, SteamCMD, Oodle, API) are kept as they are.
- **Ribbon labels stay English in this slice.** `RibbonIcons` maps icons by the exact English label, so translating
  them needs a label key separate from the display text. That is a follow-up.

## Verification

- **ArtworkHarness** (offline headless render of the real window), 239 checks in total. The language checks cover:
  - every page has an English title and subtitle;
  - German and Spanish have exactly English's 89 keys, none blank;
  - the fallback;
  - for each of German and Spanish: the tabs, navigation, header and a second page switch live; all 7 tabs fit the
    category bar at the minimum 950×650 window; and the header still cannot cover them;
  - switching back restores English;
  - the Settings picker applies and saves the choice.

  The harness redirects the language store into its own output folder.
- **Gate contracts:** every `{services:Tr}` key in the window exists in English; German and Spanish match English's
  key set; English is unchanged.
- **Live Desktop:**
  - choosing Deutsch switched the tabs, navigation, header and the language label and note at once
    (`language-de-live.png`);
  - after closing and reopening, the app started in German;
  - choosing English switched back, and the saved preference is now `en`.

## Not done yet

- Other languages, including CJK, which needs its own font check.
