# v0.8.14.0 — Cards Follow the Signed-In Role

This is the fifth item of the automated run and the first of the multi-user follow-ups: "hide more cards by role".

## Before

The server enforces every route by role (`RequireRole`: Viewer < Operator < Admin < Owner, `MystTiqRole`). The Desktop
had two flags:
- `CanManageAdmin`, used to disable about a dozen cards;
- `CanManagePrincipals`, used for two.

The result:
- A Viewer saw every admin card, greyed out.
- Collapsible cards (Whitelist, Starter Kits) could not even be opened when disabled.
- The Give Item box was not gated at all, so the server refused a lower role's click.
- Fleet Actions was gated at Admin, but the server allows Operators (backup, doctor and update for all servers).

## What changed

- **`RoleAccess`** (Desktop, pure) holds the one rule:
  - `Rank(role)` mirrors the server enum;
  - an unknown or mis-cased role gets Viewer, never more;
  - `Allows(signedIn, role, minimum)`: the local, token-less connection (no principal) keeps full access, as before;
  - `HiddenNotice`.
- **The ViewModel** gains `CanOperate` (Operator+) next to `CanManageAdmin` and `CanManagePrincipals`, all on
  `RoleAccess`. It also gains `RoleHiddenNotice`, and all of these are raised when the principal changes.
- **Cards.** A card the role cannot use is **hidden**; a card it can only read is **visible but read-only**:

  | Card | Viewer | Operator | Admin | Owner |
  |---|---|---|---|---|
  | Teleport Points | hidden | read-only | ✓ | ✓ |
  | Give items or Pals (box) | hidden | hidden | ✓ | ✓ |
  | Item/Pal finder | hidden | ✓ (Add buttons read-only) | ✓ | ✓ |
  | Whitelist, Starter Kits (collapsible) | hidden | hidden | ✓ | ✓ |
  | Character / Account Migration | hidden | hidden | ✓ | ✓ |
  | Automation "New Rule" | hidden | hidden | ✓ | ✓ |
  | Threshold Rules, Anti-Cheat rules | read-only | read-only | ✓ | ✓ |
  | Mute Alerts, Pause delivery, Discord Bot | hidden | hidden | ✓ | ✓ |
  | Create Principal, User Accounts, Clone World | hidden | hidden | hidden | ✓ |
  | Fleet Actions | hidden | ✓ | ✓ | ✓ |

  Whitelist and Kits are hidden rather than read-only for Operators because a disabled collapsible card cannot be
  opened, so read-only would show only a closed header.
- **Fleet Actions buttons.** Found in the live check: Backup All, Doctor All and Update All stayed greyed out even
  when connected, for every role. This is an older bug: their commands depend on the connection and on IsBusy, but
  neither re-evaluation list included them. Both lists now do, and the buttons enable once connected. They were not
  clicked, because they act on the real servers.
- **A notice** at the top of the page content ("Signed in as Operator: cards your role cannot use are hidden …") shows
  whenever something is hidden. It does not show for local use or the Owner.

## Verification

- **Logic harness** ("Role cards"):
  - every `MystTiqRole` value ranks as on the server;
  - unknown and mis-cased roles get Viewer;
  - local use gets full access;
  - each role reaches exactly its own level;
  - the notice text.
- **ArtworkHarness: 439 checks.** For local, Viewer, Operator, Admin and Owner in turn, every card in the table is
  found by its title and checked for visible and enabled on its own card border, and the notice shows only when
  something is hidden. `role-operator-security.png` renders the Operator's Security page: notice, principals list,
  and no Create Principal or User Accounts.
- **Server side:** unchanged; every route was already enforced.

## Not done

- The Ribbon's buttons are not role-gated yet (for example Start for a Viewer). The server still refuses them.
- This version is Desktop-only. The live signed-in check against a real remote instance, including on Linux, is
  v0.8.15.0.
