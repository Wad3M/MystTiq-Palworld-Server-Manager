# v0.7.84.0 — Fleet Clone World Workflow

## Context

Direct live feedback earlier this session: "the clone world option in fleet should be a workflow
with drop down options to clarify what it is doing." Follow-up: "it should indicate better what
server is being cloned (server name - description)." The work was fully built and compiled into the
live app at that time, but the user explicitly said "table this for a future update" rather than
shipping it — this version is that future update.

## Changes

- **Clone World is now an explicit, labeled workflow** on the Fleet page instead of a single flat
  card: a **SOURCE** section names the connection this tab currently uses (profile name plus its
  `BaseAddress`, always accurate since it's what the tab actually talks to — chosen over a
  description field since not every profile has one set), a **NEW PROFILE** section for the new
  profile's ID and optional display name, and a **PORT OFFSET** section with a dropdown and an
  explanation of what it does (added to the source server's own ports so both can run at once).
- **New (this version): a "Restart MystTiq Now" button** appears after a successful clone. Reuses
  `RestartOwnedSidecarAsync`, the same mechanism v0.7.83.0 built for the new-server wizard's own
  second-server flow, closing the identical "needs a restart to come online" gap here too — offered
  as an explicit button rather than fired automatically, since (unlike the wizard's brand-new,
  not-yet-in-use tab) this page's connection is already actively in use; the user decides when it's
  convenient to take the local service down briefly.

## Verification

`dotnet build` on `MystTiq.Desktop` and the full solution — clean, 0 warnings/errors. The core
workflow card (source/new-profile/port-offset sections, confirmation checkbox) was already
live-verified during the original session it was built in; the new restart button reuses
`RestartOwnedSidecarAsync`, already proven end-to-end in v0.7.83.0's own live verification.
