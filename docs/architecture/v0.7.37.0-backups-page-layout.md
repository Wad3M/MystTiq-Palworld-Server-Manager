# v0.7.37.0 — Backups Page Layout

## Goal

Thirteenth version in the GUI/workflow/UX overhaul roadmap. Roadmap items 34, 37, and 38 — three layout fixes to the Backups page, grounded against a v0.2.16.4 reference screenshot's Backup Center.

## What shipped

### Removed the redundant header text (item 34)

`MainWindow.axaml`'s Backups page previously opened with a small `StackPanel` showing `BackupState` ("N backup(s)") and `BackupTotalSizeText` directly above the summary cards — both values fully duplicated by the TOTAL ARCHIVES card's own `BackupArchiveCountText`/`BackupTotalSizeText` bindings immediately below. Removed the redundant block; the summary card is the single source of truth for both numbers now.

### Two-column layout (item 37)

The page was previously one long vertical `StackPanel`: summary cards, then the backup table, then a full-width "Selected Backup" card, then a full-width "Retention Cleanup" card — each competing for the same full window width and pushing the table further down with scrolling. The reference build instead splits into two columns: a wide table on the left, and a narrower right-hand column stacking "Retention Policy" and "Backup Locations" cards.

Adapted for this app's current state: wrapped the backup table `Border` and a new `StackPanel` (containing the existing "Selected Backup" and "Retention Cleanup" cards, stacked) in a `Grid ColumnDefinitions="2.2*,*" ColumnSpacing="12"` — table left (wider), action cards right (narrower). The reference's third right-column card, "Backup Locations" (an Open Backup Root action), has no direct equivalent to move here: that exact action already relocated into the ribbon during v0.7.27.0's ribbon consolidation pass, so there was nothing left standing in the page body to carry over. The table's `ListBox` also gained more vertical room (`MaxHeight` 340 → 480) now that it isn't sharing width with the cards below it.

### Created column leads (item 38)

Both the header row and each row's `DataTemplate` reordered their `Grid.Column` bindings from `FileName, CreatedText, SizeText, VerificationText` to `CreatedText, FileName, SizeText, VerificationText` — `Created` is now the leftmost column, `Backup` (filename) second. `ColumnDefinitions` adjusted from `2*,*,*,*` to `*,2*,*,*` so the (typically long) filename column keeps its extra width in its new second position.

Per the original finding, the reference build's own fuller column order is `Created, Size, Status, Verified, Archive` (filename last) — noted there as worth using if column order is revisited beyond just "Created first" in a future pass; this release deliberately implements only the explicitly-requested minimal change (Created leads), not the reference's full column reordering.

## Explicit non-goals

- No further column reordering beyond moving Created to lead — the reference's fuller `Created, Size, Status, Verified, Archive` order (filename last) is left for a future pass if requested.
- No relocation of the Selected Backup card's Verify/Restore/Delete Selected buttons into the ribbon — the original finding flagged this as "worth reconsidering... though not explicitly requested yet," not a firm ask for this release.
