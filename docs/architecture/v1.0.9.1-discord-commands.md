# v1.0.9.1 — Discord commands that answer (internal)

Roadmap B-4 (scheduled by the owner 2026-10-12, D-11).

## What existed

The bot (`HeadlessDiscordBotService`, since v0.6.17.0) registers guild slash commands: `/mysttiq-status`, `-players`,
`-start`, `-stop`, `-restart`, `-save`, `-backup`, `-broadcast`, `-kick`, `-ban`, `-unban`. Each maps to a MystTiq role
(`DiscordBotFormatting.RequiredRole`), the caller's Discord roles map to MystTiq roles, lifecycle commands take the
coordinator's locks (`server-start-discord` and so on), and the backup takes `world-mutation` inside the backup service
(Q-4). The backlog note "alerts only today" was out of date.

## The gap: Discord's 3 seconds

An interaction must be answered within 3 seconds or Discord shows "The application did not respond", and an answer
after that is refused. The bot called `RespondAsync` only after the work. A start waits up to the startup timeout, so a
start, stop, restart or backup always lost its answer. Nothing deferred.

## DiscordCommandFlow

`DiscordCommandFlow.RunAsync(reply, name, granted, execute, record)`:
1. A caller without the role is answered at once, privately, and recorded; nothing runs and nothing is deferred.
2. Otherwise `DeferAsync` (Discord shows "thinking"), then the work, then `EditAsync` with the result.
3. A failure edits the public reply to a plain "Command failed" and sends `Command failed: <reason>` privately (the
   reason can carry paths; before, it was private too).
4. A reply Discord no longer takes (the interaction token lasts 15 minutes) is recorded as "Discord reply not
   delivered"; the work stands.

`IDiscordCommandReply` is the reply side; the bot's `SlashCommandReply` wraps `SocketSlashCommand` (`DeferAsync`,
`RespondAsync`, `ModifyOriginalResponseAsync`, `FollowupAsync`), each with mentions off as before.

## Pre-start check

The REST start and restart run `HeadlessModManagementService.LogPreStartDiagnosticsAsync` first (UE4SS layout and
`mods.txt` reconciliation, logged to the console). The Discord ones did not; the bot is now handed that check.

## Evidence

- LogicHarness: refusal (a Viewer, and no mapped role), acknowledge-before-work with the edited result, a failure with a
  private reason, an expired interaction. The fake reply records every call in order.
- Live (owed by the owner, carried): the owner's bot runs `/mysttiq-backup` and `/mysttiq-restart` and both show their
  results. The bot token and guild are the owner's; this session does not hold them.
