# v1.0.8.4 — The Configuration and Workspace Pages (internal)

Roadmap C-4, with the mover from C-2.

## ConfigurationViewModel (`vm.Configuration`)

**What moved:**
- the Palworld settings editor: the simple and advanced views, categories, search, validation, presets, import and
  export;
- MystTiq's own service settings (`Config*`), with the service's timing values;
- the Launcher's start options: the former `MainWindowViewModel.Launcher.cs`, saved with the service settings.

**What stays with the window:** the unsaved-changes guard on navigation (`ContinuePendingNavigation…`), which is part of
navigation.

**How the other pages follow it, without sharing fields:**
- When the service settings are read, the page raises `ConfigurationLoaded`, and the Workspace page checks its paths
  again.
- The page sets the Workspace page's status line through a delegate.
- When `PalworldConfigLoaded` changes, the window refreshes the workspace's health text and the wizard's name generator.

## WorkspaceViewModel (`vm.Workspace`)

**What moved:**
- the folders MystTiq and the server use, and the deployment mode;
- the active world, the world files beside it, and the integrity check;
- validating the active world.

**What it is given:** the paths come from the Configuration page (a constructor parameter), and the server-readiness
checklist (`EnvironmentItems`) is the window's, passed in.

**One change to the World page:** it now validates through `() => Workspace!.ValidateActiveWorldAsync()`, because the
Workspace page is created after it.

**The session gained `IsLocalProfile`.**

## The setup wizard stays with the window

The roadmap lists the setup wizard under C-4. Moving it was tried and reverted: its steps create the profile and the tab,
start the local service, and switch tabs (`IsCreatingNewProfile`, `CreateTab`, the credential store and the bootstrapper).
That is tab coordination, which C-9 leaves with the window. Moving only its form fields would split one flow across
two places. Preparing a world import (`PrepareForWorldImportAsync`) starts and stops the server for the wizard, so it
stays too.

## Found while moving

**Tuple-typed fields broke two mover scans.** One declaration is `static readonly (string Name, …)[] …`:
- the declaration finder could not match the tuple type;
- the name scan read the keyword `readonly` as a member name.

Both are fixed.

**Static members.** A static member is now reached through its class (`WorkspaceViewModel.IsAbsoluteServerPath`).

**A harness check that could skip itself.** It reflected on the window by property and method name, and silently
skipped when the method was missing. It now reads the Configuration page and fails if the method is gone.
