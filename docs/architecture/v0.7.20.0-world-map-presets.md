# v0.7.20.0 — World Map Presets

## Background

Requested directly, alongside a broader plan for finishing the session's remaining backlog items. The user provided two real Palworld map images — `docs/images/palpagos.webp` (the base game map, "Palpagos Islands") and `docs/images/worldtree.webp` — to incorporate into the existing World Map card (`MainWindow.axaml`, Players page, v0.6.16.0). Before this release, the card's background was entirely "browse for your own image" (`BrowseMapBackground_Click`, `MainWindow.axaml.cs`) or nothing at all (a plain coordinate grid) — there was no bundled default.

This is deliberately the first of two related versions. The user's stated goal is real coordinate calibration (player dots placed at their true in-game position, not just a nicer background) — but that's a materially higher-risk change with its own open research question (see `docs/architecture/v0.7.21.0-*.md` once written). Splitting the two apart means this release's real, low-risk value (bundled presets) ships independently of how the calibration research resolves.

## What shipped

### Image preparation

Both source images were 4096×4096 WEBP (~0.8-1.1MB each). The World Map canvas (`MainWindow.axaml` ~928) is a fixed 480×480 `Border`, so the source resolution was pure unnecessary weight — converted via ImageMagick to 1024×1024 PNG (still comfortably sharp at 480×480, including on a high-DPI display) and re-compressed, landing at ~850-930KB each, roughly the same footprint as the WEBP originals despite the format change. Bundled under `src/MystTiq.Desktop/Assets/Maps/`.

### `MapPresetService` — extract once, reuse the existing load path entirely

The core design decision: **do not build a second image-loading path for presets.** `SetMapBackgroundImagePath(string path)` (`MainWindowViewModel.cs` ~1222) already does everything needed — loads a `Bitmap` from a real file, persists the choice via `LocalMapPreferencesStore`, and falls back cleanly to the plain coordinate grid if the file is ever missing/unreadable. A preset only needs to become "a real file" once, and then it's just that same mechanism.

New `MapPresetService` (`Services/MapPresetService.cs`) exposes a static `Presets` list (`MapPreset(Key, DisplayName, AssetUri)` — `"palpagos"`/`"Palpagos"`/`avares://MystTiq.Desktop/Assets/Maps/palpagos.png`, and the World Tree equivalent) and one method, `GetOrExtractPresetPath(MapPreset)`: checks whether the preset has already been extracted to `<local config root>/MystTiq/MapPresets/<key>.png`; if not, opens the bundled `avares://` asset via `Avalonia.Platform.AssetLoader.Open(...)` and copies it to that path once. `LocalMapPreferencesStore` gained one new public static method, `GetLocalConfigRoot()` (exposing its existing private `GetConfigRoot()` cross-platform resolution logic), so `MapPresetService` shares the exact same config root rather than duplicating that resolution.

`MainWindowViewModel.SetMapPreset(MapPreset?)` (new, next to the existing `ClearMapBackground`) calls `GetOrExtractPresetPath` then `SetMapBackgroundImagePath(path)` — two lines, all the real logic (Bitmap loading, preference persistence, fallback behavior) already existed.

### UI

The World Map card's header `Grid` (`MainWindow.axaml` ~914-924) previously carried the expand/collapse toggle plus the Browse/Clear buttons in three columns — already tight, and now needs two more buttons for the presets. Simplified back to a single-column toggle; a new `WrapPanel` inside the expanded content area (right after the card's description text) now holds an `ItemsControl` of preset buttons (bound to `MainWindowViewModel.MapPresets`, one `Button` per `MapPreset` via `SetMapPresetCommand`/`CommandParameter="{Binding}"`, the same `$parent[ItemsControl].((vm:MainWindowViewModel)DataContext)` reach-up-to-the-page-ViewModel pattern already used elsewhere in this file for per-row commands) alongside the pre-existing Browse and Clear buttons.

## Explicit non-goals

- **Real coordinate calibration.** `RebuildPlayerMapPoints` (~3361) is completely untouched this release — dots still auto-fit to the bounding box of currently-online players, exactly as before. Sequenced as its own version specifically so this release's real, working feature isn't gated on unresolved calibration research.
- **A third/custom preset management UI** (rename, delete, add more than the two provided). Out of scope — two fixed, bundled presets plus the pre-existing browse/clear is what was asked for.

## Verification

- Full solution `dotnet build` (Release) — 0 warnings/0 errors, after fixing one instance of the recurring XML-comment-`--` AVLN1001 parse error in a new comment.
- Both converted PNGs verified to have a valid PNG signature.
- The Desktop app was launched directly (`dotnet run`, ~12 seconds, then stopped) and produced no startup exceptions or error output — a real, if partial, signal that the new `avares://` asset references and `MapPresetService`/`MainWindowViewModel` wiring don't break app construction.
- No GUI click-through capability in this environment (unchanged, disclosed every version) — actually clicking a preset button, confirming the file extracts correctly on first use, reuses the cached copy on subsequent clicks, and renders in the 480×480 canvas is left to the user.
