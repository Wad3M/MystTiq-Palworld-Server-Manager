# v1.1.1.0 — MOD Sources, player checks without a desktop, Linux and Docker downloads (internal)

Roadmap F-4 to F-13. Owner, 2026-10-14: "I would like to move the MOD Browser, Nexus Mods Catalog, and whatnot to its own
item under MODs called MOD Sources and implement those 9 fixes", and mid-version: "our package should include a linux
build and a docker build". The nine fixes are the deficiencies listed after v1.1.0.3.

## F-4 MOD Sources

`NavigationPage.ModSources` is appended (saved page numbers keep their meaning). The page shows an introduction, the Steam
Workshop card (`WorkshopSourceCard`), the MOD browser (`ModBrowserCard`) and the Nexus Mods catalog. MOD Library keeps the
summary and the ZIP install side by side, the load order and profiles, and the installed MODs. The Workshop scan runs on
arriving at MOD Sources (once per tab, as before on MOD Library); Refresh on the Ribbon scans again; a Nexus
`nxm://` link opens MOD Sources. The nav entry reuses the MOD Dashboard icon (the icon set stays at 28 files).

## F-5 Player checks without a desktop

The player checks ran inside the `/status/poll` route, so with no desktop open nothing checked joins (the case of a
service, a systemd unit or Docker). They are now `RunPlayerChecksAsync` (same order: player list, whitelist, join check,
identity guard, pending moves, name guard, kits, temporary bans), called by the poll through
`HeadlessPlayerWatchService.RunFromPollAsync` and by the service's own 15-second timer when no desktop has polled for
30 seconds. One `SemaphoreSlim` keeps the two from running at once; a failing read is logged once per distinct message.

## F-6 The new-character notice

With automatic moves on, a player listed with no character after the 90-second loading grace whose character exists
under their old ID is kicked once with `IdentityGuard.NewCharacterNotice` (their character is safe; join again, make a
character with any name; MystTiq moves theirs onto it). Within 30 minutes they are let through, as v1.1.0.2 did, to make
the character the move replaces; after 30 minutes they are told again. The kick message is what Palworld shows on
disconnect, so it stays English.

## F-7 Every account

An account's character: the learned ID, else the Steam formula's when that character exists, else the earliest-seen
record in the player list for that account whose character exists. The player list covers Xbox (`gdk_`) accounts and
accounts seen before MystTiq learned their ID. The guard's alert says "their account's character".

## F-8 A link by hand

`POST /players/ids/link` (Admin) with `userId` and `playerId`: refused without an account, with a malformed ID or with no
character file for it. The ID is learned for the account; when the account's last join was given another ID that has a
character, a move from the linked character to that ID is queued (run when nobody is online, or with Restart server and
move character); otherwise the next join is checked against it. Players > Player IDs has the form.

## F-13 Linux and Docker downloads

The release workflow gets a `docker` job on `ubuntu-latest` running `scripts/Build-DockerImage.ps1 -Save` (publishes the
linux-x64 service, builds `deploy/docker/Dockerfile`, saves the image as
`MystTiqPalworldServer_v<version>_Docker-linux-x64.tar.gz`); the release job packages the Linux download
(`Package-GitHubRelease.ps1 -Runtime linux-x64`), fetches the image archive and hashes and attaches everything. Linux
desktop acceptance (E-4: file pickers, scaling, other desktops) is still open; the owner asked for the download now.

## F-14 Tab switching

Found while running this release's harness: the rapid tab-switch check took about 20 minutes. Measured on a copy with a
stopwatch per step of `ActiveTab`'s setter: `ThemeApplier.Apply` took 3,652 of 3,658 ms per switch with two windows open
and 11,860 ms with six (every theme resource rewritten, every DynamicResource re-resolved in every window); the rest
took under 10 ms. v1.1.0.3 measured the same (4.5 s per switch), so it is older than this release. `Apply` now remembers
what it last wrote (application, accent, mode, palette, contrast theme) and returns when asked for the same again: 14 ms
per switch, whatever the number of windows. A Windows contrast theme is read fresh each time, so in that mode it still
applies. ArtworkHarness: the same theme keeps its resources, another theme applies, and 300 switches stay under 3 minutes.
