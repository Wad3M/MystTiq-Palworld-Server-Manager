# v0.6.18.3 — Configuration Page Overhaul

## Goal

Eight pieces of direct user feedback on the Configuration page — the page that edits the live `PalWorldSettings.ini` through Simple/Advanced views, a QoL preset dropdown, search/filter, and Import/Export.

## Grounding

Investigated the actual page before designing anything; several items turned out simpler than they looked:

- "Generate Server Name" wasn't broken — `GenerateServerNameCommand` already correctly wrote into the same `PalworldSettingDto` instance the Server Identity field is bound to. Pure relocation.
- Quoting is Desktop-only. `PalworldSettingsConfigurationService` (`MystTiq.Core`) round-trips each setting's raw value byte-for-byte, quotes included, with no opinion on display formatting.
- Filter auto-apply already existed for Advanced Settings (`ConfigSearchText`/`SelectedConfigCategory`'s setters already called `ApplyPalworldConfigurationFilter()`); it just never reached the Simple view, which used a completely separate, unfiltered collection.
- Advanced Settings already carried everything needed for diff-highlighting (`DefaultValue`, `IsModified`) — a styling change, not a data change. One refinement: `IsModified` is server-computed once at load time, not live, so a new `IsDifferentFromDefault` computed property was added instead, updating immediately as the user edits a value.
- Simple Settings' expansion had a ready-made source: `SimpleConfigurationNames`, a 34-name curated list already in the codebase, previously only gating a filter with no real UI effect. `RebuildSimplePalworldSettings()` only turned 8 of those 34 into actual controls.
- The "MystTiq preset" needed no hardcoded values at all. Per explicit user choice, it should capture whatever is currently loaded, not a value map guessed and baked into shipped code — exactly what a generic "save current settings as a new named preset" feature already does. "MystTiq" isn't a special case in the code; it's just the first name someone saves.
- Two extra dead-code findings folded in as free cleanup: two hardcoded `IsVisible="False"` blocks (a PalServer/Service/PID card and an Uptime/Last-observed/Last-transition card) that could never actually show.

## What shipped

- **Quote-stripping**: `PalworldSettingDto` gained a `DisplayValue` computed property, gated by a fixed, known list of setting names (`ServerName`/`ServerDescription`/`AdminPassword`/`ServerPassword` — not runtime quote-sniffing, which would be fragile once a value's been edited once). All setting-value `TextBox`es (Simple's identity fields and Advanced's generic row template) rebind from `Value` to `DisplayValue`.
- **Preset auto-apply**: `SelectedConfigPreset`'s setter now calls the existing apply logic directly when it changes (guarded against "Custom," which has no preset data, and against the reverse-detection path, which already bypasses this setter by design). The "Apply Preset" button is gone.
- **Custom presets**: new `LocalConfigPresetStore` (mirrors `LocalMapPreferencesStore`'s exact shape — Desktop-local, `%AppData%/MystTiq/config-presets.json`), a "Save As Preset" name field + button, and `PalworldConfigPresets` rebuilt to include locally-saved names alongside the three built-ins.
- **Live diff highlighting**: `PalworldSettingDto.IsDifferentFromDefault` (new, live) drives a `Classes.differsFromDefault` style on each Advanced Settings row.
- **Simple Settings expansion**: `RebuildSimplePalworldSettings()` rewritten to be data-driven off `SimpleConfigurationNames` (all 34 names accounted for: 4 identity/credential fields handled directly in the Server Identity section, 22 rate settings as sliders via the existing `PalworldSimpleSettingItem`, 2 boolean toggles via a new `PalworldSimpleToggleItem`, 6 port/limit fields as plain text fields), organized into Server Identity / Network, Access & Limits / Gameplay Rates groups.
- **Search/filter**: repositioned to sit directly above the settings list; `ApplyPalworldConfigurationFilter()` now also rebuilds Simple's three collections through the same filter predicate, so both views respect search/category identically.
- **Header cleanup**: the row's `PageSubtitle`-duplicating description text removed; Import/Export promoted to the first, most prominent position. Both dead `IsVisible="False"` blocks removed outright.

## Explicit non-goals (this pass)

- No server-side change — `MystTiq.Core`/`MystTiq.HeadlessHost` untouched.
- Custom presets are Desktop-local only, not synced across machines/profiles.
- Advanced Settings still shows every live key — only Simple's curated subset grew, and only from the already-curated 34-name list.
- v0.6.18.4 (Start/Stop/Restart button state) and v0.6.19.0 (multi-tab) are separate passes.

## Verification

`dotnet build` (Release) across all three projects and the full solution — 0 warnings/0 errors. `scripts/Test-v0.6.18.3-Logic.ps1` static contract checks confirm the structural wiring. This release touches zero server-side code, so the frozen v0.6.18.2 regression gate and the full v0.5.1.5 runtime smoke suite are expected — and confirmed — fully unaffected.

**Real logic-level verification** (a small throwaway console harness referencing the actual `MystTiq.Desktop` project, not a reimplementation): confirmed `PalworldSettingDto.DisplayValue` strips quotes for display and correctly re-adds them on write (`"MystTiq Palworld Server"` ↔ `MystTiq Palworld Server`), that a non-quoted setting (a rate) passes through `DisplayValue` unchanged, that `IsDifferentFromDefault` correctly flips live as a value is edited and reset, and that `PalworldSimpleToggleItem` correctly round-trips `"True"`/`"False"` through its `IsChecked` bool. For the preset store, the harness first checked whether `LocalConfigPresetStore.StoragePath` actually resolved to the real user's `%AppData%\MystTiq\` directory before touching it — it did, so rather than write test presets into the real user's real config directory, the identical JSON round-trip logic was verified against an isolated temp file instead. All checks passed.

**Disclosed verification gap, unchanged from every checkpoint since v0.6.4.0**: no GUI click-through capability in this environment. The actual visual layout and slider ranges feeling right in practice are the user's to confirm once built.
