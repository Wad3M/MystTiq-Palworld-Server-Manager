# v0.7.1.0 — Page Ordering, Tab Bar & Simple Settings Visibility

## Goal

First slice of a broader UX pass the user asked for: audit every page's element ordering for logical sense, investigate a reported Simple Settings bug, add visual "flare," change the tab-bar "+" icon, show each tab's server name + Local/Remote, and work toward every page fitting on screen without scrolling. The full scope was too large for one release; this is the bounded, low-risk first slice. The rest is sequenced as v0.7.2.0 (port-conflict validation for new-server creation), v0.7.3.0 (new-server wizard), and v0.7.4.x (card flare + the no-scroll initiative, both ongoing/directional).

## Grounding

Three research passes preceded this release:
1. A page-by-page audit of all 22 `MainWindow.axaml` pages, reporting element order and a scroll-fit verdict against a ~600-620px budget (1440×880 window minus chrome). Found only ~2 of 22 pages fit today; the rest need real scrolling, several severely. Flagged 8 concrete ordering issues, 7 of which this release fixes (the 8th, Alert Center's three concatenated feature areas, is deferred to the no-scroll initiative since it needs restructuring, not reordering).
2. A deep dive into the reported "Simple Settings not loading all settings, not sectioned" complaint. Found the code already matches the v0.6.18.3 design exactly (34 curated settings, 3 labeled sections, filter above both Simple and Advanced views) — no bug in the source. The one real, confirmed gap: a curated setting missing from the live `PalWorldSettings.ini` (older server build) is silently skipped with no indication.
3. A dive into the tab bar/card-flare/wizard scope, confirming `TabSession` had no Local/Remote indicator and identifying the existing `Border.serverTabSurface`/`ConnectionProfile.LocalDefault` pieces needed to add one.

## What shipped

**Page-ordering fixes** — each a localized reorder in `MainWindow.axaml`, not a redesign:
- Players: the World Map card moved from between the search bar and the player list (which it doesn't filter) to after the player list/detail section.
- Backups: removed the duplicate Verify/Restore/Delete Selected buttons from the top action `WrapPanel` — they remain, correctly gated on `SelectedBackup`, in the "Selected Backup" card.
- Automation: swapped the "Rules" list and "New Rule" creation form so existing rules show first.
- Monitoring/Activity & Audit: moved the CPU/RAM/Threads stat `Grid` above the audit log card instead of below it.
- Fleet: swapped "Server Profiles" and "Clone World" so existing profile IDs are visible before typing a new one.
- Diagnostics Center: "Restart Server" moved behind a `Border` divider and given `Classes="danger"`, separating it from the read-only diagnostic actions (Run Diagnostics/Re-run Network Tests/Add-Repair Firewall Rule/Open Server Log).
- Settings: replaced the editable `ConfigServerRoot`/`ConfigSteamCmdPath`/`ConfigBackupRoot`/`ConfigRuntimeRoot` `TextBox`es (duplicating the same fields on the Workspace page) with a read-only summary and a "Manage in Workspace →" button (`NavigateCommand`/`CommandParameter="Workspace"`).

**Pal Editor relocation**: moved the entire Pal Editor section (list + edit form) from the Guilds sub-page to the Players page, after "Player Administration" and before "Character / Account Migration." Confirmed via code inspection that `RefreshPalsAsync()`/`ExplorerPals`/`SelectedExplorerPal` are not triggered by page navigation (only by their own "Refresh Pals" button), so the move is purely a UI relocation with no ViewModel wiring changes.

**Simple Settings gap indicator**: `MainWindowViewModel.RebuildSimplePalworldSettings()` now computes `SimpleSettingsGapText`/`HasSimpleSettingsGap` — checking all 34 curated names against the live (unfiltered) `PalworldSettings` collection, independent of the search/category filter — and `MainWindow.axaml`'s Simple Settings section shows an amber `Border.statuscard` naming any missing settings when `HasSimpleSettingsGap` is true.

**Tab bar**: `TabSession` gained `ConnectionKindText` ("Local"/"Remote", empty when `Profile is null`), recomputed whenever `Profile` changes. The tab `DataTemplate`'s second row now shows this instead of `ServerUrl`; `Border.serverTabSurface`'s `MinWidth` grew from 180 to 200 and the name row got an explicit `FontSize="12"` to give it a bit more breathing room.

**"+" icon**: `Styles/IconGeometries.axaml`'s two-part capture-sphere icon (`IconAddTabRing`/`IconAddTabDot`) was replaced with a single `IconAddTab` — a plain filled plus-sign `StreamGeometry` — verified by rendering as SVG in the Browser pane and inspecting a screenshot before committing, same technique introduced in v0.7.0.0.

## Explicit non-goals (this pass)

- Port-conflict validation for new-server creation (v0.7.2.0).
- The new-server creation wizard (v0.7.3.0).
- Card "flare" and the no-scroll initiative (v0.7.4.x) — both large enough to need their own passes; see the plan for why full elimination of scrolling isn't realistic in a single release.
- Alert Center's three concatenated feature areas (thresholds/Discord bot/anti-cheat) — flagged by the audit but deferred to the no-scroll initiative since it needs page restructuring, not reordering.
- Any server-side change — 100% `MystTiq.Desktop`.

## Verification

`dotnet build` (Release) — 0 warnings/0 errors. This release touches zero server-side code, so the frozen v0.7.0.1 checkpoint regression gate and the full v0.5.1.5 runtime smoke suite are expected — and confirmed — fully unaffected.

**Disclosed verification gap, unchanged from every checkpoint since v0.6.4.0**: no GUI click-through capability in this environment. This release is entirely reordering/relocation of existing, already-working elements plus two small new bindings — verification here is compile-clean plus static contract checks; the actual on-screen reading order and tab bar appearance are the user's to confirm once built.
