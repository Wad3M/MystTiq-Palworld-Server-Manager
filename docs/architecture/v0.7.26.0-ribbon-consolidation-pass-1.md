# v0.7.26.0 — Ribbon Consolidation Pass 1

## Goal

Second version in the GUI/workflow/UX overhaul roadmap. v0.7.25.0 built the shrink-to-fit ribbon infrastructure (`RibbonActionViewModel`/`RibbonGroupViewModel`, `VisibleRibbonGroups`/`OverflowRibbonGroups`, `BuildRibbonGroupsForActivePage`) specifically so subsequent versions could safely add more ribbon buttons without risking silent overflow. This is the first version to actually use it: items 17, 23, 29, and 30 from the roadmap's findings log.

## What shipped

### Server Setup: "Verify Files"

`VerifyEnvironmentCommand` (unchanged) is now reachable from a new "Environment" ribbon group, only shown while `IsServerSetupPage` is true. The button that used to sit inside the page's "Environment Health" summary card (`Border Classes="statuscard accentServer"`) is removed — same command, same behavior, new location.

### Configuration: Import / Export / Save / Reset, "Load Active" removed

A new "Configuration" ribbon group (shown while `IsServerPage` — the property name for the Configuration page — is true) holds four actions:

- **Import** and **Export** open a real file picker. This codebase has an established convention that anything needing a native dialog stays in code-behind (it needs a `TopLevel`/`Window` reference the ViewModel doesn't have) — `ImportPalworldConfiguration_Click`/`ExportPalworldConfiguration_Click` (`MainWindow.axaml.cs`) are unchanged, just no longer wired to a page-local button. Since the ribbon's shared button `DataTemplate` only had a `Command` binding until now, a new `NativeDialogAction` string was added to `RibbonActionViewModel` — when `Command` is null, the ribbon button's new shared `Click="RibbonAction_OnClick"` handler dispatches by that string instead (`"ImportConfig"`/`"ExportConfig"`/`"ExportConsole"`), calling the existing code-behind methods directly. This keeps the ribbon able to host both kinds of action without every future ribbon button needing to be command-shaped.
- **Save** and **Reset** are the existing `SavePalworldConfigurationCommand`/`ResetConfigChangesCommand`, unchanged.
- **"Load Active" is removed entirely**, not just relocated — flagged as redundant. Its `LoadPalworldConfigurationCommand` wrapper property was fully deleted (constructor assignment, `RaiseCanExecuteChanged` call, and the property itself) since nothing else referenced the *command* — but the underlying `LoadPalworldConfigurationAsync` method stays untouched, since it's still called from three other internal code paths (page-navigation auto-load, post-operation reload, and one other call site) that have nothing to do with the user-facing button.

The Configuration page's own toolbar row (`Grid ColumnDefinitions="Auto,*,Auto"`) that used to hold all five buttons is gone; the page's row count/`Grid.Row` indices were renumbered down by one accordingly (Simple/Advanced/QoL preset row, search row, notification strip, and the main settings grid all shifted from rows 1-4 to rows 0-3).

### Console: Refresh / Pause / Clear / Export, RCON moved above Console Log

A new "Console" ribbon group (shown while `IsConsolePage` is true) holds Refresh View, Pause/Resume, Clear View, and Export — the first three are the existing `RefreshConsoleViewCommand`/`PauseConsoleCommand`/`ClearConsoleViewCommand`; Export follows the same `NativeDialogAction` pattern as Configuration's Import/Export (`"ExportConsole"` → `ExportConsole_Click`). The Console Log card's own header row, which used to hold these four buttons, now only shows the title/log-file-path text.

Separately (not a ribbon relocation — a plain reorder, requested directly): the RCON card now renders **before** the Console Log card on the page, rather than after it. Both cards are unchanged internally; only their order in `MainWindow.axaml` swapped.

## Explicit non-goals

- No change to the ribbon's shrink/overflow *mechanism* itself (that's v0.7.25.0) — this version only adds content to exercise it.
- Configuration's "Save As Preset" button was **not** relocated — not mentioned in the request, stays where it is.
- No attempt to also relocate Backups/MOD Dashboard/UE4SS/Server Doctor buttons yet — those are v0.7.27.0 (Ribbon Consolidation Pass 2).
