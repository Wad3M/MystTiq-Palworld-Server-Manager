# v0.6.18.2 — Server Setup Page Cleanup

## Goal

Direct user feedback on the Desktop app's Server Setup page: the top hero card was "useless," the "First-Run Server Defaults" card didn't belong on a settings page someone might revisit rather than the moment they create a new server, and "Check for Updates"/"Install Missing" duplicated functionality that already lives on Update Center.

## Grounding

Investigated the actual page before changing anything, and two of the three asks turned out to be more than cosmetic:

- The hero card's description text (`MainWindow.axaml`, formerly lines 337-346) was a **verbatim duplicate** of `PageSubtitle` for `NavigationPage.ServerSetup` (`MainWindowViewModel.cs:1310`), which the shared global page header (`MainWindow.axaml:122-131`) already renders above every page. The only non-redundant content was the ENVIRONMENT HEALTH badge.
- "Check for Updates"/"Install Missing" were already-documented duplicate wrappers, not the real implementation. A code comment already on record at the top of `InstallMissingEnvironmentAsync` states the actual design intent: *"Update Center's own 'Update Palworld Server' button is now the one authoritative place that mutation happens; Setup only performs it directly for the genuine first-run case."* `CheckEnvironmentUpdatesCommand` called the exact same `PreviewDistributionPlanAsync()` Update Center's own button calls; the toolbar's `InstallMissingEnvironmentCommand` called the exact same `UpdatePalworldServerAsync()` used elsewhere. Per explicit user confirmation, these were removed rather than rebuilt on another page, since the real thing already exists.

## What shipped

**Server Setup page**: hero card removed. The 3-up stat row (Components/Ready/Attention) became a 4-up row with the environment-health badge and a single "Verify Files" action folded in. The "First-Run Server Defaults" card was removed entirely. The "Server Operations" card (Check for Updates / Install Missing / Verify Files) was removed — Verify Files moved into the stat row, the other two were dropped since Update Center already owns the real functionality. The environment checklist table's per-row "Install" action (only fires for a genuinely missing component) is untouched, and still correctly redirects to Update Center for the "already installed, check for updates" case (an existing behavior, not new).

**Settings page**: a new "In-Game Server Defaults (new server only)" card was added to the connection-profile editor, directly below the existing Name/Service URL/Bearer token/TLS pin fields. It's visible only while creating a brand-new profile — a new `IsCreatingNewProfile` computed property (`SelectedProfile is null`) gates it. Every field and command it uses (`SetupServerName`, `GenerateSetupServerNameCommand`, `CreateDefaultServerSettingsCommand`, etc.) is the exact same wiring the old Server Setup card used — nothing new was built, only relocated and re-gated.

A real, small correctness fix was needed to make the gate work at all: the `SelectedProfile` setter previously returned early (`if (!SetField(...) || value is null) return;`) *before* raising any property-changed notifications when the new value was `null` — meaning `IsLocalProfile` (and the new `IsCreatingNewProfile`) never actually notified the UI on the exact transition (`BeginNewProfile()` setting `SelectedProfile = null`) that matters most for this feature. Fixed by moving the notification raises ahead of the null-guard.

## Explicit non-goals (this pass)

- No changes to Update Center — it already has the real Check-for-Updates/Install-Missing functionality.
- No new "New Server" wizard page — the relocated card lives on the existing Settings page profile editor. A dedicated wizard/entry point is what v0.6.19.0's planned "+" chooser redesign will build toward.
- v0.6.18.3 (Configuration page changes) and v0.6.18.4 (Start/Stop/Restart button state) are separate, later passes.

## Verification

`dotnet build` (Release) across all three projects and the full solution — 0 warnings/0 errors. `scripts/Test-v0.6.18.2-Logic.ps1` static contract checks confirm the structural wiring (card removed/relocated, dead commands gone, `IsCreatingNewProfile` present and correctly raised). This release touches zero server-side code, so the frozen v0.6.18.1 regression gate and the full v0.5.1.5 runtime smoke suite are expected — and confirmed — fully unaffected.

**Disclosed verification gap, unchanged from every prior checkpoint since v0.6.4.0**: no GUI click-through capability in this environment. The actual visual layout, spacing, and the new-profile-mode visibility toggle's on-screen behavior are the user's to confirm once built.
