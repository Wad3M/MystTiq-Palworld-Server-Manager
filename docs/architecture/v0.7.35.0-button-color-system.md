# v0.7.35.0 — Button Color System

## Goal

Eleventh version in the GUI/workflow/UX overhaul roadmap. Roadmap item 32 — a cross-cutting fix, explicitly designed to supersede the narrower per-page notes recorded as items 19, 20, and 27 during the original walkthrough (Server Setup's VERIFY/MANAGE row buttons, Configuration's Generate button) rather than styling each one independently.

## Root cause

Confirmed in code: every unstyled `Button` in the app shares the identical `ButtonGradient` background (`Styles/DesignSystem.axaml`'s base `Button` selector, no class). Browse, Open, Verify, Manage, Generate, Import, Export, Load Active, Reset Unsaved, and many more all rendered pixel-identical, regardless of what the button actually did — not a per-page styling gap, an app-wide default.

## Design

Two new semantic classes, added once to `DesignSystem.axaml`, following the exact same construction pattern as the existing `Button.success`/`.danger`/`.warning`/`.primary` (Color-stop tokens → `LinearGradientBrush` base/hover/pressed → style selectors), so they stay theme-aware and visually consistent with the rest of the button system rather than being flat one-off hex values:

- **`Button.inspectAction`** (cyan `InspectGradient`) — non-mutating "look at/confirm" actions: nothing changes as a direct result of clicking it.
- **`Button.targetAction`** (violet `TargetGradient`) — "act on a specific thing" actions: takes the user somewhere or changes a specific target's state.

Neither reuses `PrimaryGlassGradient`/`SuccessGradient`/`DangerGradient`/`WarningGradient` — already spoken for by Save/Start-class buttons, danger actions, and warning actions respectively — matching the original finding's explicit instruction to avoid "whatever gradient reads as Save."

## What shipped

### Workspace's Browse/Open buttons (the finding's original trigger)

All 4 "Browse" buttons (`Click="WorkspaceBrowse_Click"`, opens a file/folder picker) now carry `Classes="inspectAction"`. All 10 "Open" buttons (`Click="WorkspaceOpen_Click"`, reveals a path in the OS file explorer — Executable root, Workspace root, Application data, Palworld server, SteamCMD, Backups, Runtime, Downloads, Exports, Logs) now carry `Classes="targetAction"`. Applied via two `replace_all` edits keyed on the unique `Content="Browse" Tag="`/`Content="Open" Tag="` literal patterns; verified the edit only touched these Workspace rows (10 targetAction + 4 inspectAction matches, confirmed against the `WorkspaceOpen_Click`/`WorkspaceBrowse_Click` handler counts) and did not touch the many unrelated "OPEN" navigation buttons used elsewhere in the app (Dashboard's card-header OPEN-to-page buttons, a different semantic entirely, out of scope for this item).

### Server Setup's VERIFY/MANAGE row buttons (items 19, 20)

The per-row action button (`MainWindow.axaml`, bound to `ActionDisplay`, one shared `DataTemplate` for every row) previously had no `Classes=` at all. `EnvironmentChecklistItemDto` gained two computed properties keyed off the row's real `Action` string (already sourced from `HeadlessEnvironmentChecklistService`, whose action verbs are `VERIFY`, `RESCAN`, `MANAGE`, `INSTALL`, `CREATE`, `ENABLE`):

- `IsInspectAction => Action is "VERIFY" or "RESCAN"` — both are read-only checks.
- `IsTargetAction => ActionSupported && !IsInspectAction` — covers `MANAGE`/`INSTALL`/`CREATE`/`ENABLE`, all of which change something; gated on `ActionSupported` so a disabled "BACKEND REQUIRED" row gets neither color class (it already reads as inactive via the existing `Button:disabled` opacity rule).

Bound via `Classes.inspectAction="{Binding IsInspectAction}" Classes.targetAction="{Binding IsTargetAction}"` on the shared button template, so every row picks up the right color automatically without per-row XAML.

### Configuration's Generate button (item 27)

Confirmed during the original walkthrough that `GenerateServerNameCommand` was already functionally enabled (`RelayCommand(GenerateServerName, () => PalworldConfigLoaded && !IsBusy)`) — the reported "disabled" read was a size/visibility issue, not a `CanExecute` gap. Changed from an icon-only `🎲` button to `🎲 Generate` with `Classes="inspectAction"`, larger padding (`14,7`), and `FontWeight="SemiBold"`, matching the reference build's roomier labeled button. Uses `inspectAction` (not a new color) since Generate doesn't persist anything by itself — its own tooltip already says "Save Changes is still required."

## Explicit non-goals

- No change to `Button.success`/`.danger`/`.warning`/`.primary`/`.ghost` or any other existing button class.
- No restyling of the Dashboard's "OPEN" navigation buttons (Players/Guilds/Mods/Active World/Backup cards) — a different semantic (navigate to a page) established and shipped separately in v0.7.33.0, not part of this item's scope.
- No restyling of every other unstyled button in the app beyond the three named areas — item 32 asks for a reusable system design plus its application to the originally-flagged buttons, not a full app-wide button audit.
