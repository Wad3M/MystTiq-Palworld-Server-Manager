# v0.9.2.0 — Game names in your language

## Why

Since v0.8.13.0 the Give Item picker and the map show the game's item and Pal names, read from the server's own game pak
by MystTiq's read-only extractor (`Tools/extract_game_names.py`, run with the user's Python and its Oodle module). It
always read the English tables. With the window and its messages in 12 languages (v0.9.0.0, v0.9.1.0), an English
"Lamball" in a Japanese window was the next most visible leftover.

## What the game ships

Read from the real server's pak index (`Pal-WindowsServer.pak`, 158,571 files): the name tables
`DT_ItemNameText_Common` and `DT_PalNameText_Common` exist under `Pal/Content/L10N/<culture>/…` for de, en, es, es-MX,
fr, id, it, ko, pl, pt-BR, ru, th, tr, vi, zh-Hans and zh-Hant, and once more outside L10N in
`Pal/Content/Pal/DataTable/Text/`. That base table is Japanese (メルパカ, シラヌイ…): Japanese is the game's source
language. So every one of MystTiq's 12 languages has the game's own names, with the same culture codes.

## How

- **Extractor:** `--lang ja` reads the base tables; any other code reads its L10N folder, and exits 4 when the pak has
  none. Checked against the real pak: 1,997 items and 322 Pals in Japanese and in Korean.
- **Service:** `HeadlessGameNameService` keeps one state per language (loaded pak stamp, catalog, status, last failure)
  and one cache file per language (`<runtime>/game-names/<code>.json`; the existing `en.json` is reused). A code is
  normalised to one of the 12 (any case); anything else is English. A language whose names cannot be read shows the
  English names, and the status says so; without Python or ooz there are no names at all, as before.
- **Routes:** `/players/give/catalog?lang=` and `/world/players-guilds?lang=`. Other callers of the explorer (ownership
  and migration previews, Doctor) keep English: they do not show names.
- **Desktop:** `MystTiqApiClient` sends `Localizer.Instance.LanguageCode`. A language change reads a loaded Give Item
  picker again; the map refreshes itself every few seconds while it is open.

## Composed texts

Some Desktop texts are built from several sentences: the summary line under the map ("3 player(s) online on the map.
2 base(s) shown from the world save.") and a Pal's tooltip (name, level, place and coordinates, then notes).
`MessageCatalog` now splits a line that does not match whole into sentences and translates each. When every sentence is
known that wins over a whole-text template: otherwise "{0} base(s) shown from the world save." matched the whole line
with the first sentence as its value, which the ArtworkHarness caught on the first run. 40 more messages cover these
sentences, alpha Pals ("{0}, alpha") and the host's uptime ("Up {0} d {1} h").
