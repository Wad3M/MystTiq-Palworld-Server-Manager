# v0.8.19.0 — Every Route Declares Its Role, and the Ribbon Follows It

This was planned as "Ribbon buttons follow the signed-in role" (a v0.8.14.0/v0.8.15.0 follow-up). Mapping each Ribbon
button to the role its route needs turned up a security gap on the server, so this version fixes that first.

## What was found

An audit of every route in `LocalManagementApiHost` (185) found **105 with no role at all**. `RequireRole` is an
endpoint filter, and a route without it accepts **any** signed-in principal:
- a **Viewer**;
- an account **limited to another server**, because scoping is also done by `RequireRole`.

With authentication on (remote or multi-user use, since v0.7.114.0), any signed-in person could therefore:
- **run any RCON command** (`POST /rcon/command`);
- **kick or ban** (`POST /players/{id}/action`) and **teleport players**;
- **rewrite PalWorldSettings.ini** (`PUT /palworld/config`, `POST /palworld/config/defaults`);
- **enable, disable, delete, install and roll back mods**, and import Workshop mods;
- update pip components, install the console-capture proxy, repair the firewall, and restart through network
  diagnostics;
- read and change every other server of the fleet, whatever server the account was limited to.

Local, token-less use was never affected: with authentication off every request is the Owner.

## The fix: secure by default

- `RequireRole` now also records its role on the endpoint (`RequiredRoleMetadata`).
- Each server's route group (both the `/api/v1/servers/{id}` group and the default server's unprefixed one) gets
  `RequireRoleByDefault`. A route that declares no role is:
  - **Viewer** to read (GET, HEAD);
  - **Admin** to change anything (POST, PUT, DELETE, PATCH);
  - **scoped to its server** in both cases.
- A route that should be open to less says so with its own `RequireRole`. The Operator-level changes:
  - save the world now;
  - notifications (self-test, mark read, pin, dismiss);
  - player notes and warnings;
  - a diagnostic recheck, and the network-diagnostics restart;
  - crash analysis and the save-tools self-test;
  - the server update;
  - backup verification and the retention preview.
- The fleet-level reads outside any group get an explicit Viewer: port check, UE4SS releases, service, principals
  list, operations and the server list.
- A new route is protected without anyone remembering to. The gate now fails if a fleet-level route has no role,
  except sign-in, sign-out, password change, whoami and the health check.

**Behaviour change:** kick, ban, unban and teleport are **Admin** now, like the whitelist. An Operator runs the server;
moderation is Admin.

## The Desktop

- **Ribbon.** Each button that changes something is mapped to the role its route needs:
  - **Operator:** start, stop, restart, force stop; backup; mod safe-start; crash analysis; the self-tests; mark all
    read; verify all backups; install missing; restart from diagnostics;
  - **Admin:** save the Palworld settings; enable, disable or repair mods; UE4SS preview, install and rollback;
    firewall repair.
  A button the signed-in role cannot use is **disabled**, and its tooltip ends "(needs the Admin role)". The Ribbon is
  rebuilt when the role changes.
- **Page buttons** whose routes are Admin now follow `CanManageAdmin`: Kick, Ban, Unban, Teleport and RCON Send. Save
  Now follows `CanOperate`.
- Local use keeps every button, as before.

## Verification

- **Route smoke** (`Test-v0.8.19.0-RouteSmoke.ps1`, 6 checks). Authentication is really on, with the shared Owner
  token plus Viewer, Operator and Admin accounts, and an Admin limited to another server:
  - a Viewer still reads (status, players, notifications, host, the server list, operations);
  - RCON commands, kick/ban, PalWorldSettings.ini, mods and teleport are refused for Viewer **and** Operator
    (403 `insufficient-role`, required Admin);
  - an Admin passes;
  - save now, mark read, verify backups and crash analysis are refused for a Viewer and allowed from Operator;
  - the other server's Admin is refused here on every path, reading included (`server-scope-mismatch`);
  - the Owner token and sign-in still work.
- The v0.7.114.0 multi-user smoke still passes 11/11 against the new server, and the v0.8.15.0 remote sign-in
  (Linux VM) runs in the gate.
- **Logic harness:** the default by method.
- **ArtworkHarness: 508 checks.** Every page's Ribbon for local, Viewer, Operator and Admin (23 gated buttons), the
  rendered Save button disabled for an Operator with "Admin" in its tooltip, and Kick disabled for an Operator.
- **Gate:** the route count check above.

## Not done

- Buttons deeper in the pages (per-mod toggles, the config import) are not all gated. The server refuses them, and
  the Desktop shows the refusal (v0.8.15.0).
- The role levels were chosen per route in this version. They are listed above and in the gate, and can be changed
  per route if an Operator should be allowed more.
