# v0.8.17.0 — The HOST Tab, Process Priority and Eco Mode

This is the first item of the resource, performance and network optimisation line (user decision 2026-09-24:
"process priority/eco mode, bandwidth, and a HOST tab, as 0.8.17.0+"). This version covers the HOST tab and process
priority/eco mode. Bandwidth follows, on the HOST tab.

## The HOST tab

A new category, **Host**, sits between Tools and System and holds one page, **Host & Performance**. It shows the
machine the connected server runs on. For a remote server that is the server's own machine, not the PC running the
Desktop.

| Card | Shows |
|---|---|
| This machine | name, operating system, processor name and logical processors, processor load, memory used/total/available, uptime |
| Disks | every fixed disk (on Linux only those holding something of the server, plus `/`), free and total, marked with what of this server it holds (install, saves, backups), and "less than 10 % free" |
| Network | every adapter that is up and has carried traffic (no loopback, tunnel or filter layer), its received and sent traffic in bits per second, and link speed. This is the whole machine's traffic, not only the server's. |

**Found in the live check:** on this Hyper-V host, Windows also lists every NDIS filter bound to an adapter as an
adapter of its own, with the same counters, so the same traffic showed up to four times. Examples:
`Ethernet-WFP Native MAC Layer LightWeight Filter-0000` and `vEthernet (…)-QoS Packet Scheduler-0000`.

- An adapter named `<another listed adapter>-<filter>-NNNN` is now left out (`HeadlessHostMonitor.IsFilterLayer`).
- So is an adapter that has never moved a byte.
- A physical adapter bound to a virtual switch still shows the same traffic as the switch's own `vEthernet` adapter,
  because both carry it.
| Server priority and eco mode | the policy (below), the eco state and why, and each server process with its actual priority, efficiency mode and memory |

Where the readings come from (`HostMetricsReader`, Core):
- **Windows:** `GetSystemTimes` (processor) and `GlobalMemoryStatusEx` (memory).
- **Linux:** `/proc/stat`, with idle including iowait, and `/proc/meminfo` (`MemAvailable`).
- **Network:** `.NET NetworkInterface` counters.

`HeadlessHostMonitor` is one instance for the whole fleet. It turns counters into rates against the previous reading;
the first reading of a session samples twice, one second apart. The page refreshes with the Desktop's existing
5-second tick while it is open.

The page uses the System category's artwork and the Diagnostics navigation icon until it has its own.

**Layout, found in the live check.** This machine has about a dozen data drives, and the first layout (disks and
network side by side, priority card last) buried the one card with settings under a long disk list. Now:
- the cards are full width, in order of use: machine, priority, network, disks;
- the disks holding something of the server come first.

## Process priority and eco mode

Per server, stored in its runtime folder as `resource-policy.json`:

| Setting | Values |
|---|---|
| Priority | **Leave as it is (default)**, Below normal, Normal, Above normal, High. Real-time is not offered. |
| Eco mode | **Off**, On, When no one is online (after 1–240 minutes, default 10) |

The rules (`ResourcePolicyDecision`, Core; pure and tested):
- **Default priority changes nothing.** MystTiq does not reset a priority set elsewhere.
- **Eco mode** turns on the operating system's efficiency mode and runs the server **below normal**, whatever
  priority was chosen.
  - On Windows this is EcoQoS through `SetProcessInformation(ProcessPowerThrottling)`, the same switch as Task
    Manager's "Efficiency mode". MystTiq does not also drop the priority to Idle, as Task Manager does.
  - On Linux there is no efficiency mode, so eco mode lowers the priority only.
- **When no one is online:**
  - the clock starts at the first empty reading and runs while the server stays empty;
  - a player joining resets it and the server returns to full speed on the next tick;
  - **an unknown player count never starts eco mode.** Who is online comes from the dashboard's live read (the
    Palworld REST API or RCON); without it, eco mode waits and says why.
- **Efficiency mode is only switched back where MystTiq set it**, so a setting made elsewhere is left alone.

How it is applied (`HeadlessResourcePolicyService`):
- On Windows the game itself is the grandchild `PalServer-Win64-Shipping-Cmd.exe`, created after the launch and again
  on every restart. So the policy is applied to **every managed process**:
  - at once when it is saved;
  - on the automation tick (every 15 s), which keeps it through restarts and crashes.
- A process is only touched when it differs from what the policy wants, so each change is logged once in the activity
  log. Eco on and eco off are also logged once each.
- **Linux niceness is per thread.** A process's existing threads keep their own, so it is set on every thread in
  `/proc/<pid>/task`.
- **Linux does not let an unprivileged user lower niceness again.** Going back from below normal (or from eco mode) to
  normal needs MystTiq's service to run as root or with `CAP_SYS_NICE`. The error says so, and the page explains it.
  - Verified on the VM: an unprivileged MystTiq sets niceness 10 on every thread and cannot set 0 again.
- A refused change (access denied, a protected process) is reported on the page, not thrown.

Routes, per server and scoped like every other:
- `GET /host`: Viewer; reading changes nothing.
- `GET /resources/policy`: Viewer.
- `PUT /resources/policy`: **Admin**. A policy out of range is refused (400).

On the Desktop, the priority card follows the v0.8.14.0 pattern: everyone reads it, and only Admin and above can
change it. An unsaved choice is not overwritten by the next reading. "High" shows a warning: it puts the server ahead
of everything else on the machine, including MystTiq and remote access.

## Verification

- **Logic harness**, two scenarios:
  - **The rules.** Each eco branch, including never on an unknown count and the exact boundary; the empty clock; the
    targets; efficiency undone only where set; validation 1..240; the niceness mapping; the `/proc/stat` and
    `/proc/meminfo` parsers.
  - **The service**, with a scripted server, a fake process control and a controllable clock:
    - the default changes nothing; saving applies at once; an unchanged process is not touched;
    - eco turns on after exactly the empty minutes and off when a player joins, logged once each;
    - efficiency set elsewhere is left alone; a refused change is reported;
    - without efficiency mode (Linux) only the priority changes;
    - the policy survives a restart; a damaged file falls back to changing nothing; a stopped server has nothing to
      apply.
- **Windows route smoke** (`Test-v0.8.17.0-RouteSmoke.ps1`, 9 checks). This runs service mode on the published exe
  with a stand-in PalServer, and every priority claim is checked on the **real process**:
  - the host readings match Windows (processor count, memory within 64 MB, the install's disk marked);
  - the default leaves the priority at Normal;
  - saving applies at once and is kept on disk;
  - eco on gives efficiency mode on, as read back from Windows, and below normal even with High chosen;
  - eco off returns efficiency to the system default;
  - eco when empty waits without a player count;
  - out of range gives 400;
  - **after a crash the restarted server gets the policy again on the next tick**;
  - the activity log has each change once.
- **Linux, isolated on the VM** (`Test-v0.8.17.0-LinuxIsolated`, 10 checks). The stand-in server is a copy of python3
  named `PalServer-Linux-Shipping` with four threads:
  - the `/proc` readings match (processors, `MemTotal`);
  - the disk is marked;
  - no efficiency mode is reported;
  - niceness 10 is set on every thread;
  - raising it again is refused with the named privilege;
  - eco mode lowers the priority only;
  - eco when empty waits.
- **ArtworkHarness: 492 checks.**
  - The HOST text formatting.
  - The Host page with a sample reading: header, Ribbon, every card, the process list, the pickers filled from the
    policy, an unsaved choice kept, the High warning, and minutes validated before sending.
  - The priority card: read-only for an Operator (it is also in the role table, for every role).
  - All **8** category tabs fit at 950x650 in English, German and Spanish.
  - Renders: `host-dark`, `host-priority-high`, `host-950x650`.

## Not done

- **Bandwidth** is the next version: the HOST tab shows traffic, but nothing limits it yet.
- Readings are live only; there is no host history.
- Processor affinity (pinning cores) is not offered.
- The page's art and navigation icon are placeholders from other pages.
- On Linux a systemd unit's own `Nice=` is not set; MystTiq changes the running process.
