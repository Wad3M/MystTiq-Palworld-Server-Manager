# v0.7.112.0 — Give Item

## Why

The Players page's "Give Item" had been a visible but hardcoded-off stub (`CanExecute => false`) since
the Desktop was built. It was parked for v0.8.x pending a provider decision. On 2026-09-22 the user pulled it
into 0.7.x. Provider decided: PalDefender over RCON, the dependency Starter Kits (v0.7.94.0) already take.
MystTiq still has no live-save write access.

## Design

- `HeadlessKitService.GiveEntriesAsync(entries, playerId, players, token)`. It uses the same entry format,
  validation (`Validate`), command building (`BuildCommands`: items batched into `giveitems <UserId>
  Id:Amount ...`, one `givepal <UserId> PalId Level` per Pal), provider check and error-reply detection
  (`LooksLikeFailure`) as a kit.
  - It is a one-off: no kit is saved and **no claim is recorded**, so it never affects auto-gift.
  - The id pattern (`^[A-Za-z0-9_]{1,64}$`) is what prevents an id like `PalSphere; Shutdown 1` from
    smuggling a second RCON command. It is covered by both the harness and the smoke.
- `DeliverAsync` was extracted from `GiveAsync`, so kits and Give Item share one command loop. The kit
  path's behaviour and messages are unchanged.
- `POST /api/v1/players/{playerId}/give {entries}`, Admin (same as giving a kit). A refusal is 409 and is
  written to the Activity log as "Give Item failed"; a success logs "Items given".

## Desktop

Player Administration card: a "Give items or Pals" box using the kit editor's line format (`item PalSphere
10`, `pal WeaselDragon 5`) and a Give button. The right-click menu entry "Give Items (typed in Player
Administration)" runs the same command. Both are enabled only for an online player with something typed.
The result (or the provider's reason it cannot deliver) appears in the card's status line.

## Verification

- Logic harness: 1 new scenario. It covers the exact commands sent (whitespace trimmed), that no claim is
  recorded, and refusals for an injection-shaped id, amount 0, an empty give and an offline player, with
  nothing sent for any of them. It also covers a missing provider and an error-looking server reply.
- `scripts/Test-v0.7.112.0-RouteSmoke.ps1` against the published exe. It covers the injection-shaped id,
  an empty give, no PalDefender, PalDefender without RCON, and PalDefender with RCON but the player not
  online. Each is refused with the right reason, nothing is sent, and each refusal reaches the Activity log.
- Live Desktop: the Give box and button render on the Players page, disabled with no player online.

## Not verified

- An actual item arriving in a live player's inventory. No player is online on this machine; the success
  path is proven only against the harness's fake provider. PalDefender's real reply text to `giveitems` is
  still unverified, as it has been for kits since v0.7.94.0.

## Not done

- No item-id picker or catalogue: ids are typed. A catalogue must match the installed game version, and
  none ships with MystTiq today.
