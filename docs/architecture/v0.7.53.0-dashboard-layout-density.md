# v0.7.53.0 — Dashboard Layout Density

## Goal

Item 13 from the original findings log: the Dashboard should be laid out more compactly, matching
an older MystTiq build's (v0.2.16.4) denser stat cards. Grounded but never assigned a version until
v0.7.32.0's own implementation flagged the gap and appended it as a future item.

## Precedent followed

The exact same treatment v0.7.32.0 already applied to Server Setup, Backups, MOD Library, and
Server Doctor: explicit per-instance `Padding`/`FontSize` overrides on the affected cards, no
changes to the shared `.card`/`.statuscard` styles — so nothing on any other page using those
classes is affected by this version.

## What shipped

- Outer Dashboard `StackPanel`: `Spacing="7"` → `"6"`.
- First 4-column stat-card `Grid` (SERVER / ACTIVE WORLD / BACKUP / OVERALL HEALTH):
  `ColumnSpacing="10"` → `"8"`; each card's `Padding="10"` → `"8,6"`; big-number `FontSize`
  18 → 15 (SERVER state, BACKUP amount, OVERALL HEALTH text); ACTIVE WORLD's nickname 15 → 13,
  its path detail 10 → 9; button `Padding` 10,4 → 8,3.
- Second 4-column stat-card `Grid` (PLAYERS / GUILDS & BASES / MOD PLATFORM / CPU-MEMORY): same
  `ColumnSpacing`/`Padding` reduction; big-number `FontSize` 17 → 14, 15 → 13; inner `StackPanel`
  `Spacing` 3 → 2; OPEN button `Padding` 9,3 → 7,2; the CPU/Memory card's inner `ColumnSpacing`/
  progress-bar `Spacing` 8 → 6.
- World Pulse strip (`Border` wrapping five summary columns): `Padding="10"` → `"8,6"`,
  `ColumnSpacing="14"` → `"12"`; every big-number `FontSize` reduced by 2-3px (18→15, 16→13, 13→12);
  every label `FontSize` 10 → 9; Last Activity's `MaxHeight` 45 → 40.

## Explicitly out of scope

The same v0.2.16.4 reference screenshot that motivated this item also showed structural differences
— ribbon buttons rendered inline in the title bar instead of today's separate row, and a
collapsible-tree left nav instead of today's category-tabs-plus-fixed-list. Neither is a density
change; both are meaningfully larger IA changes than this item's own "smaller/denser cards" framing
asked for. Left untouched — not part of this version.

## Verification

`dotnet build` on `MystTiq.Desktop` and the full solution — clean. One AVLN1001 `--` XML-comment
error hit and fixed in this version's own new comment (the same recurring pattern this session has
hit on nearly every version that touches a XAML comment).

## Known gaps (disclosed)

- No visual verification possible in this environment — same limitation as every prior version
  touching the UI, and especially relevant here since this whole item is a visual-density judgment
  call against a reference screenshot this session cannot render or compare against pixel-for-pixel.
  The specific padding/font-size values chosen are reasonable estimates following the v0.7.32.0
  precedent's own values, not confirmed against a rendered window — may need a follow-up tuning pass
  once actually seen.
