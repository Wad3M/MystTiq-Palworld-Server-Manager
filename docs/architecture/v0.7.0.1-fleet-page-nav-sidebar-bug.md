# v0.7.0.1 — Fix Release (Fleet Page Nav Sidebar Bug)

## Goal

User report, with a screenshot of the running app: opening the Fleet page left the entire left nav sidebar blank, and none of the top category tabs (Home/Server/World/Backups/Mods/Tools/System) appeared selected. The user had flagged Fleet as "still orphaned" after v0.6.19.1's earlier Fleet page fixes (status dots, error messages) — this is the actual bug behind that report, not something those fixes touched.

## Grounding

`MainWindowViewModel.IsV5SystemCategory` gates the visibility of the entire System category's nav sidebar `StackPanel` in `MainWindow.axaml`, and also drives the "System" category tab's `IsChecked` state:

```csharp
public bool IsV5SystemCategory => SelectedPage is NavigationPage.Settings or NavigationPage.ActivityAudit
    or NavigationPage.Notifications or NavigationPage.Automation or NavigationPage.Security or NavigationPage.AlertCenter;
```

`NavigationPage.Fleet` is missing from this list, even though Fleet's own nav `ToggleButton` lives inside the very `StackPanel` this property gates. The moment `SelectedPage` becomes `NavigationPage.Fleet` (i.e., you're actually looking at the Fleet page), `IsV5SystemCategory` evaluates to `false` — the whole nav sidebar for that category disappears, and the System category tab loses its checked state. The page is still fully functional (data, actions, refresh all still work), but it visually looks disconnected from the rest of the app's chrome the instant you open it — exactly the "orphaned" feeling reported.

This predates v0.6.19.1 and v0.7.0.0; neither release touched this property.

## What shipped

- Added `NavigationPage.Fleet` to `IsV5SystemCategory`'s pattern match.
- Found and fixed the identical omission in `IsSystemGroupSelected`, a sibling property with the same page list that is not currently referenced anywhere in `MainWindow.axaml` (superseded by the `IsV5*Category` properties) — fixed for consistency so the same mistake can't resurface if that property is ever wired up later.

## Explicit non-goals

- No other category-visibility properties were found with the same omission (checked all of `IsV5HomeCategory`/`IsV5ServerCategory`/`IsV5WorldCategory`/`IsV5BackupsCategory`/`IsV5ModsCategory`/`IsV5ToolsCategory` and their `Is*GroupSelected` equivalents against the full `NavigationPage` enum).
- No server-side change.

## Verification

`dotnet build` (Release) — 0 warnings/0 errors. This release touches zero server-side code, so the frozen v0.7.0.0 regression gate and the full v0.5.1.5 runtime smoke suite are expected — and confirmed — fully unaffected.

**Disclosed verification gap, unchanged from every checkpoint since v0.6.4.0**: no GUI click-through capability in this environment. The fix is a single boolean expression change verified by direct code inspection against the exact screenshot the user provided (which showed the blank sidebar); the user's screenshot is the ground truth this fix targets, and confirming the sidebar now populates correctly on the Fleet page is the user's to do once built.
