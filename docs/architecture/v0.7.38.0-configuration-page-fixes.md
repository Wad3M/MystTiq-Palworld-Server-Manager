# v0.7.38.0 — Configuration Page Fixes

## Goal

Fourteenth version in the GUI/workflow/UX overhaul roadmap. Roadmap items 24, 25, 26, 27, and 28 — five fixes to the Configuration page, grounded against a v0.2.16.4 reference screenshot.

## What shipped

### Notification strip relocated (item 24)

The preset-loaded message (`PalworldConfigState`), "N unsaved setting change(s)" (`PalworldConfigDirtyText`), validation text (`PalworldConfigValidationText`), and the "Simple Settings shows…" helper line previously all sat in one block directly under the Simple/Advanced toggle row — competing with that row and the search/category filter for attention right as the page loads, regardless of which settings section a user actually cared about.

Split precisely along what the original finding named: those four pieces moved down to sit just above the World Settings heading (inside the Simple view), right next to what they're reporting on. The file path (`PalworldConfigPath`) and the Advanced Settings helper line — not named in the finding, and relevant in both views — stayed at the top under the toggle row.

### "Gameplay Rates" renamed to "World Settings", split into labeled sub-sections (item 25)

The reference build's own examples named a few settings per group ("World": Death Penalty/Longer Days/Shorter Nights/More Item Drops/Faster Resource Respawn/Supply Drop Interval; "Player & Pal": Player/Pal Health Regeneration) without listing every setting — the original finding explicitly deferred the full grouping design to implementation time, instructing a pass through the actual curated settings data. This release does that pass: every one of the 22 curated rate settings (`SimpleRateDefinitions` in `MainWindowViewModel.cs`) was assigned to one of three semantic groups:

- **World** (7): DayTimeSpeedRate, NightTimeSpeedRate, ExpRate, PalCaptureRate, PalSpawnNumRate, SupplyDropSpan, BuildObjectDeteriorationDamageRate — environment/spawn/decay pacing.
- **Player & Pal** (8): PlayerDamageRateAttack/Defense, Player/PalStomachDecreaceRate, Player/PalStaminaDecreaceRate, Player/PalAutoHPRegeneRate — survival/combat body stats for both players and Pals.
- **Items & Work** (7): CollectionDropRate, CollectionObjectRespawnSpeedRate, WorkSpeedRate, MonsterFarmActionSpeedRate, ItemWeightRate, ItemCorruptionMultiplier, EquipmentDurabilityDamageRate — economy/base-productivity/equipment rates. Not named in the reference's own examples, but a real semantic cluster distinct from the other two, added since the reference's list was illustrative rather than exhaustive.

Implementation: `PalworldSimpleSettingItem` (`Models/PalworldConfigurationDtos.cs`) gained a `Group` property; `SimpleRateDefinitions`' tuple type grew a `Group` field; the former single `SimplePalworldSettings` collection was replaced by three named `ObservableCollection<PalworldSimpleSettingItem>` properties (`SimpleWorldRateSettings`/`SimplePlayerPalRateSettings`/`SimpleItemsWorkRateSettings`), each routed to during `RebuildSimplePalworldSettings`. The XAML got three near-identical `ItemsControl` blocks (matching the existing duplication style already used throughout this file) under a "WORLD SETTINGS" heading, each with its own "World"/"Player & Pal"/"Items & Work" sub-header.

### Advanced Settings keeps the same identity/network cards (item 26)

Previously, Advanced Settings was "a totally different page layout": Simple view showed the Server Identity card and Network/Access & Limits section, but switching to Advanced jumped straight to a bare flat OptionSettings table with zero identity/network context. Restructured so the Server Identity card, the settings-gap warning, and the Network/Access & Limits `ItemsControl`s are now direct children of a shared `StackPanel` (the whole `Grid.Row="3"` container, previously a `Grid` with two `IsVisible`-toggled overlapping children, is now this `StackPanel`) — always visible regardless of view. Only the content below them differs: World Settings' three labeled groups for Simple, the full flat `FilteredPalworldSettings` table for Advanced, each still gated by its own `IsVisible="{Binding IsConfigSimpleView/AdvancedView}"`.

### Generate button (item 27)

Already fixed in v0.7.35.0's button color system pass — bigger, labeled "🎲 Generate", `Classes="inspectAction"`. Verified no further work was needed here; nothing changed this release.

### Reference note (item 28)

Directly addressed by item 25's implementation above — the grouping design was built from the real current `SimpleRateDefinitions` data, not invented from scratch or left as a placeholder.

## Explicit non-goals

- No change to Advanced Settings' own flat-table columns/sorting/filtering behavior — only its surrounding layout (now sharing the identity/network cards) changed.
- No new settings added to the curated Simple list — all 22 pre-existing curated rate settings were regrouped, none added or removed.
