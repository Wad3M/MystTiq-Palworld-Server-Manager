# v0.8.13.0 — Game Names, and an Image on Every Ribbon Button

This is the fourth item of the user's automated run: "Give Item display names and unseen items via a pak reader". The
user's last ten Ribbon icons (`palworld_missing_10_icons.zip`) came in at the same time and are folded in here.

## Names: what the game files hold

The server's own pak (`Pal/Content/Paks/Pal-WindowsServer.pak`, and `Pal-LinuxServer.pak` on Linux) has English
localisation tables for items and Pals:
- `Pal/Content/L10N/en/Pal/DataTable/Text/DT_ItemNameText_Common.uexp`
- `Pal/Content/L10N/en/Pal/DataTable/Text/DT_PalNameText_Common.uexp`

The same tables exist for other languages. Each row's text is saved as (namespace, key, text), and the key is
`ITEM_NAME_<id>_TextData` or `PAL_NAME_<id>_TextData`. The `<id>` is exactly the id the world save and the give commands
use, so nothing has to be guessed. Ids match ignoring case: the save writes `Sheepball` where the table has `SheepBall`.

On the real server this gives 1997 item names and 322 Pal names. That covers 120 of the save's 122 item ids and all 30
of its Pal species. The two uncovered items are `ClothArmorCold_2` and `ClothArmorHeat_2`, which keep their ids.

## Why a Python script

The pak is version 11, with an unencrypted index, but every file in it is Oodle-compressed.
- The server ships no Oodle library of its own; Oodle is built into the server exe.
- The open-source decompressor (ooz) is GPL, so it is not built into MystTiq.
- The `ooz` Python module is what the PlM/Oodle save tooling (palworld-save-tools) already installs, and MystTiq already
  checks for that tooling.

So MystTiq ships a small read-only script of its own, `Tools/extract_game_names.py`. It uses only the standard library,
plus `ooz` for Oodle-compressed files. MystTiq runs it with the user's Python. Nothing from the game is bundled.

## What changed

- **`extract_game_names.py`.**
  - It reads the pak footer (version 11 only), the full directory index, and the two entries.
  - It decompresses them with `ooz`. The module is imported only when an Oodle file is read, and a module without
    `decompress` counts as not installed.
  - It prints `{"lang", "items": {id: name}, "pals": {id: name}}`, escaped to ASCII.
  - Exit codes: 2 means no working ooz, 3 means an unsupported pak, 4 means the table was not found.
- **`HeadlessGameNameService`**, one per profile.
  - It finds the pak and returns cached names while the pak's path, size and time are unchanged. The cache lives at
    `<manager runtime>/game-names/en.json`.
  - Otherwise it runs the extractor, with a 60 s timeout, and caches the result.
  - A failure is remembered for 10 minutes per pak, so it is not retried on every request.
  - It never throws. Without names, everything works on ids, and the detail says why and what is needed: "Python was
    not found", "Python's Oodle module (ooz) is not installed", or the last line of any other error.
  - It skips the Microsoft Store `python.exe` stub.
- **Give Item catalogue** (`/api/v1/players/give/catalog`).
  - Every row carries its `name`.
  - The game's other items and Pals are added and marked `inGameFiles`.
  - Order: items before Pals, ids this server has seen before game-only ones, then by name.
  - `namesAvailable` and `namesDetail` say where the names came from, or why there are none.
- **Explorer** (`/api/v1/world/players-guilds`). Pal positions carry `speciesName`.
- **Desktop.**
  - The picker shows "Pal Sphere (PalSphere) · Item · in world ×12".
  - It marks "not yet seen on this server".
  - The search finds the name as well as the id ("pal sphere", "lamball").
  - The map shows "Cattiva" and "Zippy (Chillet)", and drops "Species are the game's internal names" once all names
    are known.
  - Found in the live check: the picker's "Showing the first 300 of N matches" line never cleared once the search was
    narrowed (a v0.8.3.0 bug, obvious with the larger list). It now returns to the catalogue's own line.
