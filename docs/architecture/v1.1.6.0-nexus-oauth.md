# v1.1.6.0 — Nexus Mods sign-in with OAuth (internal)

Nexus Mods support, 2026-10-26, during the upload review: "your mod uses Personal API keys. Which is not allowed under
our upload guidelines. Please update your mod to use OAUTH instead" (https://modding.wiki/en/api/oauth2-guide). The
owner chose to ship it as v1.1.6.0.

## Flow (`NexusOAuth`, a public app with PKCE)

1. `NewVerifier` (48 random bytes, base64url) and `ChallengeFor` (SHA-256, base64url; RFC 7636).
2. A `TcpListener` on `127.0.0.1:{CallbackPort}` (47823), then the browser opens
   `https://users.nexusmods.com/oauth/authorize` with `client_id`, `response_type=code`, an empty `scope`, the redirect
   `http://127.0.0.1:47823/nexus/callback`, a random `state`, `code_challenge_method=S256` and the challenge.
3. The listener answers stray requests (a favicon) with 404 and waits up to five minutes for the callback.
   `ReadCallback` takes the code only when `state` matches (compared in constant time), and reports `error` /
   `error_description`. The browser tab gets a short page in the display language.
4. The code is exchanged at `https://users.nexusmods.com/oauth/token` (`grant_type=authorization_code`, the redirect, the
   Client ID, the verifier). `ReadAccount` checks the access token: three parts, `alg` RS256, the signature against
   Nexus's published public key, not expired; the account name, id and Premium (`premium` or `lifetimepremium`) come
   from its `user` claim. An answer that fails the check is not used.
5. The tokens are kept in `CredentialStore` (DPAPI for this Windows account; memory only elsewhere) as `nexusmods-oauth`.
   `GetAccessTokenAsync` refreshes when less than a minute is left (`grant_type=refresh_token`; a refresh that returns no
   refresh token keeps the old one); a 4xx answer means access was withdrawn, so the person is signed out.
6. A personal key saved before v1.1.6.0 (`nexusmods-api-key`) is deleted when `NexusOAuth` is created.

`NexusModsClient` sends `Authorization: Bearer <access token>`; the MOD browser's `NexusModSource` takes a token function.
The Client ID is `NexusOAuthClientId` in `Directory.Build.props` (an `AssemblyMetadata` of the desktop). Until Nexus
issues it the card says sign-in is not available yet and nothing is opened.

## Registering with Nexus (the owner)

Email support@nexusmods.com: application name, a short description, a logo for a dark background, the source link, and
the callback address `http://127.0.0.1:47823/nexus/callback`. Put the Client ID they send into `Directory.Build.props`.

## Evidence

The desktop harness's N-1 check (a scripted token endpoint, a simulated browser following the real loopback redirect,
a test signing key); the v1.1.6.0 gate's contracts. A real sign-in needs the registered Client ID.
