# v1.0.9.0 — Every command reachable (internal)

Roadmap T-1, and D-11 recorded.

## The three commands removed

A sweep after the split listed every `ICommand` the desktop declares (251) and where each is used. Three had only
their declaration and their assignment:
- `ToggleWorldMapCommand` (the Map page): bound nowhere since the world cards began setting the expansion directly
  (noted in v1.0.8.3). `IsWorldMapExpanded` stays; the world cards still set it.
- `ChooseLocalConnectionCommand` and `ChooseRemoteConnectionCommand` (the setup wizard): the Local / Remote choice step
  was removed earlier; the tab commands call `ChooseLocalConnection()` and `ChooseRemoteConnection()` directly, and
  those stay.

## The reachability check

The gate reads every ViewModel file and every `.axaml` / `.axaml.cs` file. It removes each command's declaration line
and its `X = new ...Command(...)` assignment, then requires each command's name to appear somewhere else: a XAML
binding, a code-behind call, a Ribbon group, a command-role list or other code. A harness reference does not count. Tried
both ways before it was kept: it passes on this tree and fails, naming the command, when a declared-and-assigned command
with no use is added.

## Other sweeps that found nothing

- No window or code-behind code listens for a property name that moved to a page (`PropertyName` checks).
- Page properties computed from window state are raised when that state changes: `BrowserViewUrlVerbatim` (fixed in
  v1.0.8.9), `WorkspaceDeploymentMode` (raised on tab switch), `ShowSaveFolderAccessFix` (raised when the tab's backup
  inventory loads).

## The backlog (D-11)

The owner scheduled B-4, B-3 and B-2 on 2026-10-12, then a documentation pass and a new accepted baseline (T-2,
v1.1.0.0). B-4 already exists in large part: the Discord bot has had start, stop, restart, save, backup, broadcast and
moderation slash commands since v0.6.17.0. v1.0.9.1 closes its gaps (Discord's 3-second reply limit for long commands,
the pre-start MOD check).
