# v0.8.3.0 — Give Item Picker

This closes the v0.7.112.0 follow-up "an item-id picker/catalogue matched to the installed game version". Give Item and
Starter Kits take Palworld's internal ids (`PalSphere_Mega`, `Kitsunebi`), which admins had to know or look up.

## Where the ids come from

Palworld keeps its item table inside the packed game archive, a single 5 GB `Pal-WindowsServer.pak` on this
server. Reading it would need a full Unreal asset and DataTable parser. A hand-written list goes stale with each game
update, and a wrong id is worse than no list. The catalogue uses three sources that are real by construction:

- **The world save.** Two things in the decoded `Level.sav.json` carry an id:
  - every item slot, in `ItemContainerSaveData`, has its item's `static_id`;
  - every Pal, in `CharacterSaveParameterMap`, has a `CharacterID`.

  These are exactly the ids the installed game version wrote.
  - `SaveGameIdReader` streams the file with `Utf8JsonReader`, without building a DOM.
  - It skips empty and `None` slots, plus anything outside the give validation's id rule (`^[A-Za-z0-9_]{1,64}$`).
  - Alpha Pals (`BOSS_<id>`) count as their species and are flagged.
- **Saved Starter Kits.**
- **Earlier gives.** `HeadlessKitService` now remembers each manual Give that was delivered with no error-looking
  reply, in `players/give-history.json`. The list is newest first, has one row per id, and is capped at 200.

The limit: an item nobody in this world has had yet is not listed. The page says so, and typing an id by hand still works.

The decoded save is `Level.sav.json`. It is refreshed whenever a world change commits (v0.6.12.0), so it can be older
than `Level.sav`. The ids it contains are still valid, and the picker shows when the save was decoded.

## Pieces

- `SaveGameIdReader` (HeadlessHost): the streaming reader.
- `HeadlessGameIdCatalogService`, which does three things:
  - resolves the newest world, the same rule the explorers use;
  - caches the parse by path, write time and size;
  - merges the three sources into one row per (kind, id), ignoring case, with world casing winning.

  Each row carries its world count, in-kit, given-before and alpha flags. The route is
  `GET /api/v1/players/give/catalog`, also profile-scoped. It is read-only, so it needs Operator, like reading kits.
- Core: `GameIdSearch.Matches` (every typed word, ignoring case and underscores), `KitEntryText.Append` (adds a line
  and keeps any half-typed text) and `KitEntryText.TryParseAmount` (items 1 to 1,000,000, Pal level 1 to 100, the
  server's own limits).
- Desktop: a "Find an item or Pal" card under Player Administration, which has:
  - search, then Load IDs;
  - a list showing where each id comes from;
  - an Amount/Level box;
  - Add to Give and Add to Selected Kit.

  Switching server tabs clears the list, so another server's ids are never offered.

## Verification

- Logic harness, 5 scenarios:
  - the reader, on a fixture shaped like palworld-save-tools output, with the traps: empty and None slots, an
    RCON-injection-shaped id, alphas, and a sibling `value` that is not a species;
  - merging;
  - search, append and limits;
  - give history, which keeps delivered gives, not refused or failed ones, and survives a restart;
  - the service: no world, an undecoded world, the cache, a changed save, and an unreadable save.
- `scripts/Test-v0.8.3.0-RouteSmoke.ps1`, on the published exe, with a synthetic save:
  - with no world yet, the route returns kit ids;
  - it returns merged rows on both route forms;
  - a 19 MB save of 200,000 slots is read in about 0.3 s, and 31 ms from cache;
  - a changed save is read again.
- Real data, read-only: the live world gives 122 items and 29 Pal species. That matches an independent count of the
  raw save: 30 names, with the two `BOSS_` alphas folded into their species.
- Live Desktop (clone profile): Load IDs, search "sphere mega", add with amount 10, the Pal switches the box to
  Level, and an honest "select a kit first" message. Screenshot: `give-item-picker-live.png` in the checkpoint.

## Not verified
