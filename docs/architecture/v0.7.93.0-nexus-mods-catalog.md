# v0.7.93.0 — Nexus Mods Catalog

## Context

Second of the "real gaps" sequenced after the competitive feature review (Live-Session Backlog in
`docs/roadmap/PRODUCT_ROADMAP.md`). MystTiq had Steam Workshop import and a validated ZIP install;
competing panels (PalSupervisor and others) also browse Nexus Mods. Before designing anything, the
Nexus public API v1 spec and its API Acceptable Use Policy were read, because they constrain what is
honestly possible.

## What the Nexus API allows (and therefore what this ships)

- **No catalog search.** v1 offers `trending`, `latest_added`, `latest_updated` (10 mods each) and
  `mods/{id}` lookup. The card offers exactly those, plus lookup by mod id or a
  `nexusmods.com/palworld/mods/{id}` page URL. It does not pretend to search.
- **Direct downloads are Premium-only.** `download_link.json` returns 403 for free accounts unless the
  caller supplies the one-time `key` and `expires` from an `nxm://` link. So: Premium accounts get
  **Download & Install Selected File**; free accounts get **Open on Nexus** (browser download, then the
  existing Choose ZIP) and **Install From Link**, which parses a pasted `nxm://palworld/mods/{m}/files/{f}?key=…&expires=…`
  link and uses that key. Nothing bypasses the Premium gate.
- **Each user brings their own API key, and it must not live server-side.** The client runs in the
  Desktop app, so the key is never sent to the MystTiq management server. It is held in memory, and
  saved only when the user presses **Save Key** (DPAPI-encrypted via the existing `CredentialStore`,
  Windows only); **Forget Key** deletes it.
- **Headers/attribution.** Requests send `apikey`, `Application-Name`, `Application-Version` and a
  User-Agent; the card shows Nexus attribution and an independence disclaimer; rate-limit headers
  (`x-rl-hourly-remaining`, `x-rl-daily-remaining`) are surfaced; 401/403/404/410/429 map to plain
  messages.

## Design

- `MystTiq.Core/Services/NexusModsLinks.cs` (pure, unit-tested in the logic harness): `nxm://` parsing
  (Palworld only, requires key and expiry), mod id / page URL parsing, `IsAllowedDownloadHost` (https on
  `nexusmods.com` / `nexus-cdn.com` and their subdomains only, lookalike hosts refused), and archive
  sniffing (`zip` / `7z` / `rar` from magic bytes).
- `MystTiq.Desktop/Services/NexusModsClient.cs` (`INexusModsClient`): the v1 calls plus a streaming
  download with a 750 MB cap. The CDN URL is pre-authorised, so the API key is not sent to it.
- `MainWindowViewModel`: connect / save / forget key, the three lists, lookup, files (old-version files
  hidden), open page, download-and-install pipeline. The pipeline downloads to a temp file, sniffs the
  header, refuses anything that is not a ZIP with a specific message (7z/rar explained), then hands the
  file to the **existing** `InstallModZipAsync`, so server-side extraction limits and traversal rejection
  apply unchanged. Temp files are always deleted.
- `MainWindow.axaml`: a collapsed-by-default "Nexus Mods Catalog" expander on the MOD Library page.

## Before a public release

Nexus's policy says public-facing applications must contact Nexus support with a testing build before
release, and that personal keys are not for embedding in a public app (each user supplies their own,
which is what this does). That registration is a project decision, not something code can do; it is
recorded in the roadmap.

## Verification

- Solution and Desktop builds clean, 0 warnings/errors.
- Logic harness: 5 new `NexusModsLinks` scenarios pass (well-formed link; rejects other games, missing
  key/expiry, wrong shape, wrong scheme, blank; mod id from number/URL only; https Nexus-host allowlist
  incl. lookalike refusal; archive header detection).
- Live: the three endpoint paths (`users/validate`, `games/palworld/mods/trending`,
  `games/palworld/mods/3329`) exist and answer HTTP 401 "Please provide a valid API Key" to an invalid
  key sent with the required headers, which the client maps to its key-rejected message.
- **Not verified end to end:** no Nexus API key was available in this environment, so authenticated
  responses (JSON field mapping for mods/files/download links) and a real download-and-install were not
  exercised, and there is no GUI automation for the native app. The DTOs follow the published spec; the
  first real Connect/Trending/Install by the user is the true test, and any field mismatch would show as
  a blank field rather than data loss.
