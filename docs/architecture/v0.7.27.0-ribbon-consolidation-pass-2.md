# v0.7.27.0 — Ribbon Consolidation Pass 2

## Goal

Third version in the GUI/workflow/UX overhaul roadmap: the second wave of ribbon relocations, continuing directly from v0.7.26.0 using the same infrastructure v0.7.25.0 built. Items 31, 33, 39, 46, and 55 from the roadmap's findings log.

## What shipped

Five new per-page groups added to `MainWindowViewModel.BuildRibbonGroupsForActivePage()`, each relocating an existing in-page toolbar's buttons to the ribbon with zero behavior change:

- **Workspace** ("Workspace" group): Refresh (`LoadConfigurationCommand`). "Validate All" (`ValidateWorkspaceCommand`) stays on the page — not part of this relocation, per the original request.
- **Backups** ("Backups" group): Create (`CreateBackupCommand`), Verify All (`VerifyAllBackupsCommand`), Refresh (`RefreshBackupsCommand`), Open Root (`OpenBackupRootCommand`). The page's remaining header (`BackupState`/`BackupTotalSizeText`) is unchanged.
- **MOD Dashboard / MOD Library** ("MODs" group): Refresh MODs and Verify & Scan (`RefreshModsCommand`/`VerifyModsCommand`). These two pages already shared one in-page toolbar row before this release, gated by the existing `IsModInventoryPage` property (`SelectedPage is NavigationPage.ModDashboard or NavigationPage.ModLibrary`) — the new ribbon group reuses that exact same combined condition rather than splitting it into two separate per-page groups, so both pages keep reaching these two actions exactly as before.
- **UE4SS** ("UE4SS" group): Refresh Runtime — the *same* `RefreshModsCommand` as the MODs group above, just under its own `IsUe4ssPage`-gated group with a page-appropriate label/automation name, matching the in-page button (`Content="Refresh Runtime"`) it replaces.
- **Server Doctor** ("Doctor" group): Run Doctor (`RunDoctorCommand`) and Export Report (`ExportDoctorCommand`).

All five groups follow the `else if` chain already established in v0.7.26.0 for Server Setup/Configuration/Console — one group per page, added right after those three.

## Explicit non-goals

- No change to the ribbon's shrink/overflow mechanism itself — with up to 4 groups now potentially visible at once (Server Control, Quick Actions, plus one page-specific group), the overflow path is more likely to actually trigger on a narrower window than it was in v0.7.25.0/v0.7.26.0, which is exactly the scenario it was built to handle.
- No further relocations beyond these five — remaining ribbon-worthy buttons (Force Stop, Install Missing, Kill Processes) are new capabilities, not relocations, and are their own version (v0.7.28.0).
