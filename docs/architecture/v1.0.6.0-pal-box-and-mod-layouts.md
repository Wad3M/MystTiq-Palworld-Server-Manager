# v1.0.6.0 — Pal Box Edits and Game-Folder MOD Layouts (internal)

The owner agreed the proposed milestone on 2026-10-06 ("approve 1"): S-3 (add and remove a Pal, moved from v1.0.4.0) and
M-2 (MODs laid out as the game folder). The same message asked for the evidence owed elsewhere to be gathered
automatically where possible ("try to do 3 automatically (VM is on)").

## S-3: where Pals live

These are the clone's decoded world and player save (PlM, 2026-10-06):

- **A Pal's record:** each Pal is an entry in `CharacterSaveParameterMap`.
  - Its key is `{PlayerUId: zero, InstanceId, DebugName}`.
  - Its `value.RawData.value` holds `object.SaveParameter.value`, which carries `CharacterID`, `Level`,
    `OwnerPlayerUId`, `OldOwnerPlayerUIds` and `SlotId:{ContainerId, SlotIndex}`.
  - It also holds a `group_id`: the owner's guild.
  - A player's own character record has `IsPlayer`.
- **The Pal box:** it is the `PalStorageContainerId` in `Players/<uid>.sav` (960 places; the party is
  `OtomoCharacterContainerId`, 5).
  - Its entry in `CharacterContainerSaveData` lists only filled places, each `{SlotIndex, RawData:{player_uid: zero,
    instance_id}}`.
  - Every Pal's `SlotId` matched its place (37 of 37).
- **The guild:** its `GroupSaveDataMap` entry lists every member character in `individual_character_handle_ids`. That
  is 89 entries: the players with their own uid as `guid`, and every Pal with a zero `guid`.

## S-3: the edit (`PalBoxEdits`, pure)

**Add.** The Pal is a copy of a Pal of that species whose `SlotId` container is a Pal box (the player's own preferred).
A Pal box is recognised as a container the size of the player's box. Copying a record the game wrote keeps level, HP,
talents and skills consistent; MystTiq does not generate stats. The copy is changed as follows:
- a new `InstanceId`;
- the player as `OwnerPlayerUId` and the only `OldOwnerPlayerUIds`;
- the first free box place in `SlotId`;
- `OwnedTime` set to now;
- no `NickName` or `LastNickNameModifierPlayerUid`;
- the player's guild as `group_id` (taken from the player's own record).

A slot (copied from the box's own layout) and a guild member entry are added alongside it.

**Remove.** Only a Pal in the player's own box, and owned by them. Its record, its place and its guild entries go
together.

**Verification (`VerifyOnlyThisChanged`):** the world's character ids, the box (place, id, species, level, name, gender)
and the guild's member ids must each be exactly the old ones plus or minus this Pal.

**Refused:**
- a species with no Pal in a Pal box (nothing the game wrote to copy);
- a Pal outside this player's box (party, base, another player's box);
- a player with no guild;
- a full box.

## S-3: the guard (`HeadlessPalBoxEditService`)

It is the same as the v1.0.4.0 inventory edit:
- a single-use preview (15 minutes);
- PalServer stopped;

## M-2: layouts

`ModArchivePlanner` (Core) now installs two layouts it refused in v1.0.5.0.

**A LogicMods PAK (`LogicModsPak`).**
- Its archive folder (the PAK and the files beside it, such as `BasesPlus.modconfig.json`) is copied into
  `Pal\Content\Paks\LogicMods\<package>`, keeping the names.
- That folder layout is the one Steam Workshop items use. The service already lists, removes and rolls back such
  folders as nested PAK MODs (`ScanNestedPakFolder`, `FindNestedPakModFolder`).

**A PAK with one UE4SS script root (`MixedPakAndScripts`, `PAK+UE4SS`).**
- It installs as two parts under one package name: the PAK (to `~mods` or, as above, to LogicMods), and the scripts from
  their root as a UE4SS MOD folder.
- The MODs page lists both parts, and each is removed or rolled back by its own type. The UE4SS part gets its own
  rollback snapshot before the install.

**Checks and notes.**
- Both layouts need UE4SS (`HasUe4ssRoot || HasLegacyModsRoot`).
- Both destinations are checked before any file is copied, so a taken name writes nothing.
- When `BPModLoaderMod : 1` is missing from mods.txt, the result says that LogicMods PAKs will not load. MystTiq does not
  switch it on: that is the owner's configuration.

## Fixed on the way

- **A held file at the final replace.** A fresh `Level.sav` held for a moment (seen once in the Pal box smoke: "Unable to
  remove the file to be replaced") rolled a good edit back. `FileRetry.Replace` now retries a sharing violation up to six
  times, 0.5 s apart. A denied access is not retried.
- **The restore's leftover copy.** On the clone, three of the game's own September backups were owned by Administrators,
  read-only for users, and the restore could not delete its temporary copy of them. The copy was a verified duplicate:
  all 21 files matched the restored world. The restore now names the reason and points to Fix Save Folder Access.
