# v1.1.5.1 — Safe file paths (internal)

Owner, 2026-10-26: "we need to look into these issues and adjust the code", about GitHub code scanning (CodeQL, default
setup) on `main`: 23 "Uncontrolled data used in path expression" alerts and one "User-controlled bypass of sensitive
method". The owner chose to ship the fixes as v1.1.5.1 rather than move the v1.1.5.0 tag.

## The path alerts (#1-#22, real)

- `HeadlessModManagementService` (#1-#3, #9-#22). The package passed `NormalizePackage` (a bare file name, no `..`, no
  invalid characters), which CodeQL does not know as a check; the **type** passed nothing. It names
  `mod-snapshots\<TYPE>_<package>.zip` and `mod-descriptions\<TYPE>_<package>.json`, and ASP.NET decodes `%5C` in a
  route segment, so `/mods/..%5C..%5Cx/pkg/description/source` (Operator) wrote or deleted a `.json` outside the runtime
  folder. Now `IsKnownType` refuses any type but PAK, UE4SS and NATIVE at Rollback, Get description and Set description
  source (an ordinary failure result, as for other refusals), `NormalizeType` throws inside the path builders, and the
  snapshot and cache paths, the PAK files and the UE4SS folder go through `SafePath.ChildOf`.
- `HeadlessCharacterMigrationService.DisposeSourceCharacterAsync` (#4-#8). The route's `{sourcePlayerId}` named the
  `.sav` files that Archive moves and Delete deletes, with no check (the preview and apply steps only accept players
  found in the save; this step did not). It now takes only `SafePath.IsPlayerId` (32 hexadecimal characters), and the
  save, companion and archive paths go through `SafePath.ChildOf`.
- Not flagged, checked anyway: the player copy and delete services build paths only for a player found in the world
  save, so a made-up ID never reaches a path.

`SafePath.ChildOf(root, name)` resolves `Path.GetFullPath(Path.Combine(root, name))` and refuses it unless it starts
with the full root plus a separator (ordinal, case-insensitive on Windows): `..\`, `../`, absolute paths, the folder
itself (`""`, `.`) are all refused with `InvalidDataException`. A full-path prefix check is the guard CodeQL recognises.

## The bypass alert (#24, false positive)

`LocalManagementApiHost`'s authentication middleware: a request without `Authorization: Bearer …` gets 401; with one,
the token must equal the service's secret (`HeadlessSecretFileService.FixedTimeEquals`, constant time) or a principal's
session before `next()` runs. The decision has to depend on what the request sends; that is what authentication is.
Recommended: dismiss as "False positive" with this reason.

## Evidence

The logic harness's "Safe paths" scenario (refusals, nothing written, the decoy save untouched, a real type still
saves); the v1.1.5.1 gate's contracts; after the push, the CodeQL re-scan on `main`.
