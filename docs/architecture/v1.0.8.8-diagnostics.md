# v1.0.8.8 — Update Center, Server Doctor, Crash Analyzer and Diagnostics Center (internal)

Roadmap C-8, with the mover from C-2.

## DiagnosticsViewModel (`vm.Diagnostics`)

**What moved:**
- the Update Center: the component lists and every row's Update (the former `MainWindowViewModel.ComponentUpdates.cs`);
- Server Doctor: the checks, the unified findings, recheck, fix and export;
- the Crash Analyzer: findings, the isolation plan and the crash history;
- the Diagnostics Center: network, the internet reachability check, firewall status and Allow through Firewall, UPnP,
  this computer's and this connection's findings, anti-cheat, and console capture (the former
  `MainWindowViewModel.ConsoleCapture.cs`).

**What stays with the window, handed to the page:**
- the server-files update (`UpdatePalworldServerAsync`) and its result text (`DistributionDetail`), and the pip update:
  they are the HOST page's install flow;
- the machine's Palworld instance list (`RefreshAllInstancesAsync`), which Run Doctor refreshes after its report;
- `Navigate` and the MOD pages (UE4SS's Update opens the UE4SS page with the latest release previewed).

**A notification's repair link** stays with the window and now calls `Diagnostics.FocusFinding(id)` instead of setting a
field.

**The session** gained `ServerIsRunning` (Restart from Diagnostics needs it). `FormatTime` and the version text
(`AppVersionText`) are shared statics of the window.

**Allow through Firewall with no saved profile** (the setup wizard's last step) used the editor's fields built with no
id; it now asks the session, which builds the same profile (the selected profile's id is null exactly then).
