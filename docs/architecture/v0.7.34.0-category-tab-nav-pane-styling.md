# v0.7.34.0 — Category Tab & Nav Pane Styling

## Goal

Tenth version in the GUI/workflow/UX overhaul roadmap. Roadmap items 9 and 10 — two style-resource swaps flagged from a screenshot comparison, both isolated to `Styles/DesignSystem.axaml` and one line of `MainWindow.axaml`.

## What shipped

### Category tab checked/hover gradients swapped (item 9)

Screenshot evidence showed the selected category tab ("Home") rendering with the bright/light solid fill, while the user wanted the *selected* state to read as the darker/glass look and *hover* to be the bright one.

Grounding confirmed this was backwards relative to intent already documented in the stylesheet itself: a comment directly above the per-category `:checked` `BorderBrush` overrides reads "Category selection is dark glass; semantic color lives on the overline, underline and glow" — but the actual setters didn't match that comment:

- `ToggleButton.categoryTab:checked Border.categoryTabGlow` set `Background="{DynamicResource CategoryActiveGradient}"` (the bright gradient).
- `ToggleButton.categoryTab:pointerover Border.categoryTabGlow` set `Background="{DynamicResource GlassOptionHoverGradient}"` (the darker glass gradient).

Swapped which resource each selector uses — `:checked` now uses `GlassOptionHoverGradient`, `:pointerover` now uses `CategoryActiveGradient`. Both resources are pre-existing `ThemeCatalog`-backed brushes; no new resources were created, and every per-category `BorderBrush`/`BoxShadow` accent (the colored underline/glow that identifies which category is selected) is untouched — only the two shared background setters moved.

### Navigation pane background changed (item 10)

The nav pane container's background was `NavGlassSurfaceGradient` — a flatter fill, distinct from the diagonal bright-to-dark glass sheen (`GlassOptionHoverGradient`) already reused across ribbon buttons, category tabs, and nav buttons. Changed the nav pane `Border`'s `Background` (`MainWindow.axaml`) from `NavGlassSurfaceGradient` to `GlassOptionHoverGradient`, matching the look referenced ("like the hover look on a category tab, e.g. Server").

`NavGlassSurfaceGradient`'s own definition in `DesignSystem.axaml` was left in place — it's a shared style-resource declaration, not something scoped to only this one usage, and removing an unused resource definition goes beyond what this finding asked for.

## Explicit non-goals

- No change to the `.card`/`.statuscard` shared styles or any other selector — this release touches exactly two `Background` bindings.
- No removal of the now-unreferenced `NavGlassSurfaceGradient` resource definition.
