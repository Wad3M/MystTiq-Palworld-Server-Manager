# v0.9.8.0 — small screens, alerts and Linux install

The smaller follow-ups left open by v0.9.5.0 and v0.9.6.0, a title-bar report from the user, and a Linux desktop
shortcut the user asked for on 2026-09-29.

## The "+" disappeared on small windows

The title bar's brand column was a fixed 430 px. At the window's minimum width (950 px) that left the tab strip about
330 px, and the tabs, the "»" and the "+" were one horizontal panel clipped at its right edge, so whatever did not fit,
the "+" first, was cut off (reported by the user). Now:

- the tabs sit in an Auto column capped at the strip's width less the "+" and, when shown, the "»"
  (`TabListMaxWidth`); both buttons follow in their own columns, so they are never cut and stay next to the tabs;
- at least one tab stays in the strip: the tab list's selection binds the active tab, and an empty list cleared it
  (found by the ArtworkHarness while building this); a tab too wide for the space is clipped in its own column;
- below 1200 px the brand drops its "Palworld Server Manager" subtitle and its fixed width
  (`ShowBrandSubtitle`, updated after the window's layout pass, not inside it).

The ArtworkHarness checks the "+" is inside the strip and the window, and the active tab is shown, at 950, 1100 and
1440 px.

## Alerts when a component falls behind

v0.9.5.0 showed a game server behind Steam's public build, and PalDefender's "not updated for this game version"
warning, as Doctor findings only. The Alert Center now has a `ComponentOutdated` rule (on by default; a rules file
from before this version reads as on) that raises "Game server update available" and "PalDefender update needed"
through the usual channels, with reminders and a "Resolved" notice, like every other alert. Steam's build is the cached
one, so the alert never waits on SteamCMD, and an unknown build decides nothing (an open alert is not called resolved).

## Firewall rules and the network in use

A rule covers the Domain, Private or Public profile (or several). The check now reads which profile the computer is on
(`INetFwPolicy2.CurrentProfileTypes`) and counts a rule only where it covers it. The clone's rule on this machine is
Private-only; on a Public network it now reads "A rule allows UDP 8311 only on other networks (Private); this computer
is on a Public network", and Allow through Firewall repairs it to every profile.

## Server search on wider networks

The search used the /24 around each adapter address whatever the subnet. It now uses the adapter's own prefix, capped at
/22 (1,022 addresses, still a few seconds at 256 at a time); a smaller subnet is searched as itself. Typed ranges accept
/22 to /32.

## Linux install with a desktop shortcut

`scripts/Install-MystTiqDesktopLinux.ps1` copies the Linux download to a machine over SSH (verifying its SHA-256),
unpacks it into `~/MystTiq/<version>` with `~/MystTiq/current` pointing at it, and writes a `mysttiq.desktop` launcher to
the desktop and `~/.local/share/applications`, starting `~/MystTiq/current/MystTiq.Desktop`, so a later install updates
the same shortcut. XFCE 4.18+ only runs a desktop launcher without asking when it is marked trusted; the script sets that
through the logged-in session's bus when there is one. Nothing outside the home folder is touched. It replaces
`Deploy-Test-MystTiqDesktopLinux.ps1`, which was pinned to v0.3.1.9 and an old address. First used on the test VM on
2026-09-29 (v0.9.7.0; the launcher was marked trusted and the app started).

## Accounts across an upgrade

`Test-v0.9.8.0-UpgradeAccounts.ps1`: the accepted baseline (v0.8.25.0) creates an Operator, an Admin, a Viewer who then
changes her password, and an Admin who is then disabled. This version lists the same accounts, each signs in with its
password and role (the changed one with the new password only), the disabled one is refused, and the Owner token still
works; an account created by this version signs in after rolling back to the baseline.
