# v0.7.5.0 — No-Scroll Initiative, Pass 1

## Goal

The deferred second half of the v0.7.1.0→v0.7.4.x UX plan: work toward every page being usable without scrolling at a typical window size, without cutting content. The plan's own framing was explicit that this is directional and multi-release, not a single deliverable — v0.7.4.0 shipped card flare alone, and the user asked to continue with the no-scroll work next.

## Fresh audit

Page heights are not static across releases — features landing in between shift the ranking. A re-audit (via a research pass over the current `MainWindow.axaml`) found the worst offenders had changed since the original v0.7.1.0 planning audit:

| Page | Est. height (this pass) | Driver |
|---|---|---|
| Players | ~2450px | World Map (fixed 480×480 canvas) + Pal Editor, both relocated/added here in v0.7.1.0 |
| Doctor | data-dependent, ~1600px+ | One card per finding |
| Diagnostics Center | ~1800px | Three separately-versioned diagnostic tools concatenated (Network Diagnostics, WAN/External Reachability v0.6.11.0, Local Machine Diagnostics v0.6.4.0) |
| Alert Center | ~1580px | Three unrelated feature areas concatenated (Threshold Rules, Discord Bot, Anti-Cheat & Save-Integrity Scanning) |
| Configuration (Simple Settings) | data-dependent, ~1000–2500px | `WrapPanel` of setting tiles scales with however many of the 34 curated settings are present |
| Settings | ~1600px (editing) / ~1920px (wizard Step 2) | Managed Server Configuration + Security cards — see bug below |

Players overtaking Guilds as the worst offender is a direct, traceable consequence of v0.7.1.0's own Pal Editor relocation (moving it off Guilds, where it didn't conceptually belong, onto Players) — a reminder that fixing one page's ordering can make another page's height problem worse, and height needs to be reassessed after each release rather than assumed fixed from the original audit.

## Bug fixed: wizard card bleed-through

The audit surfaced a genuine correctness bug, not just a height problem: the Settings page's "Managed Server / Headless Configuration" and "Security" cards (`MainWindow.axaml`, previously with no `IsVisible` binding at all) rendered unconditionally below the v0.7.3.0 wizard, regardless of which step was active or whether a profile even existed yet to configure. The wizard's Step 1/2/3 cards were correctly gated behind `IsWizardStep1`/`IsWizardStep2`/`IsWizardStep3`, but the two cards below them were not — meaning the wizard flow never actually got shorter than the non-wizard view; it was strictly the full view *plus* whichever step card was showing.

Fixed by adding `IsVisible="{Binding !IsCreatingNewProfile}"` to both cards, matching the exact gating already used by the adjacent Save Profile/Delete Profile buttons. This is a real behavior fix (a new-profile wizard no longer shows Managed Server Configuration/Security data for a server that may not exist yet) as well as a height win.

## What shipped

### Global denser spacing (zero content removed)
Three small, broadly-applied levers identified by the audit as the biggest "free" wins:
- `Styles/DesignSystem.axaml`: `Border.card` `Padding` 14→11.
- `Styles/DesignSystem.axaml`: the shared `Button`/`TextBox`/`ComboBox` `MinHeight` 34→31 (and `Button`'s `Padding` 12,6→12,5 to match).
- `MainWindow.axaml`: every page-root `StackPanel`'s `Spacing` 16→12 — 18 occurrences, mechanically verified via regex count before and after.

None of these touch layout structure or remove any element; they only tighten the space each element already occupies.

### Collapsible secondary sections
A new lightweight pattern rather than a stock Avalonia `Expander` (a `Style Selector="Expander.navgroup"` already existed in `App.axaml` but was unused/dead — no `<Expander>` element appears anywhere in `MainWindow.axaml` — so introducing the real control now would be untested territory; a plain bool + button-header follows the MVVM idioms already used everywhere else in this codebase, e.g. the existing Simple/Advanced Settings view toggle):

- **`Button.sectionToggle`** (`Styles/DesignSystem.axaml`): a header-styled button — transparent background, no border, no padding, hand cursor — that reads as plain clickable text, not a button chrome, so it fits inline as a section header.
- Six new `MainWindowViewModel` bool properties (`IsWorldMapExpanded`, `IsPalEditorExpanded`, `IsWanDiagnosticsExpanded`, `IsLocalDiagnosticsExpanded`, `IsDiscordBotExpanded`, `IsAntiCheatExpanded`), all defaulting to `false` (collapsed), each with a matching `ToggleXCommand` (`RelayCommand`) that flips the bool. No persistence — every section starts collapsed each app launch, which is the intended behavior for "secondary, occasional-use" content.
- Applied to: Players' **World Map** (the fixed 480×480 canvas is the single largest content block on the page) and **Pal Editor** (a full two-column stat-edit grid); Diagnostics Center's **WAN / External Reachability** and **Local Machine Diagnostics** (Network Diagnostics, the primary tool, stays expanded); Alert Center's **Discord Bot** and **Anti-Cheat & Save-Integrity Scanning** (Threshold Rules, the page's primary content, stays expanded).
- Each header row's secondary action buttons (e.g. World Map's "Browse for Map Background"/"Clear Background", Local Machine Diagnostics' "Diagnose Connection") are also gated behind the same expanded flag, so a collapsed section shows only its title and chevron — not orphaned action buttons with nothing to act on.

## Explicit non-goals / deferred

- **Simple Settings tile `WrapPanel`** (Configuration page): the most data-volume-dependent page in the app — height scales directly with how many of the 34 curated settings are present in the live `PalWorldSettings.ini`. No structural change made this pass; a future pass should look at reducing tile size or column density rather than collapsing (this content is the page's entire purpose, not secondary).
- **Doctor page**: height scales with finding count; no easy mechanical win without changing what a "finding" card looks like.
- **Alert Center as separate nav pages**: the plan's original suggestion was splitting Discord Bot and Anti-Cheat into their own reachable pages rather than collapsing them in place. This pass chose the lower-risk, lower-surface-area collapse pattern instead — consistent with the same mechanism used on Diagnostics Center and Players — deferring the larger nav-restructuring option to a later pass if collapsing proves insufficient.
- Further passes remain expected; this is explicitly not a "no-scroll is done" release.
