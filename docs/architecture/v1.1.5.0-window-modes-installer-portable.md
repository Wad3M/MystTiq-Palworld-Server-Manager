# v1.1.5.0 — Resizable window, Simple/Advanced, installer, portable (internal)

Roadmap V-1, V-2, W-1 and W-2. Owner, 2026-10-22: "roll all future updates to v1.1.5.0", "I would like a windows installer
and a portable version for Windows", then "go ahead and build v1.1.5.0".

## V-1: a window you can size

`WindowDecorations="None"` (the custom title bar) also removed the system's resize borders. `MainWindow.Placement.cs`
adds `ResizeGrips`: eight transparent borders (5-6 px on the edges, 10 px corners, 6 px at the top right so the close
button keeps its clicks) tagged with their `WindowEdge`, which call `BeginResizeDrag` (Windows and X11), hidden while
maximized. `WindowPlacement.Fit` puts a remembered placement (`window-placement.json`, normal bounds plus maximized) back
on the screens there are: raised to the minimum size, cut to its screen, moved onto the screen it overlaps most (centred)
when its title bar would not be reachable, never above the top. The app calls `UsePlacementStore`; the harnesses never
do, so a test cannot move or overwrite the owner's placement. Saved a second after a change, and at once when hidden to the
tray, on Exit and on a Windows shutdown.

## V-2: Simple and Advanced

`SimpleMode.HiddenPages` is the one list: Console, Workspace, Launcher, Inspector, World Transactions, MOD Dashboard,
UE4SS, Crash Analyzer, Save Tools, Diagnostics, HOST, Activity & Audit, Security and Fleet. In Simple their side-menu
buttons and the HOST tab are hidden, the World and MODs tabs open Players and MOD Library, the Configuration page's
Advanced button is hidden (and its simple view chosen), and Automation's New Rule card is replaced by a line saying where
it is. Navigation is not blocked. `LocalDisplayPreferencesStore` keeps `UiMode` beside `Density` (each save keeps the
other). The title bar's switch is a ghost button (structural, no intent class).

## W-2: the portable copy

`PortableMode` (Core) turns on when `portable.txt` is beside the executable, or one folder up from `headless\`. Every
folder lookup asks it first: `RoamingAppData` (desktop stores) is `data\config`, `LocalAppData` (runtime, crash reports,
the nxm inbox, update downloads) `data\local`, and `CommonAppData` (the service's configuration, fleet, secrets,
certificates; its default configuration path) `data\service`. A portable copy never reuses a helper it did not start
(the configured port held by an installed copy means a free port of its own). Writes to Windows are refused with
`PortableMode.RegistryRefusal`: the sign-in start (`StartWithSystem.IsSupported` is false), the nxm:// handler, and the
helper's `service-install` (exit code 2). `Package-GitHubRelease.ps1` makes `..._Windows-x64-Portable.zip` from the same
app folder plus `portable.txt` and its own START_HERE.

## W-1: the setup

`installer/MystTiq.Installer.wixproj` (WiX 5 from NuGet, `WixToolset.Sdk`, UI and Util extensions), built by
`scripts/Build-WindowsInstaller.ps1` from the packaged app folder (signed or not) into `..._Windows-x64.msi`. Per-machine
to `Program Files\MystTiq`; every file harvested with `Files Include="$(AppFolder)\**"`; `installed.txt` marks the copy;
Start-menu shortcut and a desktop-shortcut feature (WixUI_FeatureTree with the MIT licence); `MajorUpgrade` with
same-version upgrades; ARPCOMMENTS says the data is kept. ICE38/43/57 are suppressed (per-machine shortcuts in the
shared folders). The MystTiq service (`MystTiqPalworld`) is handled with quiet `sc.exe` actions only when its registered
program is in `\MystTiq\headless\` (case-insensitive): stopped before `StopServices` (ahead of any file removal), started
again before `InstallFinalize`, and deleted on a real uninstall (not an upgrade). The Update Center (`MystTiqSelfUpdate`)
downloads the setup for an installed copy (checked against SHA256SUMS.txt, kept under `LocalAppData\MystTiq\updates`) and
opens it with `msiexec /i`; a portable copy gets the portable ZIP. The release workflow hashes and attaches `*.msi`.
