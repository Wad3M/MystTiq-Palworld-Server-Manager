# v0.7.98.0 — Doctor: Disk, Backups, Admin Password, Memory and Recent Crashes

## Context

Fourth of the "enhancements to features we already have". The Doctor checked that paths exist, that ports
do not collide, that a config value known to cause instability is not set, and (on Linux) disk space. It did
not check the things that actually end a server's life:

- **Disk space** was only checked on Linux. On Windows nothing looked at free space, although a full disk
  stops the server and can corrupt a save (and the Crash Analyzer, v0.7.97.0, now recognises "disk full").
- **Backups**: only "the backup folder exists". Nothing said whether any backup exists or how recent it is.
- **Admin password**: nothing checked it. With the REST API or RCON on and an empty AdminPassword,
  authenticated requests are rejected, so MystTiq cannot kick, ban, save or broadcast.
- **Memory**: nothing looked at it.
- **Crashes**: the Doctor and the Crash Analyzer did not talk to each other, so a critical finding never
  reached the Doctor page or the Dashboard badge.

## What changed

The unified diagnostics report feeds both the Doctor page and the Dashboard badge, so the new findings show
up in both with no UI change. Decisions live in a pure `DoctorHealthRules` class; `HeadlessDiagnosticsService`
only gathers the inputs.

- **Disk space** (Resources): one finding per drive holding the server and/or backups (combined when they
  share a drive). Fail under 2 GiB free and Warning under 5 GiB (the same thresholds the Linux check used).
  If backups live there, free space below twice the largest backup is a Warning too, so the next backup is
  not the one that fails. The drive is resolved by longest mount-point prefix, so a folder on another drive
  or mount is measured on its own. The Linux Doctor's own server-drive check is not duplicated.
- **Memory** (Resources): Warning below 8 GiB installed (the commonly cited recommendation is 16 GiB, worded
  as a recommendation, not a requirement) or below 1.5 GiB free right now. An unreadable value is Skipped.
- **Backup freshness** (Backups), judged against the world rather than the clock: a stopped server whose
  world has not changed since the last backup is fully protected by an old backup. What counts is how long the
  world's latest changes have gone unprotected: Pass under a day, Warning up to 14 days, Fail beyond. A world
  with no backup at all is a Warning (not a Fail, so a freshly installed server is not nagged as broken the
  moment its first world appears). Palworld's own rolling `backup` folders are ignored when finding the
  world's last change.
- **Admin access** (Security): only judged when the REST API or RCON is on. Warning for an empty password
  (functional: MystTiq cannot administer), a very common password, or one under 8 characters. **The password
  is never echoed** in evidence or recommendation; only its length or the fact that it is a common value.
- **Recent crashes** (Stability): reads the newest Crash Analyzer report. Only findings that are new and
  Critical warn, so running the analysis again (which marks them reviewed) clears the warning. A report from
  before v0.7.97.0 carries no keys and cannot say what is new, so it is Skipped with a prompt to re-run.
- These are health-relevant (only the advisory "Identity" category is excluded from the totals), so a Warning
  can move a running server's Dashboard badge to DEGRADED and a Fail to ATTENTION, as intended: no health
  deduction without a visible finding.

## Deliberately not done

- No automatic fixes: each finding says what to do; none changes anything for you.
- No check of whether the REST and RCON ports are reachable from the internet. That needs an outside
  probe; the recommendation only says to keep them closed.
- No thresholds tuned to a specific machine: the numbers are stated in the evidence so they can be judged.

## Verification

- Solution and Desktop builds clean, 0 warnings/errors.
- Logic harness: 5 new scenarios cover every threshold: disk (fail, warn, next backup would not fit),
  backup freshness (none, none with no world, recent, old backup with an unchanged world, 5 / 20 days and 30
  hours of unprotected play), admin access (off, empty, quoted empty, common case-insensitively, short,
  strong, and that no password string ever appears), memory, and recent crashes (none, reviewed, new
  critical, new non-critical, older-format report).
- New live route smoke `Test-v0.7.98.0-RouteSmoke.ps1` (isolated sidecar, fixture with a weak password, a
  world and no backups, a log with an out-of-memory line): the new findings appear with real GiB figures;
  the weak password warns and does not appear anywhere in the report; a world with no backup warns and a
  fresh backup clears it; an unreviewed critical crash finding warns and analysing again clears it; the
  report's warning total matches its health-relevant findings.
- Real-data check (read-only): the Default Server now reports 320 GiB free of 953, 14.7 GiB of 31.9 free,
  an admin password that is set, no crash analysis yet, and **a real backup warning: the newest backup is
  12.1 days old and the world was written 6.4 days after it.** That was confirmed independently against the
  files (world last written 9/15 15:41; newest backup 9/9 06:54).
- **NOT verified:** the Doctor page rendering (no GUI automation; the findings reuse the existing list, so no
  new layout was added), and the Linux paths (drive resolution and the skipped server-drive finding were not
  run on Linux).
