# Competitive Survey — v0.6.15.0 and Beyond

## Goal

A direct user request: survey other Palworld dedicated server management tools on GitHub, compare their features against MystTiq's actual current feature set, and turn genuinely new or better capabilities into a scoped roadmap addition for the `v0.6.x.0` line.

## Method

Three parallel research passes (general desktop/GUI managers; Docker/web-panel/hosting-automation tools; CLI tools, Discord bots, and save-file editors), each briefed with MystTiq's real feature set so findings would be genuine gaps rather than restating things MystTiq already does. 21 distinct repositories surveyed:

**Desktop/GUI managers**: Lukium/palworld-admin, PrakashMandal-IV/palworld-server-manager, amantu-qbit/palworld-server-manager, TRRabbit/palworld-server-manager, Rhyse76/palworld-server-manager, Andrew1175/Palworld-Dedicated-Server-Manager, diogomartino/palworld-ds-gui.

**Docker/web-panel/hosting**: thijsvanloef/palworld-server-docker, jammsen/docker-palworld-dedicated-server, PalSupervisor/PalSupervisor, JaredScar/Palbox-Manager, RNZ01/palworld-server-dashboard, na-ji/palworld-admin.

**CLI/Discord bots/save editors**: PalworldSaveTools (deafdudecomputers), Palworld Save Pal (oMaN-Rod), Palworld Pal Editor (KrisCris), PalworldServerTools (shupershuff), PalworldAdminCLI (JengaMasterG), Sphere (projectsphere), Palbot (dkoz, archived).

## Findings, ranked by validation strength

### Tier 1 — multiple independent, actively-maintained tools converge on the same gap

1. **Item/Pal-stat/inventory/base-storage save editing.** The single strongest signal in the whole survey: PalworldSaveTools (800★, commits within the last day), Palworld Save Pal (293★, commits today), and Palworld Pal Editor (574★, active) all do real, surgical editing of individual Pal stats/IVs/skills/passives, player inventory contents, and base/guild-chest storage — none of which MystTiq can do. This was explicitly flagged and deferred as far back as the v0.6.7.0 checkpoint ("the surgical byte-level EditPlan engine... confirmed via research that no Pal/inventory container struct decoder exists anywhere in the codebase") and the v0.6.9.0 checkpoint (anti-cheat scanning blocked on the same missing infrastructure). Three mature, hundreds-of-stars tools proving this is real, wanted, and buildable is a strong signal to finally build it.
2. **Live in-game world map with player/Pal positions.** Appears in six separate tools (PrakashMandal-IV, amantu-qbit, TRRabbit, PalSupervisor, JaredScar, RNZ01) — the single most common feature across the whole survey that MystTiq lacks entirely.
3. **Two-way Discord bot control**, not just outbound notifications. TRRabbit, Lukium, PalSupervisor, and Sphere all let Discord issue real server commands (player lookup, RCON pass-through, moderation); MystTiq's Discord integration is dispatch-only today.
4. **Anti-cheat / save-integrity scanning.** PalSupervisor (level-gap thresholds with configurable responses) and Sphere (invalid Steam ID detection on join) both do this for real. Blocked on the same missing Pal/save-struct decode infrastructure as item 1 — building that unblocks both.

### Tier 2 — real, smaller-scope, worth scoping later

- In-panel MOD marketplace installs (PalSupervisor's one-click Nexus Mods integration) — MystTiq's MOD manager has no browse/install-from-marketplace capability.
- A public, read-only server-status page (RNZ01's `/view` route) for sharing status with a community without granting admin access.
- A self-updating Discord "live status card" that edits one message in place (jammsen) rather than MystTiq's current one-shot notification dispatch.
- TOTP two-factor authentication for admin accounts (JaredScar) — a real security enhancement MystTiq's RBAC doesn't have.
- Resource-threshold (CPU/RAM) auto-restart as a distinct automation trigger kind, alongside MystTiq's existing crash-detection and idle-auto-stop (Lukium, PalSupervisor).
- Cross-platform save conversion, Steam ↔ Xbox Game Pass (Palworld Save Pal) — real but niche.

### Explicitly not pursued (considered, rejected)

- **A full browser-based web dashboard** (RNZ01, na-ji, jammsen's sidecar) — the single largest capability gap versus the Docker/web-panel category as a whole, but a major architectural shift (MystTiq is a native desktop app + API by design) that deserves its own dedicated scoping pass, not a `v0.6.x.0` addition. Flagged as a candidate for a future major version line, not scheduled here.
- Kubernetes/Helm orchestration (thijsvanloef) — MystTiq targets single-host Windows/Linux installable-service deployment, not cloud orchestration; out of scope by design, not a gap.
- Multi-game support (Rhyse76) — a market-positioning choice (MystTiq is intentionally Palworld-specific), not a feature gap.
- Freemium monetization (TRRabbit) — a business model, not a feature.
- Home Assistant/smart-home integration (shupershuff) — real but a narrow hobbyist niche, low value for the broader audience.
- A bare RCON-only CLI (JengaMasterG) — MystTiq's existing RCON integration already exceeds this.

## Resulting roadmap sequence

Because items 1 and 4 share the same foundational blocker (no Pal/inventory struct decode capability exists anywhere in the codebase), the save-data edit engine is scoped first, as the foundation the world map and anti-cheat work can build on:

- **v0.6.15.0 — Save-Data Edit Engine Foundation** (shipped): extend the already-proven decode → mutate → encode → verify pipeline (`HeadlessSaveCodecService`, already powering Guild/Base Ownership repair) to individual Pal instances and player inventories within the decoded save JSON. This is composition, not a rewrite — the transactional safety pattern (safety backup, staged encode, independent re-verify decode, atomic commit) already exists and is proven; this pass extends what it can target.
- **v0.6.16.0 — Live World Map** (shipped): visualize live player positions, sourced from the existing REST player polling MystTiq already runs. Scoped to player positions only during implementation — Pal positions aren't exposed by Palworld's REST API at all, and base positions need new `Level.sav` decode work this codebase doesn't yet do; both stayed explicitly deferred rather than folded in.
- **v0.6.17.0 — Two-Way Discord Bot Control** (shipped): the "outbound dispatch already exists" premise turned out to be wrong on inspection (the Discord channel was an unimplemented stub) -- this milestone built real Discord integration in both directions: a fixed outbound embed dispatch, and a new inbound Discord bot with guild-scoped slash commands (status/players/start/stop/restart/broadcast/kick/ban), role-mapped to the caller's real Discord roles and composed directly onto the existing lifecycle/RCON/moderation services.
- **v0.6.18.0 — Anti-Cheat & Save-Integrity Scanning** (shipped): grounded in real, cited facts (SteamID64's genuine 17-digit format, Palworld 1.0's real vanilla level cap of 80) rather than the survey's uncited "level-gap thresholds" description. Three configurable rules (invalid Steam ID, impossible level, Pal stat anomaly), every one defaulting to Flag-only -- no automatic enforcement until an admin opts in. Reuses v0.6.15.0's Pal decode engine and v0.6.17.0's moderation path directly; no new game-control logic.

This closes out the full four-milestone sequence this survey scoped (v0.6.15.0 → v0.6.18.0). Tier 2 items are not scheduled into specific versions yet; they remain candidates for a future `v0.6.19.0`+ scoping pass, alongside Pal/base world-map positions (deferred from v0.6.16.0) and player inventory/save decode (deferred from v0.6.15.0, confirmed still not built as of v0.6.18.0).

Next: a fresh scoping pass for `v0.6.19.0`+, drawing from the unscheduled Tier 2 candidates and the deferred items above.
