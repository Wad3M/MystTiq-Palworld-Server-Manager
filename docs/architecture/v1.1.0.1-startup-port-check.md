# v1.1.0.1 — The start-up port check (internal)

Roadmap F-1. Reported by the owner 2026-10-13: "Something went wrong (background task)" with
`crash-20261013-081008-679.log`.

## Cause

Every desktop crash record on the owner's PC (four, 2026-10-08 to 2026-10-13, v1.0.7.0 to v1.1.0.0) is the same error: a
`SocketException` (995, operation aborted) from `TcpClient.CompleteConnectAsync`, rethrown by the finalizer as an
unobserved task exception. The only connect without a cancellation token or an awaited result was
`LocalManagementBootstrapper.PortAcceptsConnections`, run by `EnsureAvailableAsync` before it launches the helper:
`client.ConnectAsync(...).Wait(750 ms)`, then the client disposed.

On Windows a connection to a loopback port nothing listens on is refused only after about 2 s (measured on the owner's
server: 2,037 ms), because the connect is retried after the reset. So whenever the configured port was free, which is
whenever the helper had to be started, the wait ran out, the client was disposed under the pending connect, and the
connect task faulted with nothing observing it. At the next garbage collection `CrashRecorder` (from v1.0.7.0, Q-2)
caught it, wrote a record and the window showed the notice. Before v1.0.7.0 the same error happened unseen.

## Fix

`PortAcceptsConnectionsAsync(endpoint, cancellationToken)` connects with a token cancelled after 750 ms (linked to the
caller's) and awaits the attempt, so it always completes, observed, before the client is disposed. A refusal or the
time limit means free, a connection means in use, as before.

## Evidence

- ArtworkHarness: the check says a listening port is in use and a closed one free, within its limit; after it returns,
  waiting past the refusal and collecting leaves no unobserved socket error.
- The v1.1.0.0 method and the new one side by side (a standalone program, three closed-port checks each, then a wait and
  a collection): the old one left 3 unobserved socket errors, the new one none.
- Live: the owner's next desktop starts (no new crash record).
