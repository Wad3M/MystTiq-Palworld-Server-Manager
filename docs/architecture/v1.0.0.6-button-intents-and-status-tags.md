# v1.0.0.6 — Button Intents and Status Tags (internal)

Asked 2026-10-05, with screenshots of Server Setup, Workspace, Update Center, Doctor and Security: "i would like to have
consistency with all the buttons and tags. they should all be governed by the central look and not hardcoded. We also
want some colour to be in there like Delete to be red, open to be purple, verify to be green, other colours for other
buttons."

## What was there

- Buttons used five look classes (`primary`, `success`, `warning`, `danger`, `inspectAction`, `targetAction`) chosen
  page by page, so a Save could be blue on one page and green on the next. More than half of the main window's buttons (159 of 287) had no class at all. Server
  Setup switched between two looks through `Classes.inspectAction`/`Classes.targetAction` bindings. Map markers set
  their own transparent background.
- Tags were drawn by hand: Setup and Install drew three Borders per row (green, amber, red) and showed one by
  visibility; Doctor drew four badges; the Update Center coloured its text through `ComponentStatusColorConverter`;
  MOD health, network checks and diagnostics used a fixed violet or orange whatever the state.

## Button intents

`Services/ButtonIntents.cs` holds one table: an ordered list of label patterns (first match wins, case ignored), each
giving one intent. Specific phrases come first ("Apply With Fresh Safety Backup" is danger, "Choose ZIP" is apply)
before single verbs. An unmatched label is plain.

| Intent | Colour | Style |
|---|---|---|
| danger | red | `Button.danger` (DangerGlass) |
| open | purple | `Button.open` (was `targetAction`) |
| verify | green | `Button.verify` (was `success`) |
| apply | blue | `Button.apply` (was `primary`) |
| info | teal | `Button.info` (was `inspectAction`) |
| caution | amber | `Button.caution` (was `warning`) |
| plain | neutral | `Button.plain` (the default look) |

Structural classes shape a button rather than say what it does: `ribbon` (its own combinations, unchanged), `ghost`,
`sectionToggle`, `palMarker`, `marker` (map markers, transparent) and `listItem` (rows in the Map's lists, presets and
theme swatches).

Each button's XAML carries its intent as a class. The classes were written by a script that reads the table from the C#
file and the English text from `en.json`, so the two cannot disagree; the ArtworkHarness checks it again on every page.
A button whose label changes at runtime binds `services:ButtonIntent.Label` to its English label and takes the intent
from the same table (Server Setup's row action). The confirm dialog sets danger or apply in code through
`ButtonIntents.Set`. Two runtime labels have a fixed intent: the Doctor's fix button (apply) and the wizard's Next (plain).

## Status tags

`Services/StatusTags.cs` maps an English status to a kind: ok (green), warn (amber), fail (red), off (grey) or info
(blue). Exact words first (with a small list of in-between states such as "Active / Unverified" and "Connecting…"
checked before anything else), then "… failed", then the first word. A tag is one `Border.tag` with
`services:StatusTag.Status` bound to the status; a tag that only ever says one thing (Lucky, Update available, the safe
start's OK and Disabled) carries its kind as a class. The colours come from the theme's existing glass gradients and
accent borders, so the high-contrast themes apply.

Slider values on the World Settings page keep the neutral `badge` look: they are values, not states.

## Checks

- Gate: every `<Button>` in `MainWindow.axaml` and `Views/*.axaml` has an intent or structural class, none sets
  Background, Foreground or BorderBrush, and none uses an old look class; every tag is a `Border.tag` with a status
  binding or a fixed kind and no colours of its own.
- ArtworkHarness: the table's samples; every visible button on every page has one intent matching its English label;
  the same intent resolves the same background everywhere and each intent its own; Delete red, Open purple and Verify
  green by hue; tags on Server Setup, Update Center, Doctor, Diagnostics, Backups and MODs match their status; Server
  Setup's VERIFY, MANAGE and INSTALL rows; German keeps the intents.
