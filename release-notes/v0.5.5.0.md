# v0.5.5.0 — Desktop Shell UI/UX Consolidation

Desktop-only visual/UX pass closing out a round of user-driven visual feedback on the Avalonia shell. No backend, API, or platform-specific code was touched — every change is in `MainWindow.axaml`, `DesignSystem.axaml`, and view-model presentation properties.

## Navigation pill

- **Root cause of a persistent corner/outline bug found and fixed**: FluentTheme's default `ToggleButton` control template paints its own checked/pointerover background directly on an internal template part. A plain `Background` property setter on the control cannot override that state-specific template paint, so a solid `#0078D4` (Windows/Fluent default accent blue) frame was bleeding around the app's custom rounded glass pill — confirmed by direct pixel sampling of a rendered screenshot, not guesswork. Fixed by replacing `ToggleButton.nav`'s template with a bare `ContentPresenter`, so the only visuals are the ones the app draws itself via the child `Border.navSurface`.
- Nav items are taller (58px, was 42px) and the sidebar column is wider (260px, was 220px).
- The pill was being centered at its natural text height inside the 58px row (via `VerticalContentAlignment="Center"`), leaving visible dead space above and below instead of filling the row. Fixed with `VerticalContentAlignment="Stretch"` on the button plus an explicit `VerticalAlignment="Center"` on the label text so it still centers correctly within the now-full-height pill.
- Hovering an already-selected (checked) nav item previously showed **zero visible change** — the `:checked` selector's `Background` setter was winning over `:pointerover`'s regardless of mouse position, since both matched with equal cascade specificity and `:checked` was declared later. Added a `ToggleButton.nav:checked:pointerover` selector (naturally higher-specificity, so it wins regardless of declaration order) with a dedicated lightened gradient, so hovering a selected item now visibly brightens.
- Selected/hover glow switched from `BoxShadow` to `DropShadowEffect`. `BoxShadow` on an Avalonia `Border` was painting a hard rectangular block past the rounded `CornerRadius` silhouette at the corners (confirmed by extreme-zoom pixel inspection); `DropShadowEffect` blurs the actual rendered (and correctly clipped) shape, so it follows the rounded pill cleanly.
- Border thickness doubled (1px → 2px) at the user's request.

## Dashboard

- SERVER card is now a clean three-state traffic light: **red** when not running (stopped, crashed, unknown — any non-running state), **amber** while transitioning (starting/stopping/restarting), **green** while running. This replaces a fourth "neutral" grey state that previously made a stopped server look calm/idle rather than stopped, which is what the user explicitly asked to change.
- OVERALL HEALTH's state label ("READY"/"ATTENTION"/etc.) previously had a **hardcoded green** `Foreground`, so it stayed green even when the card itself had gone red for an ATTENTION state — a visible color mismatch. Now driven by a new `HealthStateColor` view-model property that tracks the same red/amber/green/neutral state as the card's own glow.

## Shared page header

- Every page previously repeated its own large bold "page name" heading in the main content area, duplicating what the nav sidebar already showed. Consolidated: the shared title/subtitle card (in the previously-empty right-hand space of the category-tab row + ribbon) now shows `PageTitle`/`PageSubtitle` for every page, widened to fit, and also carries the Auto refresh checkbox and Connected badge (previously duplicated separately in the main content area on every page).
- Removed the resulting redundant per-page banner from **18 pages**: Server Setup, Update Center, World Explorer (Inspector), Bases, Guilds, Configuration, Console, Activity & Audit, Backup Center, MOD Dashboard, MOD Library, UE4SS, Diagnostics Center, Server Doctor ("Production Doctor"), Workspace, Crash Analyzer, Save Tools, Notifications. Each page's own descriptive/dynamic body text (e.g. "Install, verify, and maintain the components required to run your Palworld dedicated server.") was kept — only the duplicated identity heading was removed.
- Removed a now-stale `ShowGlobalPageHeader` exception that had specifically hidden the shared header for Server Setup (a leftover from when Server Setup had its own separate banner, which no longer exists) — the shared header now applies uniformly to every page.
- This also frees meaningful vertical space on every page, which incidentally helps toward fitting full-screen without scrolling — confirmed the Dashboard page already fits cleanly at true 1920×1080 with room to spare after this change.

## Verification

- Full logic-test suite passes: **288/288 checks**, including 8 new checks added this release covering the template fix, full-height pill, checked+hover highlight, DropShadowEffect-not-BoxShadow, the traffic-light SERVER card, `HealthStateColor`, and the shared-header consolidation (2 checks). Also fixed 5 pre-existing checks that referenced literal banner text removed by the consolidation.
- Visually verified via direct screenshots at each step (nav corner fix, hover brightening, traffic-light colors, health text color, header consolidation, full-height pill) using a second monitor at native 1920×1080/no-scaling resolution, after an earlier attempt on the primary monitor was corrupted by its 125% DPI scaling (GetWindowRect/SetWindowPos/screen-capture coordinates disagreeing) — documented so the same trap isn't repeated.
- **No headless/API/platform-specific code was touched this release**, so the usual Linux runtime-verification pass (deploying to and exercising the reference Linux VM) does not apply the same way it does for backend features. Verified by a clean Windows/Linux desktop and headless build only. Avalonia XAML styling is cross-platform by construction and none of these changes are platform-conditional.
