# MystTiq v0.7.67.0 — Tray Reminder Toast: Layout Timing Fix

## Highlights

- **Completes v0.7.66.0's tray toast positioning fix**, found by actually testing it on the real
  reported hardware (the user asked to "try it out on the real hardware," and this machine turned
  out to be that exact hardware — same multi-monitor layout). v0.7.66.0 fixed *which monitor* the
  toast resolves to; this release fixes a second, independent bug in *where on that monitor* it
  lands: `PositionBottomRight()` read `Bounds` at the moment the window first opened, before
  `SizeToContent` had actually measured the toast's real small content size — `Bounds` was already
  non-zero at that point (so the existing `> 0` fallback guard didn't catch it), just wrong (a
  placeholder ~1521×770, roughly the size of an unconstrained default window), corrupting the
  bottom-right math on both axes.
- Fix: also reposition on `LayoutUpdated` (not just `Opened`), so the toast corrects itself once
  layout actually settles on the real content size.
- **Verified with an exact pixel match on the real hardware**: a standalone test harness drove the
  real `TrayReminderToast` class with a stand-in window placed on the actual secondary monitor,
  confirming the toast now lands at precisely `(1972, -127)` — the mathematically exact bottom-right
  corner of that monitor's working area — converging there through several `LayoutUpdated`
  corrections as the true size settled.

## Upgrade notes

- No configuration changes, Desktop-only.
- This is the first Desktop/GUI fix this project has verified with a real, exact, on-hardware
  measurement rather than static reasoning or a disclosed "not verified visually" gap — see the
  architecture doc for the full before/after data.
