# v1.1.0.3 — Player IDs: Clean-up After a Move

**A character move now leaves nothing behind.**
- After a move is checked, the old character file is removed instead of being kept in an archive folder. The safety
  backup taken before the move holds it (and the empty character it replaced), so it can still be restored from the
  Backups page.
- Character files the previous version kept in its archive folder are removed when MystTiq starts, but only when one of
  its backups holds that character.
- MystTiq's player list is tidied: a moved player's history (sessions, play time, first seen) follows them to their new
  ID, old entries that no longer name a character are folded into the player's current entry, and a player who joins
  before their character exists is no longer listed under a shared "None" entry.

Nothing in the world file needed cleaning: the empty characters' storage was never kept by the game.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.1.0.2

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the [v1.1.0.2](v1.1.0.2.md) and [v1.1.0.0](v1.1.0.0.md) notes.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
