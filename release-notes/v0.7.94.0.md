# v0.7.94.0 — Starter Kits

Third and last of the "real gaps" from the competitive feature review.

- New collapsed **Starter Kits** card on the Players page: build named loadouts (items and Pals, one
  entry per line, e.g. `item PalSphere 10`, `pal WeaselDragon 5`), give one to a selected online player,
  or turn on **auto-gift** for new players.
- **Delivery needs PalDefender.** Vanilla Palworld has no give command (why Give Item is disabled).
  Kits use PalDefender's `giveitems`/`givepal` over RCON. The card shows the real provider status, says
  plainly when delivery is impossible, and has a **Test PalDefender** button that shows the server's raw
  reply. Your Default Server has PalDefender detected; new installs do not.
- **Auto-gift is deliberately conservative:** only players MystTiq first sees *after* you switch it on
  are gifted, once each. Turning it on never mass-gifts everyone who already plays. ("First seen by
  MystTiq", not "new to the server", and the card says so.) Failed deliveries are retried at most 3
  times and never recorded as claimed; **Reset Player's Claims** allows a retry.
- Ids are validated strictly (letters, digits, underscore), which also keeps anything unexpected out of
  RCON commands. A server reply that reads as an error counts as a failed delivery.

Not verified: PalDefender's live reply (needs your server running with a player online). The Test button
and error detection are there so a mismatch is a clear message, not silent non-delivery.

Touches `MystTiq.Core`, `MystTiq.HeadlessHost` and `MystTiq.Desktop`. See
[`docs/architecture/v0.7.94.0-starter-kits.md`](../docs/architecture/v0.7.94.0-starter-kits.md).
