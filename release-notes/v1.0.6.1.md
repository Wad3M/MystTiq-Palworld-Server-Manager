# v1.0.6.1 — Your Character, Not a New One

## What happened

On 2026-10-06 a player joining from another computer with his own Steam account was given a new character instead of
his own (shown as "Unknown Player"). Started by hand, the same server gave him his own. Two things together caused it:

- **An older MystTiq service was still running the server.** The desktop app connects to whatever service answers on
  this PC. A v1.0.6.0 desktop was driving a v1.0.0.0 service started the day before, so nothing since v1.0.0.0 was in
  effect for the server. That includes the identity guard, which would have caught this and stopped the new character.
- **The server started with the options that change players' IDs.** Every start that gave players the wrong character
  had `-log`, `-stdout` or `-FullStdOutLogOutput`; starts like a double-click, without them, kept their characters.
  MystTiq's Launcher presets other than **Like double-click** were still switching them on. Worse, the Launcher page
  showed them switched on for a server with no saved launch settings, so saving that page wrote them in.

## Fixed

- **An older service is flagged.** When the MystTiq service on this PC is older than the app, the Dashboard says so,
  in red. **Update Service To This Version** stops the older service and starts the app's own. A running PalServer keeps
  running, and players stay connected.
- **No preset adds those options any more**, and a server with no saved launch settings shows them off (as it really
  starts), so saving the page cannot add them. The Launcher warns when `-log`, `-stdout`, `-FullStdOutLogOutput` or
  `-abslog` are on, and points to **Like double-click**.
- **The identity alert names the options** the server was started with and says what to do: choose Like double-click,
  save, restart, and have the player join again. As before, it kicks the player before a new character is made, when
  their real one exists.

## If this happened to you

1. Install v1.0.6.1. If the Dashboard shows the red message, click **Update Service To This Version**.
2. On **Server > Launcher**, click **Like double-click**, then **Save Launcher Settings**.
3. Restart the server and join again. Your character was never touched: it is still in the save under your Steam ID.
   The new one ("Unknown Player") can be left alone or removed later.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.6.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
