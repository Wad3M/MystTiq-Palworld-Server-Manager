# MystTiq Palworld Server Manager v0.3.0.3

## Headless Configuration & Local Management API Foundation

v0.3.0.3 introduces persistent headless configuration and the first local management API.

### Configuration

Default Linux configuration:

```text
/etc/mysttiq/mysttiq.json
```

Commands:

```bash
./mysttiq-server config-show
./mysttiq-server config-validate
sudo ./mysttiq-server config-write-default
```

The schema owns server paths, PalServer launch arguments, lifecycle timeouts, service polling, recovery policy, and local API settings.

### Local API

Default endpoint:

```text
http://127.0.0.1:8213
```

Endpoints:

```text
GET  /healthz
GET  /api/v1/status
GET  /api/v1/service
GET  /api/v1/config
POST /api/v1/server/start
POST /api/v1/server/stop
POST /api/v1/server/restart
```

The configuration validator rejects non-loopback API binding in this version. LAN/public exposure and authentication are intentionally deferred until a dedicated security phase.

Lifecycle-changing requests are serialized so simultaneous control requests cannot race.

### systemd integration

`service-run` starts the API alongside the Linux supervisor when enabled.

`service-install` creates the default configuration if needed and writes the selected config path into systemd `ExecStart`, preserving custom configuration across service restarts and reboot.

### Reference environment

- Ubuntu Server 24.04.4 LTS
- x86_64 / amd64
- kernel 6.8.0-137-generic
- systemd
- service user `mystroth`
- Palworld App 2394010 / Linux depot 2394012
- UDP 8211 PalServer readiness
- local MystTiq API port 8213

Windows WPF behavior remains unchanged.
