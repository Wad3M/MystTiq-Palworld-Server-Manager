# MystTiq v0.7.73.0 — Tray Icon Honestly Reflects Running State

## Highlights

- **Fixed a real gap directly reported live**: the user found two PalServer processes running with
  no MystTiq tray icon visible anywhere, and expected "no tray icon" to reliably mean "nothing is
  running." Investigated auto-start thoroughly first — no Windows Startup entry, `Run` key,
  scheduled task, service, or automation rule anywhere; tab-session restore only reconnects/polls,
  never starts. The real cause: the tray menu's **"Exit GUI Only — keep services running"** item
  always fully quit the app (taking the tray icon with it) even while deliberately leaving
  PalServer running in the background — the one exit path specifically built to leave things
  running with no visible trace.
- **Fix, per direct confirmation**: `Exit GUI Only` now checks whether anything is running first
  (the same check the window's own close button already uses) — if so, it collapses to the same
  minimize-to-tray behavior instead of exiting, so the tray icon stays up as an honest signal. Only
  a genuinely idle app still fully exits with no tray.
- **Tray tooltip now says what's actually running**, refreshed every 5 seconds — "idle, nothing
  running" / "running: Default Server" / "2 servers running: Default Server, second-local" — instead
  of a static, state-blind string.
- **Confirmed, not changed**: headless log capture already ran entirely inside the separate
  `mysttiq-server.exe` process, independent of whether the Desktop GUI is attached — `Exit GUI Only`
  never stopped it even before this fix. This version makes that already-true guarantee visible via
  the tray, rather than needing to add it.

## Upgrade notes

- No configuration changes. `MystTiq.Desktop`-only.
- No live GUI click-testing was possible in this environment — verified by code review and a clean
  build; still owed a live click-through.
