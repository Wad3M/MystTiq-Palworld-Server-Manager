# MystTiq v0.7.75.0 — Delete Player Completely / Copy Player

## Highlights

- **New: Delete Player Completely.** Permanently deletes a player's save file, then — as a
  separate follow-up operation — cleans up their now-dangling guild membership reference (reusing
  the already-proven Remove Broken Member operation) and clears their registry history. Follows the
  same Preview → Safety Backup → Apply discipline every other destructive operation in this app
  uses.
- **New: Copy Player.** Clones a player's inventory, unlocked recipes, records, skins, and quest
  progress onto another player's own save, while the destination keeps its own identity (player
  UID, platform, session history, position, and pal-party/storage references all stay the
  destination's own). Character level/stats and pal-party contents themselves are deliberately not
  included in this version — disclosed, not silently dropped.
- **A real bug found and fixed during live testing**: the deletion's guild-cleanup follow-up
  initially failed with a lock conflict — `OperationCoordinator.Complete()` doesn't release the
  operation's resource lock, only `Dispose()` does, and the follow-up call ran before that
  disposal. Fixed and re-verified: after the fix, both the file deletion and the guild-reference
  cleanup were independently confirmed correct by decoding the raw save a second, separate way,
  outside the app entirely.
- **Root-caused the original "right-click looks broken" report**: Kick/Ban were always correctly
  wired — they were just correctly disabled (no online player / no server running) with zero
  visible disabled styling anywhere in this app's context menus. Added a real `MenuItem:disabled`
  style.

## Desktop UI

Players page's right-click menu gains "Copy Player Data From…" (a populated player-picker dropdown,
not a hand-typed ID) and "Delete Player Completely…", both showing the real server-reported preview
findings before asking for confirmation.

## Deferred, not forgotten

Base/Guild right-click convenience (jump to the existing, already-working transfer/wipe cards;
populated target dropdowns instead of hand-typed IDs) was requested in the same conversation and is
real, valuable, and scoped — just deferred to its own follow-up version rather than rushed in here,
since the underlying capability already fully works today via the existing cards.
