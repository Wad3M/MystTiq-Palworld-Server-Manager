# v0.2.15.7 FIX2 — Current-session Runtime Reacquisition

## Trigger
Runtime testing of FIX1 showed all MOD Library rows remaining **Not Loaded**, MOD Dashboard reporting **Runtime Unverified**, and the MOD Information **REFRESH INFO** control launching an online search for some selections.

## Root cause
`RuntimeStateService` captured only a byte offset for one UE4SS log. If UE4SS replaced that log during startup and the replacement had already grown beyond the old offset before the first MystTiq observation, startup `Starting Lua mod` evidence was skipped. Depending on a single selected log also made the unified source vulnerable to log rotation/path changes.

## Correction
- Track per-log creation identity plus byte cursor.
- Baseline all discovered UE4SS logs before server start.
- Read replacement/new current-session logs from byte zero.
- Observe all current-session `UE4SS*.log` candidates.
- Feed positive shared evidence into stale Dashboard runtime rows.
- Separate REFRESH INFO from SEARCH ONLINE.

## Safety
The runtime service remains read-only. It does not enable, disable, move, delete, or rewrite MOD files. Historical pre-session bytes are excluded from current-session load proof.
