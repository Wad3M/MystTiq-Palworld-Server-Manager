# v1.0.7.4 — Secrets and Archives

Roadmap items Q-14, Q-15 and Q-9 from the outside quality review.

## Secrets are encrypted on disk

- **What:** the SMTP password, the Discord and webhook URLs (each carries its own token), and the Discord bot token.
- **Windows:** encrypted with Windows data protection for this computer. A copy of the settings files taken to another
  computer cannot be read there.
- **Linux:** the files are readable by their owner only.
- **Moving over:** the first time the new service starts, it encrypts the plain settings and keeps one plain copy beside
  each file (`.before-encryption`). It adds a Notifications entry when it does.
- **Deleting the plain copy:** Server Doctor lists any plain copy under Security. Send a test notification first; once it
  arrives, **Delete Plain Copy** removes the copy. It needs the Admin role.

Sign-in tokens were already safe: the desktop keeps yours encrypted for your Windows account, and the service stores
only a fingerprint of each one.

## Every archive is checked before it is opened

- **What was checked before:** only world imports had limits on size and number of files.
- **What is checked now:** MOD installs, MOD and UE4SS snapshot restores, the UE4SS download, backup restores and
  MystTiq's own update.
- **The limits:** 20,000 files, 8 GiB expanded, and enough free disk space (with 256 MB to spare).
- An archive over a limit is refused with the reason, before anything is written.

## Secrets stay out of logs

- A failed Discord or webhook send is logged by its address only (for example `https://discord.com/****`), not by the
  full URL with its token.
- Start arguments that look like passwords or tokens (`-AdminPassword=…`, `--token …`) are hidden in the console log, its
  exports, and the identity guard's advice.
- The notification channel settings can only be read with the Admin role (like the Discord bot's). The SMTP password is
  never sent back: saving the settings without one keeps the stored password.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.7.3

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. If the Dashboard says the local service is older, click **Update Service To This Version**: the encryption runs in the service. Afterwards, send a test notification, then delete the plain copy from Server Doctor. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
