# MystTiq v0.7.14.0 — Accessibility & Interaction Feedback Pass

## Highlights

- **Screen readers can now identify every icon-only button.** Window controls, tab-close, add-tab, and the ribbon's Start/Stop/Restart/Refresh/Backup/Console/Doctor buttons previously had a mouse-only tooltip and nothing else — a screen reader user got silence. All 16 genuinely icon-only controls now have an explicit accessible name.
- **Tabbing through the app shows a focus ring again** on window-chrome buttons, the tab-close button, and the 7 category tabs — a styling quirk was silently swallowing the app's own focus-visible ring on exactly those controls.
- **The per-tab close button is easier to hit** (20px → 28px), and Minimize/Maximize/Close now show tooltips like every other icon-only control in the app.

## Upgrade notes

- This is the first release to directly audit the app against Fluent/Avalonia UI best practices (earlier passes covered page ordering, card visuals, and density separately).
- One audit finding — missing busy-state feedback on several destructive buttons — was investigated and found to already be handled correctly (via each command's own precondition, not a separate XAML binding), so nothing changed there. Full reasoning in `CHANGELOG.md`.
- No configuration schema change, no server-side change — this release is Desktop-only.
