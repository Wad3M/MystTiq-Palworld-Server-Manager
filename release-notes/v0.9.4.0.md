# v0.9.4.0 — Roles Explained, and Accessibility

- **A disabled button says why:** when you are signed in with a role that cannot use something (a Viewer on Kick, an
  Operator on Save settings), the button or menu item now tells you which role it needs and which role you have, in
  its tooltip, even while it is greyed out, and to screen readers. Its own tooltip follows. Sign in with a role that
  may use it and the hint goes away. Local use (no sign-in) is never blocked, as before.
- **Every control has a name:** lists, text boxes, drop-downs, number boxes, sliders and check boxes throughout the app
  now have names a screen reader can say (about 150 were added), in every language, and every enabled control can be
  reached with Tab.
- **More in your language:** the health states (STOPPED, DEGRADED, STARTING…) and values inside labels, such as the
  MOD health on the Dashboard ("Health: Healthy"), now follow the language too.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v0.9.3.0

Back up your server data and configuration, then extract into a new application folder. Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert.

## Known limitations

This is a development version, not v1.0. The names and keyboard reach are checked automatically on every page; a pass with a real screen reader, and checks of scaling and focus order by people, are still to do. The 11 translations are drafts awaiting native review. On Linux, file pickers and installed-service priority recovery still need acceptance. Actual give-item/Pal delivery, live map/teleport calibration and real Discord/email delivery need the live scripts to be run with a player and real channels. See the [roadmap](https://github.com/Wad3M/MystTiq-Palworld-Server-Manager/blob/main/docs/roadmap/PRODUCT_ROADMAP.md).

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server.
