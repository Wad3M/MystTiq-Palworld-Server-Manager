# v1.1.2.0 — Why It Stopped, and Start with Windows

## Why a server stopped

Every stop now records who or what asked for it, and the Dashboard shows it while the server is stopped: **Last stop:
MystTiq closed with Exit · 2026-10-19 21:05**. The reasons:

- In MystTiq: **Stop**, **Force Stop** and **Restart** (the buttons or the tray menu), **Stop & Close** on a server tab,
  and **Exit** or **Force Exit** from the tray.
- **Discord** (`/mysttiq-stop` and `/mysttiq-restart`, with the Discord user), an **automation rule** (by name),
  **MOD Safe Start**, a **character move** (a player's ID changed), a **frozen-server restart**, the **command line**,
  and the **MystTiq service stopping** (Windows shutting down, or the service stopped).
- Anything else using the API says so, with the account that asked. A program can add its own reason with `?reason=`
  on `POST /api/v1/server/stop`, `/force-stop` or `/restart`.

Each stop is also written to the activity log (**Server stopped: <reason>**). The status API returns `lastStopReason`
and `lastStopAt` for a stopped server. A crash shows as a crash, never as a stop.

## Start with Windows

**Settings > Appearance** has a new option, **Start MystTiq when I sign in (opens in the tray)**. It is off until you
turn it on. With it on, MystTiq starts when you sign in, in the tray, and starts its helper as usual; a server that was
running when the computer shut down starts again, and one you stopped stays stopped. On Linux it adds an autostart entry
for your desktop session.

When Windows shuts down or restarts, MystTiq no longer holds it up by hiding to the tray: it asks each running server to
save its world and lets Windows continue.

## Also fixed

- The Linux VM checks could wait forever on an `ssh` whose remote command had finished (the v1.1.1.3 release checks waited
  eight hours). Every non-interactive `ssh` call in the scripts now passes `-n`.

## Upgrading from v1.1.1.3

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder. Nothing to convert: a stop recorded before this version shows no reason. If you turn on **Start MystTiq when I sign in** and later move MystTiq to another folder, Settings says the entry points at the old copy; turn it off and on again. Coming from an older version, also read the [v1.1.1.3](v1.1.1.3.md), [v1.1.1.0](v1.1.1.0.md) and [v1.1.0.0](v1.1.0.0.md) notes.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
