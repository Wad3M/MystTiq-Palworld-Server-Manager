# MystTiq v0.7.64.0 — Roadmap-Wide Gap Audit and Fixes

## Highlights

- **Cataloged ~75 open items across the whole project's own disclosed history** (release notes,
  architecture docs, the roadmap files, and source TODO/stub markers) at the user's direct request to
  keep going past v0.7.63.0's theme-system fix. Most are honestly-scoped future work with no defect
  behind them — this release fixes the handful that were genuine, concrete, already-shipped-code
  bugs.
- **Automation rules now actually validate their own input.** Creating or updating a rule with e.g.
  `idleThresholdMinutes: -5` used to return HTTP 200 and store the negative value verbatim, even
  though the scheduler silently reinterprets it (clamped to 1) rather than honoring it. Now rejected
  with a clear `400` at the API boundary — for `IdleThresholdMinutes`, `JitterSeconds`, `Interval`,
  and `WarningCountdownSecondsBeforeAction`.
- **`MystTiq-PalServer-Console.log` now rotates** instead of growing forever — both writers that
  append to it (MystTiq's own structured lines, and the raw PalServer stdout/stderr capture) now cap
  it at 25 MB, keeping one prior generation.
- **Three stale "not built yet" messages fixed**: Base ownership/recovery repair (shipped
  v0.5.3.0/v0.5.4.0) was still marked "BACKEND REQUIRED" on the World Transactions page; the Server
  Setup checklist's UE4SS row still claimed no install path existed (v0.7.49.0 shipped a real one,
  reachable from the MOD Dashboard/UE4SS page — this row's own navigation was already wired and
  waiting, just gated off); the same checklist's Backup Storage row claimed no automated fix existed
  (Doctor's Fix Automatically has done this since v0.6.4.0).

## Upgrade notes

- No configuration or schema changes. `MystTiq.Core`/`MystTiq.HeadlessHost`/`MystTiq.Desktop` all
  touched; no wire-contract breaking changes — existing valid automation rules are unaffected, only
  previously-silently-misleading invalid input is now rejected up front.
- One real, newly-surfaced (not newly-introduced) gap noted while investigating log rotation:
  `LinuxServerLifecycleService` has no PalServer stdout/stderr console-capture at all, unlike its
  Windows counterpart. Not fixed this pass — flagged for a future session.
- Verified live against the real running sidecar this time (not just static/contract checks) — see
  `scripts\Test-v0.7.64.0-RouteSmoke.ps1`.
