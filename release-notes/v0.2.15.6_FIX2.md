# v0.2.15.6 FIX2 — Runtime-loaded Session Persistence

## Problem
The MOD Library could initially show UE4SS mods as Loaded, then revert all UE4SS rows to Not loaded roughly a minute later. Verification still reported the mods as Loaded because it searched multiple recent logs.

## Root cause
The library scanner treated the newest UE4SS log as authoritative on every refresh. After UE4SS rotated/replaced its startup log, the newest file could omit earlier `Starting Lua mod` evidence. Absence from that later log was incorrectly treated as evidence that the mod was not loaded.

## Fix
MystTiq now treats positive runtime-loaded evidence as a session fact. Once a UE4SS mod is positively observed as loaded during the current PalServer session, the MOD Library retains Loaded through later refreshes/log rotation. The session evidence cache is cleared on server exit and before a new server session.

## Runtime validation
1. Start PalServer normally with enabled UE4SS mods.
2. Wait until MOD Library shows Loaded.
3. Leave the server running for at least 2–3 minutes and refresh the MOD Library several times.
4. Loaded rows must remain Loaded.
5. Stop PalServer: session evidence must clear.
6. Start a new session and confirm load state is reacquired from current-session evidence.
