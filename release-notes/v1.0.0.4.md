# v1.0.0.4 — Restores You Can Check by the Day

## Backups and restore

- **Restores tell you the world's day.** After a restore MystTiq reads the restored world and says, for example, "The world
  is now Day 211 18:48, as in the backup."
- **Every backup shows its world day** in the Backups list, so you can pick the one you want by day.
- **The Dashboard's day is current again.** It used to come from a copy MystTiq refreshed only after its own world edits,
  so it could be days behind. Now it is read again whenever the world has been saved. Until that read finishes, the
  Dashboard says it is showing an older save.
- **Restores were failing because Windows wouldn't let MystTiq replace the save folder.** On some servers the save
  folder belongs to administrators (something that once ran as administrator created it), while MystTiq runs as you.
  The Backups page now says so, and **Fix Save Folder Access** gives your Windows account change rights on the server's
  `Pal\Saved` folder. Windows asks you first. Until then the Dashboard's day still works.
- **A restore no longer fails just because a file is briefly in use**, for example right after the server stops. It waits
  a few seconds. If something keeps a save file open, it names the program, and nothing is changed.
- A restore is refused while PalServer is running from the server's folder, even when it was started outside MystTiq.
- Every restore, refused, failed or done, is in the activity log.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.0.3

Back up your server data and configuration, then extract into a new application folder. Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert: the backups' days are read in the background the first time the Backups list opens. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
