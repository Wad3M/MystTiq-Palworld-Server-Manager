# MystTiq v0.7.71.0 — Console Source: PalDefender Log

## Highlights

- **Real, previously-missing console source found and fixed**, following on directly from a
  screenshot the user provided of a visible Windows Terminal console window showing PalDefender
  Anti-Cheat startup diagnostics that never appeared in MystTiq's own Console page. Checked live
  against the real production install rather than assuming: PalDefender (a UE4SS-loaded
  anti-cheat mod) writes its own timestamped per-session log file at
  `Pal\Binaries\Win64\PalDefender\Logs\{timestamp}.log`, containing exactly the screenshot's
  content — startup banner, REST API port, load confirmation, and even PalServer's own "Running
  Palworld dedicated server on :PORT" line. `HeadlessMonitoringService.ResolveConsoleSources`
  never looked for it.
- Fix: added as a new merged console source, `"PalDefender log"`, using the same
  newest-file-in-directory pattern already used for AdminCommands' own per-session logs.
- Verified live against both the real production (`default`) and clone (`second-local`) server
  profiles on this machine — confirmed via `/logs/tail` that PalDefender's real startup content
  now appears for both.

## Disclosed, unchanged scope

- This does not add *ongoing*/live console capture — PalDefender's log, like every other source
  read here, only ever carries that session's startup banner and then goes silent. Genuine live
  capture still needs the native DLL-proxy hook scoped (and deliberately not implemented, due to
  low disclosed payoff) in v0.7.57.0.

## Upgrade notes

- No configuration changes. `MystTiq.HeadlessHost`-only.
