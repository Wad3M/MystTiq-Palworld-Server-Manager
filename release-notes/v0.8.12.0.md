# v0.8.12.0 — Second-NAT Check, and UPnP That Works

- **The reachability check now looks for a second NAT.** Forwarding the game port on your router only helps if your
  router holds your internet address. The check now spots the two cases where it doesn't:
  - **carrier-grade NAT**: your ISP shares one address among many customers;
  - **double NAT**: your router sits behind another router.

  It tells you what to do in each case.
- **On your network: no second NAT.** Your router (an Arcadyan) holds the public address the internet sees, so
  forwarding the game port on that router is enough. It currently has no UPnP mapping for UDP 8211. A forward you set up
  by hand in the router's admin page won't show there.
- **Correction.** Before this release I told you your network looked like double NAT. That was wrong: the extra private
  step on the route out is your ISP's own equipment. The check no longer treats that as a warning; it says it can't
  tell and how to find out.
- **UPnP now works where it didn't.**
  - **On this server:** it never found your router, because of the extra network adapter the Linux VM uses.
  - **On Linux:** every UPnP request failed there.

  Both are fixed. On this server, the check now reads the router's mappings and address.
- **Honest about the limit.** No check can send a real game packet from outside. The page says so, and suggests asking
  a friend outside your network to join. Port-checker websites mostly test TCP, and Palworld uses UDP.
- Checked on Windows and on the Linux VM, which also re-checked v0.8.9.0's crash reports and v0.8.11.0's Pal positions
  on Linux.
