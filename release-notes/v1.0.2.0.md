# v1.0.2.0 — Unattended Reliability

## A frozen server is restarted

Until now MystTiq restarted a server whose process had gone. A server that was still running but had stopped answering,
frozen, kept its game port open and looked fine.

- MystTiq now asks each running server's REST API, about every 30 seconds, whether it still answers. A server that has
  answered and then stays silent for **3 minutes** is restarted, and you get an alert ("server stopped responding,
  restarting") followed by the usual "server is back up".
- A healthy server is never restarted. Nothing happens while the REST API is switched off, before the server has
  answered once, or while it is still starting.
- The restart counts toward the same limit as crash restarts. If that limit is used up, MystTiq tells you once and leaves
  the server alone.
- The restart is in the Activity log ("Frozen server restarted").
- The time can be changed in `mysttiq.json` (`lifecycle.unresponsiveRestartSeconds`: 0 switches it off; otherwise at
  least 60).

## Proof that alerts arrive

- Every message MystTiq sends to Discord, email or a webhook is now recorded with its result: delivered (with the
  server's answer) or failed (with the reason).
- **Alert Center > Delivery** shows each channel as **Delivered**, **Failing** (its last send failed) or **Not proven**
  (nothing delivered in the last 7 days), with the latest sends.
- The **Dashboard** warns when a switched-on channel is failing or not proven. **Send test notification** (Alert Center)
  shows the result there a few seconds later.

## The Linux service under systemd

The Linux service already runs without a desktop, starts at boot, restarts on failure and stops cleanly through its
systemd unit. This version adds a test for the Linux test machine that proves each of those on a separate test unit,
leaving the real one untouched.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.1.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
