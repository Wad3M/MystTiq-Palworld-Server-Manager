# v0.7.91.0 — Crash-Risk Configuration Detection

Follow-up to a competitive feature review against other Palworld server managers: Doctor now flags
`BuildObjectDeteriorationDamageRate = 0` — a community-reported cause of long-running server
instability (disables cleanup of decayed base structures, letting entity counts grow unbounded).
Two of MystTiq's own bundled QoL presets set this value to exactly 0, so this closes a real,
self-inflicted gap rather than a hypothetical one.

Scoped narrowly to this one well-evidenced, non-default setting. `bEnableInvaderEnemy` (also
sometimes cited as a crash contributor) was deliberately left out — it defaults to enabled in
vanilla Palworld and the risk is player/base-count-dependent, not universal, so flagging it
unconditionally would produce false positives on ordinary servers.

No Desktop UI changes needed — the finding appears automatically in the existing Doctor page's
findings list.

Touches `MystTiq.HeadlessHost` only.

See [`docs/architecture/v0.7.91.0-crash-risk-config-detection.md`](../docs/architecture/v0.7.91.0-crash-risk-config-detection.md)
for implementation detail.
