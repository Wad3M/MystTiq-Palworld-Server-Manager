# MystTiq v0.7.74.0 — Close-Dialog Exit Shortcuts & Tab-Restore Exception Isolation

## Highlights

- **Close-confirm dialog now offers Safe Exit / Force Exit directly**, not just Cancel/Minimize to
  Tray — previously it just told you to go find the tray icon afterward if you actually wanted to
  stop the server, an extra round-trip. Both new buttons run through the exact same shutdown logic
  the tray menu already uses (`App.SafeExitAsync()`/`ForceExitAsync()`, now shared rather than
  duplicated).
- **Fixed a real tab-restore bug, reported live**: only 1 of 3 saved tabs reopened after a relaunch.
  Confirmed the saved data itself was intact (all 3 profile IDs present in `open-tabs.json`, all 3
  matching profiles present in `connections.json`) — the bug was that the startup sequence ran local
  dashboard initialization and tab restoration as one unguarded continuation; an exception in the
  first step silently aborted the second before it ever ran. Each phase now runs in its own
  try/catch.
- **Checked, not re-fixed**: a separately reported per-tab color bug (switching tabs left the chrome
  tinted like the previous tab). Traced it to already being fixed by other work already present in
  the source tree since this project's last checkpoint — not something this version needed to add.

## Upgrade notes

- No configuration changes. `MystTiq.Desktop`-only.
