# MystTiq Palworld Server Manager v0.3.0.6 FIX4

## Running-Binary Service Install Hotfix

Remote-enrollment acceptance reached the service-install stage and then Linux rejected the old install behavior with:

```text
System.IO.IOException: Text file busy : '/opt/mysttiq/bin/mysttiq-server'
```

The running systemd service was executing that path while `service-install` attempted to overwrite it in place.

FIX4 replaces in-place overwrite with a Linux-safe staged replacement:

1. copy the new executable to a unique temporary file inside `/opt/mysttiq/bin`
2. apply executable permissions to the staged file
3. atomically rename the staged file over `/opt/mysttiq/bin/mysttiq-server`
4. allow the currently running process to continue on its old inode
5. let the existing systemd restart step launch the newly replaced executable

This avoids `ETXTBSY` / `Text file busy` without forcing an unsafe kill or temporarily removing the installed executable path.

No API, TLS, authentication, configuration schema, PalServer lifecycle policy, or Windows WPF behavior changed.
