# MystTiq v0.7.68.0 — Graceful Shutdown: RCON-First Fix

## Highlights

- **Diagnosed and fixed a real, previously-flagged-but-never-chased-down bug**: graceful shutdown
  had been observed falling back to forced termination on effectively every real stop
  (v0.6.10.0's own session notes: "4/4 occurrences"), never explained. Root cause found this
  session: `Process.CloseMainWindow()` silently does nothing once MystTiq's own headless-mode
  window-hiding policy (`ApplyPostLaunchWindowPolicyAsync`, running for 30+ seconds after every
  launch) has hidden PalServer's window — `.NET`'s `Process.MainWindowHandle` only resolves a
  handle for a *visible* window, so MystTiq's own "stay headless" feature was silently defeating
  its own graceful-shutdown feature.
- Fix: both `WindowsServerLifecycleService.StopAsync` and `LinuxServerLifecycleService.StopAsync`
  now try Palworld's native RCON `Shutdown` command first (when RCON is configured) — the game's
  own real graceful-exit path, with no dependency on window visibility or process signals. Purely
  additive: the existing `CloseMainWindow`/force-kill (Windows) and `SIGTERM`/`SIGKILL` (Linux)
  chain still runs completely unchanged if RCON isn't configured or doesn't result in a clean exit.
- Verified with a real Source RCON protocol stub server proving the exact command text is sent and
  the response correctly parsed — not just that the code compiles.

## Upgrade notes

- No configuration changes. If RCON is already enabled with a password configured, stops should now
  more often be genuinely graceful (world saved, clean exit) instead of always escalating to a
  forced kill after the full timeout.
- **Not verified end-to-end against a real PalServer** — the RCON wire protocol itself is proven
  live; confirming a real, running Palworld dedicated server accepts and acts on this exact command
  needs a disposable live server with RCON enabled, which this session didn't have without risking
  the production instance.
