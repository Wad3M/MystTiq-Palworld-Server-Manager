# MystTiq v0.7.69.0 — Stale Crash-State Fix (Windows)

## Highlights

- **Fixed another previously-flagged-but-never-chased-down item** from the same roadmap audit:
  a server shown as "Crashed" on Windows only ever cleared via an explicit Start — pressing Stop
  (arguably the more natural reaction) did nothing, leaving the stale Crashed state stuck
  indefinitely. Root cause: `WindowsServerLifecycleService.StopAsync`'s "nothing to stop" branch
  never wrote to the persisted state store at all, unlike `LinuxServerLifecycleService`'s equivalent
  branch, which already did. A genuine Windows-only inconsistency, not a mysterious edge case.
- Fix: Windows's branch now writes a fresh `Stopped`/acknowledged state, matching Linux exactly.
- Verified with a real `WindowsServerLifecycleService` instance (constructed with a fake
  process-inspector reporting nothing running, and a pre-seeded Crashed state) proving the actual
  `StopAsync` call clears it correctly — both the returned snapshot and the state re-read from disk.

## Upgrade notes

- No configuration changes. Desktop/Core-only, Windows-specific (Linux was already correct).
