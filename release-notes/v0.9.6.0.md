# v0.9.6.0 — Firewall and Server Search

- **Allow a server's port through the firewall where you set it:** Settings (beside the launch arguments), the new-server
  wizard's last step and Diagnostics show whether Windows Firewall lets players reach the port the server really uses,
  with an **Allow through Firewall** button when it doesn't. Windows asks for administrator rights when needed. The rule
  follows the port: after a port change, allowing the new port removes that server's rule for the old one. The Doctor
  checks it too, and Fleet's clone card reminds you that a clone needs its own rule.
- **An honest firewall check:** rules for other programs (the Palworld game client, Steam), for Store apps and for the
  PalServer.exe launcher no longer count as opening the server's port; the game binary that PalServer starts owns the
  port. The check now takes a fraction of a second instead of half a minute, and it no longer fails on computers whose
  PATH doesn't include Windows PowerShell.
- **A second server gets its own port:** a server added through the wizard used to copy the first server's -port=, or
  bind 8211 without one, whatever port you gave it. It now binds the port you chose, and the Doctor warns when a
  server's -port= and its advertised PublicPort differ.
- **A stopped server stays stopped:** stopping a server could, rarely, be taken for a crash while the server was still
  shutting down, and MystTiq restarted it. A stop now holds until the server has exited.
- **Fast server search:** the search checks 256 addresses at a time and only asks the ones that answer whether they run
  MystTiq, so a whole network takes seconds. It shows the ranges it searches and its progress, lists each service as it
  answers, and can be cancelled. Virtual adapters (WSL, Hyper-V, Docker) are searched only when you tick them, and you
  can add ranges of your own (for example `10.0.5.0/24` over a VPN). A search no longer disconnects the tab you run it
  from.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v0.9.5.0

Back up your server data and configuration, then extract into a new application folder. Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Firewall rules MystTiq made before this version carry no server name; they keep working and are left alone.

## Known limitations

This is a development version, not v1.0. On Linux MystTiq still doesn't change the firewall: it shows the `ufw` and `firewalld` commands to run. A server whose `-port=` and PublicPort differ is reported, not changed, because launch arguments apply when MystTiq restarts. The server search still covers the `/24` around each address, even on a wider network. The 11 translations are drafts awaiting native review. See the [roadmap](https://github.com/Wad3M/MystTiq-Palworld-Server-Manager/blob/main/docs/roadmap/PRODUCT_ROADMAP.md).

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server.
