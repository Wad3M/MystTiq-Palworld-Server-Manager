# MystTiq v0.6.5.0 — Provider Framework & Configuration Intelligence

## Highlights

- **Player moderation no longer depends on one interface.** Kick and Ban route through Palworld's REST API first (unchanged default behavior for REST-only servers), and now automatically fall back to RCON's `KickPlayer`/`BanPlayer` commands when REST is disabled, misconfigured, or genuinely unreachable. A server with only RCON enabled — a common real-world setup — previously had no working kick/ban path at all.
- **Provider health is visible before an action fails.** The Players page shows REST/RCON status (`GET /api/v1/players/moderation/providers`), so an admin can see up front whether either interface is actually configured.
- **First real Configuration Intelligence check ships**: cross-setting port-conflict detection (Game/REST/RCON ports) appears as a new "Configuration" finding in the existing unified Diagnostics report — visible on the Doctor page and the Dashboard health badge with no separate UI needed.
- **A real bug this fallback depends on was found and fixed during live verification**: the REST kick/ban call had no exception handling, so a connection-refused failure crashed past the fallback logic instead of letting RCON be tried. Fixed.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- `POST /api/v1/players/{playerId}/action` keeps its existing request/response shape for `kick`/`ban`; the response now additionally carries `providerId` (`"rest"` or `"rcon"`), which existing clients can ignore.
- New, additive routes: `GET /api/v1/players/moderation/providers`. Existing `/doctor`, `/server/environment`, and `/diagnostics/report` routes are unchanged in shape; `/diagnostics/report` now includes an additional `"Configuration"`-category finding.
