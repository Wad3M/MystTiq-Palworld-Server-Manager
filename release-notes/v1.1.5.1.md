# v1.1.5.1 — Safer File Paths

A small release on top of [v1.1.5.0](v1.1.5.0.md). It closes the problems GitHub's code scanning (CodeQL) found in how MystTiq's
service names files from what a request sends. Nothing else changes.

## What changed

- **MOD names stay in their folders.** A MOD's type and package name the files MystTiq keeps for each MOD: the snapshot
  that **Rollback** restores, and the saved MOD description and its source link. The type was not checked, so a request
  whose type contained `..\` could point those files outside their folders. The type must now be PAK, UE4SS or NATIVE
  (anything else is refused with "Invalid MOD type"), and every such file is checked to stay inside its own folder.
- **Moving a character names only a real player.** After a character is moved to a new player ID, the step that keeps,
  archives or deletes the old save accepted any text as the old player's ID. It now accepts only a player's 32-character
  ID, and the files it moves or deletes must be in the world's `Players` folder.

Each of these needed a signed-in MystTiq account that may manage MODs or players (with authentication off, the default
for a service used only on its own PC, only programs on that PC reach the service). Nothing suggests they were used.

## Upgrading from v1.1.5.0

Run the new setup, or extract the new ZIP or portable ZIP as you did for v1.1.5.0 (a portable copy: move your `data` folder
into it), or use **Update** on the MystTiq row of the Update Center once this release is published. Nothing to convert.
Coming from an older version, read the [v1.1.5.0](v1.1.5.0.md) notes first.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
