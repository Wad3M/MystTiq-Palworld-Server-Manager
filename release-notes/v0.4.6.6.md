# v0.4.6.6 — Resource History Graph & Runtime Metrics Parity

Official baseline entering this candidate: **v0.4.5.1**.

This tracked fix restores the legacy Resource History dashboard behavior in the Avalonia/headless architecture. The dashboard now provides a dual CPU/RAM graph, selectable 1-hour through 30-day ranges, average/peak summaries, persistent history, and accurate multi-process PalServer metrics.

The existing single aggregate status poll remains the only periodic desktop status sampler. Historical persistence is recorded server-side during that sample; range changes are explicit on-demand reads.

Promotion requires strict validation with zero warnings, current-version logic tests, Windows/Linux headless and desktop builds, runtime smoke, and GUI acceptance.

## Safe and force application exit
- Tray now exposes Safe Exit, Force Exit, and GUI-only exit as distinct choices.
- Safe Exit requests the normal PalServer graceful shutdown path before stopping the GUI-owned management sidecar.
- Force Exit uses a dedicated management API route with a zero graceful timeout, immediately escalating through the lifecycle service's existing forced-termination path, then stops the GUI-owned sidecar.
- GUI-only exit intentionally leaves server/backend services running.
- Corrects stale v0.4.6.4 documentation assertions in the current release logic gate.
