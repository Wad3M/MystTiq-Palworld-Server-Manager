# v0.9.10.0 — Review Fixes

An outside review of v0.9.9.0 found six problems. All six are fixed here, along with the wording notes from its
translation review.

- **One helper, even when it is slow:** if the local helper MystTiq started was busy and did not answer within
  three-quarters of a second, MystTiq forgot it and started a second one. It now waits for a helper that is still
  running, and replaces one only after it has actually stopped. If it cannot be stopped, MystTiq says so instead of
  starting another.
- **Names stay names:** a server called "Ready" showed as "Bereit" in German and "Listo" in Spanish, because the name
  matched a status word. Server, player, guild and world names now stay exactly as written inside translated messages,
  and the Dashboard shows the server's name and description untranslated.
- **"Up to date" only when it was checked:** a MOD with no Steam Workshop copy to compare against (or on Linux) counted
  as up to date, so removing the Workshop copy could clear an update warning. Now an update warning clears only when the
  MODs it named have been checked and are current, or have been removed.
- **New MystTiq versions are seen:** the update check asked GitHub for its "latest release", which skips prereleases,
  and every MystTiq 0.x release is published as one. It now reads the release list: while MystTiq is 0.x, prereleases
  count; from 1.0 on, only stable releases do.
- **Crash evidence that stays:** the "session ended on a player joining" finding appeared a minute after the join and
  was gone ten minutes later. It no longer depends on when the logs are read, so it is recorded once and stays in the
  crash history. Its title no longer claims how soon after the join the server stopped, since the log can't tell.
- **The source download passes its own checks:** the v0.9.9.0 source's checkpoint notes were added after the files were
  stamped, so its own gate failed one check. The notes are now part of the stamped files, and the source download is
  checked after it is made.
- **Port forwarding is allowed for:** the Doctor's port finding now says a router that forwards a different outside port
  on purpose is fine, and Fix stays a choice.
- **Translation notes:** the Pal edit preview's Level, Gender and Nickname labels are translated in all 11 languages;
  the MOD update alert no longer uses "MOD(s)" plurals; German uses "Stopp erzwingen" and "Änderungen zurücksetzen";
  the helper message says "this app" rather than "this desktop".

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v0.9.9.0

Back up your server data and configuration, then extract into a new application folder. Keep the existing service/configuration/data locations and the matching `headless` folder. Nothing to convert: the helper record from v0.9.9.0 is read as before (it gains a start time when the next helper starts). A crash finding recorded by v0.9.9.0 keeps its old title in the history.

## Known limitations

This is a development version, not v1.0. A name placed in a message without quotes and not after a word such as "server" or "player" can still be translated if it equals a known status; MystTiq's own messages quote names. English keeps your system's number and date format; the other languages use their own. The 11 translations are drafts awaiting native review. See the [roadmap](https://github.com/Wad3M/MystTiq-Palworld-Server-Manager/blob/main/docs/roadmap/PRODUCT_ROADMAP.md).

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server.
