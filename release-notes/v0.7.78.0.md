# MystTiq v0.7.78.0 — MOD Pages UX Pass

## Highlights

- **MOD Library redesigned**: local Steam Workshop MODs now load automatically on first visit each
  session. Install Validated ZIP and Available Local Steam Workshop Mods sit side by side at the
  top of the page; Installed MODs (2/3 width) and MOD DETAILS (1/3 width) sit below. The old
  9-button row is gone — all-MODs actions (Enable All, Disable All, Repair, Safe-Start Diagnostic)
  moved to a new ribbon "MOD Maintenance" group, and per-mod actions (Enable/Disable/Rollback/
  Repair/Delete Selected) are now a right-click menu on the list.
- **Install Validated ZIP simplified**: the manual package-name box and two permanently-disabled
  placeholder buttons are gone. You can now drag and drop a ZIP file directly onto the card.
- **Per-mod version and update info**: the Installed MODs list now shows each mod's own installed
  version and an "UPDATE AVAILABLE" badge when a newer copy is sitting in your local Steam Workshop
  cache — no more clicking into a MOD's details just to check.
- **MOD Dashboard redesigned** to feel distinct from MOD Library: a new color-coded health banner up
  top, recolored status cards, and a deliberately lighter "MOD Overview" list (Library is still
  where the full detail and the actions live).
- **UE4SS page fixes**: card text no longer sits flush against card borders (a shared styling gap
  that affected every `statuscard` app-wide, not just this page). Runtime Health now remembers a
  confirmed-good run instead of reverting to "Unverified" once its one-time evidence disappears
  (server stopped, log rotated, etc.).

## Upgrade notes

- No configuration changes. Touches `MystTiq.Desktop` and `MystTiq.HeadlessHost`.
- A new small file, `ue4ss-runtime-verification.json`, is written under the manager runtime root the
  first time UE4SS is confirmed running correctly — safe to delete if you ever want to reset that
  state back to "Unverified".
