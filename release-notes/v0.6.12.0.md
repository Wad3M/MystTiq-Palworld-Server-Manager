# MystTiq v0.6.12.0 — Gap Audit, Real Bug Fixes & Logic/Runtime Test Pass

## Highlights

- **A real, long-standing bug fixed**: the Players/Guilds/World Explorer read-only views could show stale data after a guild/base/character ownership change, until something outside MystTiq happened to re-decode the save. First reported as a known limitation almost a year ago and never fixed — closed for real this release, verified live by applying an actual leadership transfer and confirming the explorer view updated immediately with no extra steps.
- **A second real bug found and fixed while testing this release**: writing a default configuration file with a custom server-root path silently ignored that path and wrote the built-in default instead. Fixed.
- **Full gap review**: every previous release's disclosed "known gaps" were reviewed together for the first time, plus a live bug-testing pass exercising the real API with malformed and edge-case input. Results are documented in the roadmap so nothing gets lost.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- No new routes. No behavior change for any existing route's happy path — both fixes only change behavior in previously-broken cases (a stale sidecar; an ignored CLI override).

## What's deferred

- Two verification-only gaps remain open pending resources this project doesn't currently have: an elevated (Administrator) live-cycle test of the Windows Service installer, and deploying this session's latest source to the existing Linux box rather than only connecting to what's already there.
- A minor, non-safety validation gap: automation rule creation doesn't reject an obviously-invalid negative idle threshold at the API level (the actual scheduling logic already safely clamps it, so this doesn't cause a functional problem — just a misleading stored value).
- Three real architectural gaps are scoped as candidate next-milestone work: fleet-wide crash-recovery for cloned server profiles, a per-page "current server" selector across the rest of the Desktop app, and cross-profile automation rules.
