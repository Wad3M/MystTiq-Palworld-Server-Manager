# v1.1.0.2 — Player IDs: Join Check and Automatic Character Move

**Players who were sent to a new character get their own back, automatically.** Since its 1.0 update, Palworld can give
a returning Steam player a new player ID. Their character, Pals and buildings stay under the old ID, so the game hands
them an empty character instead. On the owner's server this happened to two players. Starting the server differently
does not change it: it happens with every way of starting the server, with or without MODs, and with or without
MystTiq.

What MystTiq does now:
- **Checks every join.** Each Steam player's player ID is compared with the ID their character lives under. The result
  is listed on the new **Player IDs** card on the Players page (correct, first seen, new ID from the game, moved).
- **Moves the character to the new ID.** When the game gives a player a new ID, MystTiq turns them away with a message
  that their character is being moved. Once nobody is online, it stops the server, takes a safety backup, moves the
  character (level, Pals, buildings, guild), checks the result, and starts the server again. The old character file is
  archived, not deleted. You can also move it yourself with **Restart server and move character**, or switch the
  automatic move off.
- **Learns each player's ID from the game**, so the identity guard no longer turns away a player who has been moved.
- A player sent to the new-character screen may now make a character: it is replaced by their real one in the move.
- The Launcher no longer says that -log, -stdout and similar options give players the wrong character; they are
  diagnosis options.

If anything about a move is not exactly as expected (for example the new character has joined someone's guild or
built a base), MystTiq does not move it and alerts you instead.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.1.0.1

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the [v1.1.0.0 notes](v1.1.0.0.md).

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
