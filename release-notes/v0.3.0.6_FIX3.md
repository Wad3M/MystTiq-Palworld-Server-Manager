# MystTiq Palworld Server Manager v0.3.0.6 FIX3

## Protected Secrets Directory Ownership Hotfix

Remote-enrollment acceptance exposed an ownership bug in the protected secrets directory.

The enrollment script created `/etc/mysttiq/secrets` as `root:root` mode `0700`.
Although the API token file itself was owned by the MystTiq service user, that user could not traverse the root-only directory. The script therefore mis-detected the existing token as missing and attempted to recreate it.

FIX3:

- creates `/etc/mysttiq/secrets` as the selected service user/group with mode `0700`
- explicitly verifies the secrets-directory owner and mode
- uses privileged `test -s` checks for token/certificate prerequisite detection
- preserves `0600` ownership checks on individual secret/PFX files
- keeps the existing pre-commit configuration rollback behavior

No API, TLS, authentication, lifecycle, PalServer, systemd policy, or Windows WPF behavior changed.
