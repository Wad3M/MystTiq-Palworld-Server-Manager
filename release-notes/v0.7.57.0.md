# MystTiq v0.7.57.0 — Native Console Capture, Proxy DLL Foundation

## Highlights

- **A new native C++ component, verified but not yet live-tested.** `native/MystTiqConsoleProxy/`
  proxies `DSOUND.dll` — confirmed by exact ordinal comparison against PalServer's own import table
  and the real system DLL — so it can sit alongside the game and run code via `DllMain` without
  changing anything about how the game itself behaves. Built, loaded in isolation, and confirmed to
  forward correctly and unload cleanly.
- **The actual console-log hook is not implemented.** It needs a live process to safely verify a
  memory signature scan against, and this machine's real PalServer currently can't launch cleanly
  at all (see below) — an honest scaffold that logs its own no-op status, not a fabricated
  capability.
- **Not part of the app.** This ships as a standalone artifact, not wired into MystTiq's install or
  deploy flow.

## A separate, unresolved finding from this session

While investigating why live testing wasn't possible, ruled out UE4SS/PalDefender/the d3d9 injection
chain as the cause of this machine's PalServer launch freeze (tested directly, with all three fully
disabled — same freeze happened anyway) and a device reboot (retried after, same freeze). Found that
`steamcmd.exe` itself crashes on this machine right now with `STATUS_STACK_OVERFLOW`, independent of
Palworld entirely — a genuine, concrete lead, but diagnosing it further needs tools (Process
Monitor, WER dump analysis) this session doesn't have.

## Upgrade notes

- No configuration changes, no new routes, no change to `MystTiq.Core`/`MystTiq.HeadlessHost`/
  `MystTiq.Desktop`. Purely a new, standalone native artifact.
- To build it yourself: `scripts/Build-ConsoleProxy.ps1` (requires the MSVC v143 toolchain).
- Do not copy `MystTiqConsoleProxy.dll` into a real server's binary directory yet — it has not been
  tested against a real, running PalServer.
