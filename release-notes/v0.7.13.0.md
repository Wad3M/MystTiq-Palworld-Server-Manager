# MystTiq v0.7.13.0 — New-Server Workflow Redesign

## Highlights

- **"Set Up New Server" is no longer buried in Settings.** It's now a dedicated, focused screen that takes over from the regular nav sidebar/ribbon/category tabs while a tab is mid-setup — you can't accidentally navigate away from a connection that doesn't exist yet, and the wizard never looks like it's part of the app's regular editing controls.
- **A new first step: Local or Remote.** Before entering any connection details, pick whether this server runs on this computer or somewhere else. Local shows an Auto-Detect button plus manual fields for a second/third local instance; Remote shows the LAN scan plus manual address/token/certificate-pin fields — only the fields that matter for your choice.
- **Verified against 3 real servers running at once**: two ordinary local servers on different ports, plus a third configured exactly like a genuine remote deployment (its own network address, authentication, and TLS) — confirming an unauthenticated connection is correctly rejected and the secured one behaves like a real remote connection would.

## Upgrade notes

- The remaining wizard steps (in-game server defaults, confirm & finish) are unchanged from v0.7.3.0 — same fields, same behavior, just relocated.
- Editing an already-saved profile from the Settings page is unaffected; that card now only ever handles editing.
- No configuration schema change, no server-side product behavior change — this release is Desktop-only.
- A real CLI bug in the headless service's `api-remote-enable` command was found while testing this release's Remote branch and is being tracked separately; it does not affect anything shipped here.
