# v1.1.4.0 — Update the Server from the Dashboard

There is no v1.1.3.0: this release was asked for as v1.1.4.

## Server update card

The Dashboard's LIFECYCLE bar is shorter, and the space beside it, above OVERALL HEALTH, holds a **Server update** card:

- the installed Palworld build and Steam's current public build (**Build 25247047**, or **25247047 → 25300000** when
  an update is out), with a tag: **Up to date**, **Update available**, **Updating**, **Unavailable** or **Not installed**;
- an **Update Server** button (Admin). It asks first and says what will happen: if the server is running and how many
  players are online (they are disconnected), and that a safety backup is taken first.

The update runs on the MystTiq service, next to the server, so it finishes even if you close MystTiq: it stops the
server (the stop's reason is "Server update"), takes a safety backup, runs the SteamCMD update, and starts the server
again if it was running. The card shows each step; the activity log records each one and the result. If the backup or
the update fails, the update stops there, the server is started again if it was running, and a notification says what
went wrong. While another operation holds the server (a start, a backup, a MOD change, a save edit), the update is
refused with the reason. Steam's answer is checked when you connect and every 15 minutes.

## Fixed

- With several servers on one computer, a stopped server said "A PalServer process is running, but not at the
  configured path" whenever another of your servers was running. A server started by a MystTiq service is now known
  to be that service's; a PalServer started by hand from another folder is still reported.
- A stop whose request was cancelled (for example a program that gave up waiting) finished without a line in the
  activity log. It now records **Server stop interrupted: <reason>**.

## Also

## Upgrading from v1.1.2.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder. Nothing to convert. If you turned on **Start MystTiq when I sign in**, Settings says the entry points at the old folder; turn it off and on again. Coming from an older version, also read the [v1.1.2.0](v1.1.2.0.md), [v1.1.1.0](v1.1.1.0.md) and [v1.1.0.0](v1.1.0.0.md) notes.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
