# v0.5.2.0 — Guild Ownership Platform

This release adds the first working slice of a real Guild/Base ownership-repair platform, replacing three disabled "BACKEND REQUIRED" stub buttons on the Guilds page with real functionality.

- Claim Orphaned Guild, Transfer Leadership, and Add Player to Guild are now real, working operations instead of stubs.
- All three share one Preview → Safety Backup → Server-side Transaction → Validate → Journal/Audit → Refresh GUI implementation (`HeadlessGuildOwnershipService`), the same pattern already proven by World Transactions, and journal into the same transaction store so existing Transaction Center history picks them up automatically.
- Adds `HeadlessSaveCodecService`, a server-side Level.sav Decode/Encode capability that detects each save's actual container format (plain PlZ vs. PlM/Oodle) per file rather than assuming one converter. This was found to matter immediately when validating against a real deployment: the reference Linux server's save uses the PlM/Oodle container.
- Fixes `PalworldSettingsConfigurationService.Load()` throwing uncaught and crashing the entire `/api/v1/status/poll` aggregate endpoint whenever `PalWorldSettings.ini` exists but does not yet contain `OptionSettings=(` — a real, observed state on a freshly-started PalServer before its first full config write, not corruption. `Load()` now returns a graceful degraded snapshot instead.
- Fixes two version-string literals that had silently drifted from the real build version: the headless CLI's `--help` output had said `v0.4.18.2` for six releases, and the Desktop's displayed `Version` property used the same fragile hardcoded-literal pattern. Both now derive the version from the assembly (`Assembly.GetExecutingAssembly().GetName().Version`) instead.
- Fixes a dead "Open Server Log" button in Diagnostics Center that navigated to a nonexistent page.
- Base ownership/Palbox repair remains BACKEND REQUIRED — the transactional pattern now exists and is proven, it has not been ported onto Base's different data shape (`base_ids`/Palbox ownership rather than guild `RawData`) yet.

Verified end-to-end against a real Linux deployment (Ubuntu 24.04.4 LTS, matching the documented reference environment), not just compiled for `linux-x64`: deployed via `scripts/Deploy-Test-MystTiqLinux.ps1`, confirmed the save-codec container-format detection, ran Transfer Leadership and Add Player to completion against a copy of a real save, and independently re-decoded the resulting file to verify the changes actually persisted (rather than trusting the service's own self-report). A real mid-transaction encoder failure during testing correctly triggered rollback to the pre-transaction file with hash verification, rather than leaving a partial write.

Promotion requires clean validation, logic, Windows/Linux desktop and headless builds, Windows runtime smoke, archive-entry verification, and SHA-256 verification.
