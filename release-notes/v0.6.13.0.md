# MystTiq v0.6.13.0 — Fleet-Wide Crash Recovery

## Highlights

- **Every server profile now has real crash recovery, not just the default one.** Previously, automatic restart-after-a-crash only worked if you'd installed MystTiq as a Windows Service or systemd unit, and even then only for your default server. Running MystTiq normally through the desktop app (the way almost everyone does) gave you zero automatic crash recovery for any profile — including a Clone World copy. Now, every profile is automatically watched and restarted if it crashes, the moment the desktop app's backend is running.
- **New: install an independent, unattended service per server.** If you run multiple servers and want each one to survive a full reboot with its own OS-level auto-restart, you can now install a separate Windows Service or systemd unit per profile with `--server-id`, instead of only being able to do this for your default server.
- An intentionally stopped server (by you, or by Idle Auto-Stop) is never mistaken for a crash and auto-restarted — verified live with a real running server.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- If you already have MystTiq installed as a Windows Service or systemd unit for your default server, its name is completely unchanged — this upgrade won't touch, rename, or orphan it.
- New CLI option: `--server-id <id>`, accepted by `service-install`, `service-uninstall`, `service-status`, `service-run`, and the direct `status`/`start`/`stop`/`restart` commands.

## What's deferred

- Per-server customization of recovery timing (poll interval, backoff, retry limits) — every profile currently shares one fleet-wide setting.
- Installing/managing per-server services from the desktop app's UI — this remains a command-line-only capability, matching how the single-server version has always worked.
