# MystTiq Palworld Server Manager v0.2.15.13

## Operational Health Model & Application Composition Refinement

v0.2.15.13 corrects the Dashboard's server-health semantics and centralizes how the MOD subsystem contributes to Overall Health.

### Corrected MOD health semantics
The previous Dashboard inferred MOD problems as `installed - healthy`. That incorrectly treated Disabled, Active / Unverified, Active, and Unknown states as server health failures.

The new `ModPlatformHealthService` classifies MOD state explicitly:
- Healthy / Confirmed Loaded / Confirmed Running: healthy contribution
- Disabled: informational/neutral
- Active / Unverified: informational/neutral
- Active / Installed / Unknown: informational/neutral
- Failed: confirmed health issue
- Missing: confirmed health issue when the MOD is enabled
- Misconfigured: confirmed health issue when enabled
- Attention/state mismatch/duplicate: confirmed health issue when enabled
- Runtime error evidence: confirmed health issue
- Confirmed conflict: confirmed health issue
- Missing dependency: confirmed health issue

Disabled MODs remain visible in the MOD Dashboard but do not reduce the running server's Overall Health.

### Composition refinement
`DashboardIntelligenceService` no longer receives raw installed/healthy counts and derives a failure count. It consumes a structured `ModPlatformHealthSnapshot` produced by `ModPlatformHealthService`.

The main Dashboard MOD card and compact health strip also consume the same centralized snapshot/summary.

### Expected examples
- 8 installed / 8 disabled / 0 failures => MOD platform informational/neutral; no MOD health deduction.
- 8 installed / 6 healthy / 2 Active / Unverified / 0 failures => no MOD health deduction.
- 8 installed / 7 healthy / 1 enabled Failed => one confirmed MOD health issue and a health deduction.

No MystTiq theme, button, tooltip, server lifecycle, runtime evidence, or MOD enable/disable behavior is intentionally changed.
