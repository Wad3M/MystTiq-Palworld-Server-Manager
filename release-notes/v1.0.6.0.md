# v1.0.6.0 — Pals in the Pal Box, and MODs Laid Out as the Game

## Add or remove a Pal in a player's Pal box

**Players > Pal box in the world save** (admins, beside the inventory card): **Load Pal Box** lists the selected player's
Pal box: place, kind, level and any name a player gave it.

- **Remove Selected Pal** takes one Pal out of the box. Pals in the party or working at a base are not removed here.
- **Add To Pal Box** adds a Pal of the kind picked beside it. It is a copy of a Pal of that kind already in a Pal box in
  this world, so its level and stats are ones the game itself wrote. It gets its own id, the player as its owner, the
  first free place and the player's guild, and not the original's name.

Each edit is guarded like the inventory edits:
- the server must be stopped;
- you see what will change and confirm it;
- a fresh safety backup is taken and checked first;
- the edited save is decoded again and must show exactly that one Pal more or less, and nothing else changed in the
  world's characters, the box or the guild;
- if anything fails, the original is put back.

Tested on a copy of a real world, and on the clone's own world through real game loads and saves: the game kept an added
Pal, and after a removal it was gone.

## MODs laid out as the game folder install too

MODs that copy the game's own folders now install where the game loads them, instead of being refused:

- **A blueprint MOD for UE4SS** (a PAK under `Paks\LogicMods`) goes into `Pal\Content\Paks\LogicMods\<name>`, with the files
  that come with it, such as its settings file. If UE4SS's BPModLoaderMod is not switched on in mods.txt, the install says
  so.
- **A PAK with UE4SS scripts** installs as two parts under one name: the PAK where it belongs, and the scripts as a UE4SS
  MOD folder. Both appear on the MODs page and can be removed.
- Both need UE4SS. Without it they are refused, and nothing is written.

Thunderstore's BasesPlus, for example, now installs from the MOD browser. Archives with several different PAKs (usually
choices of one), shimloader packages, loader DLLs and programs are still refused with the reason.

## Fixed

- A file held for a moment by another program (an antivirus scan of a freshly written save) could make the last step of a
  save edit fail. The edit was rolled back safely, but for nothing. MystTiq now waits a moment and tries again.
- When a restore cannot remove its temporary copy of the old world because some files belong to administrators, it now
  says so and points to **Fix Save Folder Access**.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.5.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
