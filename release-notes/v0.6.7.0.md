# MystTiq v0.6.7.0 — Safe World Editing, Administration & Player Recovery

## Highlights

- **Guild Membership Repair.** A new `RemoveBrokenMember` operation on the already-proven guild ownership transaction pipeline removes a dangling member reference — a guild member whose save file no longer exists — with the same Preview → Safety Backup → Server-side Transaction → Encode → Verify → Commit rigor every guild-ownership change already has.
- **Player Identity Mismatch Detection.** Two new read-only Diagnostics findings: a Steam ID observed under multiple distinct player identities, and a player observed online with no matching save file. Built on v0.6.6.0's Player Registry, cross-referenced against existing guild explorer save evidence — no new save-decode work. This is the foundation a future interactive UID-remapping wizard would build on, not the wizard itself.
- These advisory findings are explicitly excluded from the Overall Health rollup, so a routine "just joined, save not written yet" moment doesn't flip the Dashboard badge to Degraded.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- `POST /api/v1/guilds/ownership/preview` and `/apply` accept a new `operationType` value (`"remove-broken-member"`); existing values (`claim`, `transfer-leadership`, `add-player`) are unchanged.
- `GET /api/v1/diagnostics/report` gains additive `"Identity"`-category findings; existing categories and the `passed`/`warnings`/`failures` semantics for `"Health"`/`"Setup"`/`"Configuration"` are unchanged.
