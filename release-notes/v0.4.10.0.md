# v0.4.10.0 — Players Parity

This release restores the v0.2.16.4 player-management information architecture while preserving MystTiq's headless-first, remote-safe design.

## Player directory

- Combines live Palworld REST sessions and server-side saved-player discovery into one stable-ID directory.
- Adds player/ID/guild/platform search, live/save view filters, administration filters, selected-player details, evidence, and local CSV export.
- Preserves the selected player across refreshes when the same authoritative ID remains present.
- Enables Kick and Ban only for a currently online player. Unsupported Whisper, Promote, Give Item, Whitelist, Temporary Ban, Unban, and Remove Admin operations stay visibly unavailable.

## Notes and warnings

- Adds authenticated headless routes for player notes and operator warnings.
- Persists metadata atomically beneath the configured manager runtime root.
- Bounds IDs and text lengths and retains the latest 100 warnings per player.
- Audits every mutation using the player ID and counts only; private note and warning bodies are not copied to the persistent activity log.

## Shared desktop polish

- Centers standard button content horizontally and vertically.
- Adds a shared metallic gradient with hover, pressed, disabled, and keyboard-focus states.
- Before a Windows build relaunch, stops and waits only for `MystTiq.Desktop` or `mysttiq-server` executables running beneath this repository's artifact tree. PalServer and installed services are never targeted.

The release retains one aggregate periodic status request, Windows/Linux Avalonia parity, remote/LAN bearer and TLS behavior, global card containment, and View → ViewModel → API client → route → headless service wiring.

Promotion gate: strict validation reported 0 errors and 0 warnings; Windows and Linux headless/desktop builds succeeded; Windows isolated runtime smoke passed all player persistence, audit-privacy, capability-truth, and lifecycle-safety checks; logic gate passed 160/160.
