# v0.7.114.0 — Multi-User Login

Last of the four items pulled into 0.7.x on 2026-09-22.

- **Named accounts.** The Owner creates people on the Security page (username, display name, role, optionally
  limited to one server, password). They sign in from Settings → "Sign in with a user account".
- What each person can do follows their role (Viewer, Operator, Admin, Owner). A role change applies at once.
  Disabling an account or resetting its password signs it out everywhere. Sessions last 12 hours.
- Passwords are stored only as salted PBKDF2 hashes, and session tokens only as hashes. 5 wrong passwords
  lock an account for 15 minutes.
- The audit log now says **who** made each API call.
- The Desktop now knows your role as soon as it connects, so Admin/Owner-only controls are greyed out for
  everyone else on every page.
- Existing tokens (the shared token and principal tokens) keep working unchanged. Named accounts need
  authentication switched on (remote access); on the local sidecar, where authentication is off, everyone is
  already Owner.
- Also fixed: a small timing race in Teleport Points (v0.7.113.0), where the reply to a player could go out
  just before the use was recorded. The full test run caught it once.
- Checked with 3 new logic-harness scenarios and an 11-check live smoke with authentication really on. A real
  Desktop sign-in against a remote MystTiq was not exercised here.
