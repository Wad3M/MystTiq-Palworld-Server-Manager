# MystTiq v0.7.63.0 — Central Theme System Audit: Status-Color Bypass Fix

## Highlights

- **Fixes a real gap the user found live**: several status colors — the tab-bar connection dot, the
  Dashboard health label, the Fleet server list's status dot, and Update Center's component-status
  table — stayed locked to their original color through every accent-theme and Light/Dark switch,
  even though the app's central theme system (v0.7.48.0, v0.7.56.0) was supposed to cover exactly
  this. Root cause: those four values were each computed as a hardcoded hex literal in C# (a
  ViewModel property, a Model property, or a cached converter brush) and bound with a plain
  `{Binding}` rather than routed through the live `{DynamicResource}` system — a different bug class
  from the ~530 hardcoded-gradient-literal sweep those two prior passes actually covered, so it
  survived both "central theme system completion" passes undetected.
- Also found and fixed: the sidebar's mini connection-status card and the duplicate-install-location
  warning banner (both plain `Border.statuscard`, no accent class) had **no themed style at all** —
  `App.axaml`'s leftover pre-DesignSystem-era hardcoded style was the only one that ever applied to
  them, silently un-themed this whole time.
- Cleaned up `App.axaml`: removed its entire legacy parallel color-resource system (dead now that
  `Styles/DesignSystem.axaml` supersedes all of it) and two fully-dead nav-item style selectors with
  zero live usages, so the codebase has one theme system, not two.

## Upgrade notes

- No configuration changes, no new capabilities, routes, or DTOs.
- No way to visually render this app in the environment that built it — same disclosed limitation as
  v0.7.48.0/v0.7.56.0. Please click through the tab bar's status dots, the Dashboard health label, the
  Fleet page's server list, Update Center's component table, and the sidebar's mini status card across
  all four accent themes and both Light/Dark variants before considering this fully verified.
- `ConsoleLineColorConverter` (log-line highlighting in the mini console/RCON output/Console page)
  was reviewed and deliberately left hardcoded, consistent with v0.7.48.0's own disclosed decision to
  keep terminal-style views dark/green in every theme.
