# MystTiq v0.7.7.0 — Fix: Backup/Restore & Lifecycle Locking Race Conditions

## Highlights

- **Real race condition fixed**: restoring a backup could previously run at the same time as a Guild Ownership, Base Ownership, or World Transaction operation on the same save directory, since the backup service never registered with the app's own operation-locking mechanism. It now takes the same lock every other save-mutating operation does.
- **Real race condition fixed**: a network-diagnostics-triggered server restart bypassed that same lock entirely, unlike every other restart path in the app.
- **Two silent-failure bugs fixed**: a backup restore that actually succeeded but whose cleanup step failed was being misreported as "restore failed"; and a rare rollback-of-rollback failure path was being silently swallowed instead of surfaced.
- A mod-snapshot rollback now uses the same ZIP path-traversal protection already applied to fresh mod uploads.

## Upgrade notes

- This is the one release in the current fix/feature sequence that touches server-side code (`MystTiq.Core`/`MystTiq.HeadlessHost`), not just the desktop client.
- No configuration schema change.
