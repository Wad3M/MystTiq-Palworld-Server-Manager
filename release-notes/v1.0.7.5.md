# v1.0.7.5 — Under Load, and Over Time

Roadmap item Q-10 from the outside quality review: MystTiq tested under load, when things go wrong half way, and over a
day of running. The tests found three things to fix.

## An update stopped half way is no longer called installed

- **Before:** "installed" meant only that `PalServer.exe` existed. If SteamCMD or MystTiq stopped during an update
  (closed, crashed, or the computer switched off), the files around it could be half updated, and MystTiq still said
  **Installed** and would start the server.
- **Now:** MystTiq marks the server folder while an update runs and clears the mark only once Steam reports the update
  finished. Steam's own install record is checked too. A half-finished update shows as **Incomplete — Update required**,
  and the server is not started until **Update** has been run again.
- **One cause removed:** closing the desktop (or losing the connection) during an update used to stop SteamCMD half
  way. The update now runs to its end on the service.

## A backup waits for a save file that is in use

A backup used to fail at once if any save file was open, for example while the server was writing it. It now tries
for up to 10 seconds. If the file is still in use, the message names the file and the program holding it.

## Tested for load and time

- **A long test set** (run with the full gate when asked):
  - an update interrupted half way;
  - backups, starts, stops and updates sent all at once;
  - a save file held open;
  - 10,000 console lines;
  - stopping the service.
- **Rapid tab switching:** 300 switches with slow, out-of-order replies; every tab shows only its own data.
- **A 24-hour idle run** on Windows and on Linux (as a per-user systemd unit), recording memory, open handles and
  threads every half hour.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.7.4

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. If the Dashboard says the local service is older, click **Update Service To This Version**: the update and backup changes run in the service. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
