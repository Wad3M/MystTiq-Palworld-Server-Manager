# v0.7.88.0 — New Server Wizard and Dashboard Bug Fixes

Direct live feedback with screenshots surfaced five real bugs. All fixed:

- **Wizard jumped straight to Confirm & Finish**, skipping every step. Root cause: a short-circuit
  meant for the Connect flow was wrongly also firing for New Server Setup, where step 1 always
  connects to the shared default API -- so any user with an already-running default server hit it on
  every "+ New Server" attempt. Now scoped to Connect only.
- **Install Directory step had no field** to see or change the target path -- just a status sentence
  and a warning box. Added a real, editable path field with a folder-browse button.
- **Game Port now highlighted** on the Server Identity & Ports step, with a permanent note: only
  change it if running multiple servers on the same machine at once, otherwise the default is fine.
- **Clone source list was missing "Local MystTiq"** -- it reused a filter meant to avoid opening
  duplicate tabs, which had no bearing on whether a server is valid to clone from. Now lists every
  saved profile.
- **Dashboard could get stuck on "Starting / Not Ready"** with Start greyed out even after the server
  had genuinely stopped. Root cause, confirmed live against the running service: the backend
  correctly reports the server as Stopped but also (by design) reports the previous run's PID for
  reference -- the Desktop client was treating "a PID is present" as "a process is alive," which is
  wrong once that PID is stale. Now checks the actual reported phase.

Touches `MystTiq.Desktop` only.
