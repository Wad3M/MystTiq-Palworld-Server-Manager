# v0.7.89.0 — Second-Server Lifecycle Fixes and Wizard Polish

Direct live feedback while driving a genuine second local server through setup and Start surfaced
a cluster of real bugs, most stemming from code that treated "the literal default profile" as a
stand-in for "a local server" -- which breaks once a genuine second local server exists:

- **Server "did not start, no error message"** -- Start silently did nothing for any non-default
  local profile whenever the connection was momentarily unconnected. Fixed to recognize any
  loopback-addressed profile as local, with an explicit status message on failure.
- **Tab labeled "Remote" for a genuinely local server** -- same root cause, same fix.
- **Dashboard showed a different server's world data** -- a brand-new server's "still starting, no
  world yet" state left the previous tab's Active World ID/player-save count/size on screen instead
  of clearing them. Fixed.
- **"How is this overall progress at 100% when there are missing items?"** -- the progress bar only
  ever tracked the last operation's own completion, not environment readiness. Relabeled to
  "OPERATION PROGRESS" so it no longer claims to be something it isn't.
- **Install step didn't auto-refresh or show real progress** -- fixed to auto-refresh the Server
  Environment checklist after install, and now shows SteamCMD's own captured output.
- **MODs step required a manual scan** -- now auto-scans Steam Workshop on arrival.
- **MODs step had no local-ZIP install option** -- added a distinctly-colored "Install MOD ZIP…"
  button, reusing the same path MOD Library's own ZIP install already uses.

Touches `MystTiq.Desktop` only.
