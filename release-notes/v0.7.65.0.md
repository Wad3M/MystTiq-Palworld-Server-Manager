# MystTiq v0.7.65.0 — Linux Console Capture Fix

## Highlights

- **Fixes the Linux console-capture gap flagged in v0.7.64.0**, at direct follow-up request. Closer
  tracing found a more precise bug than "no capture at all": Linux's detached PalServer launch script
  was already redirecting stdout/stderr via `setsid -f ... >> file 2>&1` — just into
  `ManagerRuntimeRoot/palserver-console.log`, a location nothing on the read side (Live Console,
  `HeadlessMonitoringService`, Doctor) ever looked at. Every one of those only ever checks
  `LogsRoot/MystTiq-PalServer-Console.log` — the exact file Windows captures into.
- Relocated Linux's capture to that same filename/location, so it finally reaches the same consumers
  Windows' capture already does. Also gets log rotation (v0.7.64.0's `ConsoleLogRotation`), applied
  once per server start rather than continuously — the only point in this platform's detached-process
  architecture where rotation is actually safe (see the architecture doc for why mid-session rotation
  can't work the same way it does on Windows, where bash holds one file handle open for the entire
  session).

## Upgrade notes

- No configuration or schema changes.
- **Verified live against the real reference Linux VM** (correct address `192.168.1.143` — an
  earlier `.144` in this session's own notes was a stale typo). Built a fully isolated test (scratch
  directory, throwaway port, stand-in server script, non-conflicting game port) rather than running
  the acceptance script's own `--extended` flag directly, since that flag defaults to the live
  production config — the real `mysttiq-palworld.service` was confirmed untouched (same PID)
  throughout. Confirmed live: the console log lands at the correct new path with the expected start
  marker and real captured stdout/stderr, and rotation correctly moves a 26 MB file to a `.1`
  generation and starts a fresh one on the next server start. See the architecture doc for full
  detail.
- The Linux capture is a single merged stdout+stderr stream, same as before — no `[OUT]`/`[ERR]`
  per-line tagging like Windows has. Deliberately not attempted this pass (would need piping the
  detached shell's redirect through `sed`/`awk`, higher-risk without clear payoff).
