# v0.7.102.0 — Deficiency Fixes From Walking the Running App

Seven defects found by walking the running app after v0.7.101.0, all fixed.

- **Configuration phantom "unsaved change" (data risk).** A setting the file holds outside its slider's range
  (Item Corruption Rate 0.05 under a 0.1 minimum) was silently rewritten when the page opened, showed "1 unsaved
  change", prompted on leaving, and Save would have replaced it. Sliders no longer write back a clamped or
  snapped echo of an existing value; a real drag is still recorded. Item Corruption Rate now ranges 0 to 10.
- **Alert Center repeats.** A condition that stayed true re-alerted every cooldown as a pinned Critical and forgot
  on restart (83 unread, five identical "Low disk space"). Alerts are now episodes: one alert when a condition
  starts, one "Resolved" notice when it clears, remembered across restarts; the cooldown is now a flapping guard.
- **Disk thresholds agree.** The Doctor and Alert Center share one rule (Critical under 2 GiB or at or under the
  configured percentage, Warning under 5 GiB). The Doctor states the percentage.
- **Diagnostics Center** shows a stopped server as "NOT RUNNING", not "Network: ERROR"; only a crash is an
  error. Restart Server there now needs a running server.
- **Backups** retention boxes show two-digit values.
- **Update Center** says when your install is newer than the latest published release.
- **Automation** says when nothing is scheduled and points at the pre-set nightly-backup form. No rule is
  created for you.
- Checked live on a real sidecar (alert once, silent, survives a restart, one recovery) and on the running app.
- Not done: existing stale notifications are not deleted, and the pinned original alert stays pinned after
  recovery.
