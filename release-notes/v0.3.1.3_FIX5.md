# MystTiq Palworld Server Manager v0.3.1.3 FIX5

## PowerShell Deploy Parameter Syntax Hotfix

FIX4 correctly removed the stale v0.3.0.7 deployment version, but placed a command invocation directly in the `Version` parameter default:

```powershell
[string]$Version = & (Join-Path $PSScriptRoot 'Get-ProjectVersion.ps1')
```

PowerShell does not allow that command invocation form in a parameter default, so release validation reported parser errors.

FIX5:

- changes `Version` to a parser-safe empty-string parameter default
- resolves the current project version after `ProjectRoot` has been resolved
- preserves explicit `-Version` override support
- throws if the project version cannot be resolved
- keeps current-version archive and remote deployment paths unchanged
- adds regression checks for the parser-safe pattern

No monitoring, GUI, lifecycle, API, TLS, SSH authentication, systemd, or PalServer behavior changed.
