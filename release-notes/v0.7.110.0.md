# v0.7.110.0 — Crash Recovery: Watching After a Give-Up

Fourteenth of the "enhancements to features we already have". The last real gap named this session: when
automatic crash recovery gave up, it pinned a "server is DOWN" Critical notice that had no way to ever unpin
itself, unlike the Alert Center's own alerts (v0.7.104.0).

- After giving up, MystTiq now keeps watching (api-run/Desktop sidecar only — the OS-service `service-run`
  mode's own recovery contract is untouched). The moment the server is running again — started by you, not the
  loop — the pinned DOWN notice unpins itself and a plain "server is back up" notice arrives.
- Crash-detect-and-restart monitoring genuinely resumes afterward, on the same profile, not just a one-time
  check.
- Checked with two logic-harness scenarios (including a fresh crash right after the manual recovery, to prove
  monitoring truly resumed) and a new live smoke against the real Windows lifecycle service — not a
  fake/scripted one — including a real process the OS itself recognizes as "PalServer" being started and later
  killed again.

Also, per direction: a GitHub release for 0.7.x and contacting Nexus Mods before any public release are now
v0.8.x roadmap items, not open decisions blocking 0.7.x work.
