# v0.7.101.0 — Crash Alerts: Tell the Admin When the Server Crashes

Sixth of the "enhancements to features we already have". The crash-recovery loop restarted a crashed server but
only wrote to the console: nobody was told it had crashed, come back, or given up.

- A crash now sends a critical notification: "<server>: server crashed, restarting (attempt N of M)", when the
  restart happens, and what the logs say: the likely cause, the first thing to try, and any mod the evidence names
  (a lead, not proof). A crash that leaves no new evidence says so instead of blaming a stale line.
- A successful recovery sends "server is back up"; a failed restart sends a warning saying how many attempts
  remain.
- **Giving up** (too many restarts in the window) sends a pinned critical "server is DOWN, automatic recovery gave
  up", telling the admin it will not restart on its own until they fix the cause and start it.
- Alerts use the normal notification pipeline, so they show on the Notifications page and reach the routes
  already configured (Discord, email, webhooks). The log analysis runs at the moment of the crash and is recorded,
  so the Crash Analyzer shows the same finding.
- Restart behaviour and limits are unchanged, and an alert failure can never stop a restart.
- Verified end to end on a real sidecar with a seeded crash (the real recovery loop and lifecycle service). Not
  verified: delivery to Discord/email/webhooks, the Notifications page rendering, a real Palworld crash, and the
  OS-service supervisor (no alerts there).
