# MystTiq v0.7.46.0 — Console Newest-First Ordering

## Highlights

- **The Console page now shows the most recent activity at the top**, not the bottom — a direct request made while investigating a live connectivity issue.
- **Fixed a real "Operation failed"/won't-connect bug**, diagnosed and repaired live against a real running server: the default profile's launch arguments were missing `-port=8211`, so PalServer was silently binding Steam's default UDP port (27015) instead of the configured one — MystTiq's own readiness check only ever polls 8211, so Start/Restart timed out every time even though the server was actually healthy. This may also have affected real players connecting on the advertised port.
- **Root-caused, but not yet fixed, why the console doesn't capture ongoing PalServer/UE4SS output**: MystTiq only redirects stdout from the `PalServer.exe` wrapper it launches directly, not the `PalServer-Win64-Shipping-Cmd.exe` grandchild process that does the real engine work. Tracked as its own upcoming version.

## Upgrade notes

- The port fix is saved to your configuration but needs two restarts to take effect: the MystTiq backend itself (close/reopen the app) to reload the config, then PalServer (Restart, or Stop then Start) to actually bind the corrected port. Neither restart happens automatically — do it on your own schedule.
- If your players connect using the port you've configured (8211 by default), it's worth confirming with them after the restart that the address still works as expected.
- Export Console now exports in the same newest-first order shown on screen.
