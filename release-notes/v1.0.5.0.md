# v1.0.5.0 — MOD Browser

## Find and install MODs from inside MystTiq

**Mods > MOD Library > MOD Browser** (expanded at the top of the page). Pick a source and search:

- **Downloads and folders**: ZIPs in your Downloads folder, and any other folders you add, that hold a MOD, newest
  first. .7z and .rar archives are skipped.
- **Thunderstore**: Palworld's community there.
- **CurseForge**: with your own API key from console.curseforge.com. It stays on this PC, encrypted, and is sent only to
  CurseForge.
- **GitHub releases**: only repositories you add (owner/repo). An open GitHub search for Palworld MODs is full of
  cheat and malware lures, so MystTiq does not offer one.
- **Nexus Mods**: with the key from the Nexus Mods card. Free accounts get files only through the site's **Mod Manager
  Download** button. Press **Allow MystTiq to Take Mod Manager Download Links** once, and those links open in MystTiq. If
  another program (Vortex, Mod Organizer) has them, MystTiq names it and asks first.

Pick a MOD and one of its files, then **Install Selected File**:
- MystTiq downloads it only from that source's own sites;
- it reads what the archive holds and whether MystTiq can install it;
- you confirm, and it installs through the same validated ZIP install as before, with the server stopped.

## Archives are checked before they are installed

This applies to every install, including a ZIP dropped on the page:

- A UE4SS MOD packed inside a folder (the usual layout) now installs from that folder. Before, its scripts landed one
  folder too deep and did not load. It keeps its own folder's name.
- Archives MystTiq would have installed wrongly are now refused with the reason, and nothing is written:
  - a PAK together with Lua scripts (the scripts were dropped);
  - a PAK that belongs in LogicMods (it went to ~mods);
  - several different PAKs (they overwrote each other);
  - unreal_shimloader packages (Thunderstore's layout);
  - loader DLLs;
  - anything containing a program;
  - archives with no MOD at all.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.4.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
