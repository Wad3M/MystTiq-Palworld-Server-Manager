# MystTiq v0.7.72.0 — Console-Write Hook (Native Console Capture, completed)

## Highlights

- **Completes the native console capture project scoped (foundation-only) in v0.7.57.0.** The
  originally-planned hook target, Unreal's own `FOutputDevice::LogfImpl`, was never a safe or
  reliable option — not exported, unstable offset across builds. Found a better target instead:
  `PalServer-Win64-Shipping-Cmd.exe` imports `WriteConsoleA`/`WriteConsoleW` directly from
  `KERNEL32.dll`, the same low-level path Unreal's own console window writes through. Hooked both
  in the game's own Import Address Table (surgical — only this one importer is touched, unlike a
  shared kernel32 export patch which would affect every DLL in the process).
- **Live-verified safe end-to-end**, never touching the real production server: proven first on an
  isolated clone via a raw process launch, then again through the real shipped code path (install
  via the new API route, launch via MystTiq's own lifecycle service, confirmed
  `/logs/tail` surfaces the new source) using a fully isolated MystTiq instance.
- **A real bug found and fixed along the way**: the capture log initially opened with no file
  sharing at all, so MystTiq's own concurrent tail-read failed for the entire life of the game
  process. Fixed (`_fsopen` with `_SH_DENYWR`) and confirmed live.
- New opt-in capability: `HeadlessConsoleCaptureProxyService` + three routes
  (`GET /server/console-capture`, `POST .../install`, `POST .../uninstall`) to install/remove the
  proxy DLL. Nothing in the lifecycle/launch path calls Install automatically.

## Honest finding

Empirically confirmed, not just predicted from static analysis: Palworld's Windows dedicated
server build genuinely writes nothing further to console once startup finishes. Letting the
isolated test server run several minutes past full readiness, the capture log never grew past its
initial handful of startup lines (memory stats, console-variable echoes). The hook works correctly
and safely — there just isn't ongoing console output to capture. This adds real, previously-
invisible startup diagnostics; it does not solve "the console goes quiet during actual gameplay,"
which appears to have no further fix available short of Palworld's own build re-enabling logging.

## Upgrade notes

- Windows-only; Linux has no DLL-proxy equivalent and the service reports this honestly.
- Not installed automatically on any server, including this machine's own production install —
  requires an explicit `POST /server/console-capture/install` call.
- No Desktop GUI yet (API-level only), matching how some other backend-first capabilities have
  shipped in this project ahead of their own Desktop UI pass.
