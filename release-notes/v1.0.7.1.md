# v1.0.7.1 — Conflicts Refused, Alert Storms Bounded

The second release from the outside quality review (roadmap items Q-4 and Q-11).

## Fixed: work that could run at the same time as a server start, or a save edit

MystTiq already refused a second start, a restore during a save edit, and similar pairs. A few kinds of work still only
checked "is the server running?" and then went ahead, or held no lock at all. Tested on v1.0.7.0: a backup was written
while a server was starting, and a backup and a start sent together both ran.

Now these hold the server, or its world, for their whole run, so whatever arrives in between is refused with the reason
(and they are refused while a start, a stop, an edit or a restore runs):
- **Scheduled and manual backups** hold the world while they zip it, so a backup never captures a save edit, a restore
  or a migration half done. The safety backup an edit takes for itself is part of that edit and is not refused.
- **SteamCMD updates, every MOD change, PalDefender updates and console capture changes** hold the server, so a start
  can't begin while they rewrite its files.

Unattended automation waits for a conflicting operation instead of failing: a nightly backup and a restart scheduled for
the same minute now run one after the other. It waits up to 10 minutes, and the run's record says how long.

## Fixed: a burst of alerts could start hundreds of sends at once

Every Discord, email and webhook send used to start on its own, with no limit. Now:
- **Sends go through a queue** (up to 200 waiting), with two senders working through it.
- **Repeats are combined.** The same alert within 10 minutes is sent once, and when the 10 minutes end, one more
  message says how many times it repeated.
- **Nothing disappears silently.** A send that finds the queue full is dropped and recorded under Delivery with the
  reason, and a send that waited in the queue says how long.
- **Alert Center shows the queue** (beside Delivery): what is waiting, how long the oldest has waited, and how many repeats
  were combined or dropped since MystTiq started.
- **Send Test Notification always goes out**, even twice in a row.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.7.0

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. If the Dashboard says the local service is older, click **Update Service To This Version**. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
