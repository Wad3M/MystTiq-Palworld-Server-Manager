# v1.0.7.3 — Joining Again, and a Lighter Console

## Fixed: kicked while joining

Reported on 2026-10-11 as "unable to connect from a remote computer". MystTiq's identity guard kicked the player 8
seconds after he connected, twice, while his character was still loading.

While a player loads into the world, the server lists them with no character yet. The guard took that for the
new-character screen and kicked at once. It is meant to protect a returning player from being given a new character;
it had worked this way since v1.0.0.1.

Now:
- A player with no character yet gets 90 seconds to finish loading. Once their own character appears, nothing
  happens.
- A player still without a character after 90 seconds is kicked once per stay, so no new character is made over
  their real one.
- A player given a different character is still kicked at once, as before.

If you turned the guard's kick off to get in, you can turn it back on.

## The console does only the work that changed

Roadmap item Q-6 from the outside quality review.

- **Unchanged polls do nothing.** The console's lists were rebuilt line by line every 5 seconds (about 1,000 updates),
  even when nothing had changed. Now a poll with no new lines changes nothing, and a new tail replaces each list in one
  update.
- **Line times stay put.** A log line without its own timestamp used to show a new time on every refresh; it now keeps
  the time MystTiq first saw it.
- **Filtering waits for the page.** The Console page's filters are applied while the page is open (and before an
  export), not in the background.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.7.2

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert. If the Dashboard says the local service is older, click **Update Service To This Version**: the guard fix runs in the service. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
