# MystTiq v0.6.9.0 — Advanced Intelligence, Remote Clients, Simulation & UX Completion

## Highlights

- **Idle Auto-Stop.** A new automation trigger type stops a server that's had 0 online players for a configurable number of minutes — warning players via RCON broadcast first, then doing one final live player recheck immediately before actually stopping, so anyone who joined during the countdown isn't disconnected.
- This is a narrow, single-server, opt-in convenience — deliberately scoped apart from the future full adaptive fleet resource-policy system planned for v0.8.x, so it doesn't duplicate that later work.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- `POST`/`PUT /api/v1/automation/rules` accept a new `trigger.kind` value (`"IdleEmpty"`) with an additive `idleThresholdMinutes` field; existing trigger kinds (`DailyTime`, `Interval`) are unchanged. Automation rule responses gain an additive `idleSinceUtc` field.
