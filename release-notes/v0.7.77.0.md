# MystTiq v0.7.77.0 — MOD/Workshop Detection Fixes, UE4SS Version via Hash, Per-MOD Repair

## Highlights

- **Fixed a real detection bug**: a Steam Workshop item that's actually the UE4SS runtime itself
  (not a mod) always showed "NOT INSTALLED" because the check looked in the mod inventory, which
  by definition never contains the runtime. Now checks whether UE4SS is actually installed instead.
- **UE4SS version now shown via hash match** instead of "version metadata unavailable" — when the
  real active `UE4SS.dll` is byte-identical (SHA-256) to a locally-discoverable Steam Workshop
  copy, reports that copy's own declared version, clearly labeled as hash-matched. Found and fixed
  a second real bug along the way: two different `UE4SS.dll` files existed side by side (a stale
  one, the real active one), and version detection was reading the wrong one.
- **PalSchema and QualityOfLife properly imported** into the real active mods folder at direct
  request — `mods.txt` now lists 8 mods, matching what was remembered from v0.2.16.4.
  QualityOfLife's `.pak` files had been manually quarantined during a past troubleshooting session
  and never restored; now live again.
- **New: per-MOD Repair / Re-install.** Finds a matching local Steam Workshop source and does a
  clean delete-then-reimport (reusing the existing delete snapshot for a safety net) — fixes a MOD
  reported as incomplete/misconfigured. Fails honestly, without touching anything, when no local
  Workshop source is known for a MOD.

## Upgrade notes

- No configuration changes. Touches `MystTiq.HeadlessHost` and `MystTiq.Desktop`.
- Everything in this version was live-verified against the real production install — no isolated
  clone needed, since none of it touches player save data.
