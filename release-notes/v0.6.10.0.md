# MystTiq v0.6.10.0 — Clone World & Extended Live Verification

## Highlights

- **Clone World**: a real, new admin feature that duplicates a server profile's entire installation (game binaries + world/config) into a brand-new, independent profile with non-colliding ports — a full copy, not a shared shortcut, so future updates to one instance never affect the other.
- **A real bug found and fixed along the way**: editing the game's own settings file port alone doesn't actually change which port PalServer binds to — the game's `-port=` launch flag is what really controls it. Clone World now sets both, verified live with two real instances running on their correct, distinct ports simultaneously.
- **Extended live verification this session hadn't yet performed**: a sustained real PalServer run, two genuinely simultaneous instances confirmed stable over 5 minutes, a real authenticated cross-machine connection from Windows to an independently-running Linux MystTiq instance, and full end-to-end proof that Idle Auto-Stop (v0.6.9.0) really works against a live server — closing that milestone's previously-disclosed verification gap.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- New, additive route: `POST /server/clone` (per-profile). Adding a profile via Clone World follows the same "requires a MystTiq process restart" convention as the existing `POST /servers` (add server) route — nothing new to learn if you've used that already.

## What's deferred

- Cloning directly to a different machine or platform in one operation — the clone always targets a local sibling directory on the current host.
- Automatic non-port conflict resolution (MOD state, save-slot naming) — the clone is a byte-for-byte copy of everything else.

See [`docs/architecture/v0.6.10.0-clone-world-live-verification.md`](../docs/architecture/v0.6.10.0-clone-world-live-verification.md) for full verification detail, including two real observations disclosed but not chased down this pass (a consistent graceful-shutdown-timeout fallback, and a stale-crash-state edge case after force-killing the management process itself).
