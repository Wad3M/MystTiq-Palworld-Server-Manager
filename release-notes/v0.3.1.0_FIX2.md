# MystTiq Palworld Server Manager v0.3.1.0 FIX2

## PowerShell Build-Gate Exit Semantics Hotfix

The v0.3.1.0 FIX1 gate produced a false failure:

```text
Validation summary: 0 error(s), 0 warning(s).
Release validation passed.
[FAIL] Build :: Release validation
```

The harness invoked `Build.ps1` successfully but then inspected `$LASTEXITCODE`. That variable represents the exit code of the most recent native executable and can retain an unrelated/stale value after a PowerShell script completes successfully.

FIX2:

- treats a PowerShell build action as PASS when it completes without throwing
- treats it as FAIL when `Build.ps1` throws
- applies the same semantics to Validate, DesktopWindows and DesktopLinux
- adds a regression assertion preventing `$LASTEXITCODE -eq 0` from being used for these PowerShell build actions

No Avalonia application, headless service, WPF, API, lifecycle, TLS, systemd or PalServer behavior changed.
