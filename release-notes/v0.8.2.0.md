# v0.8.2.0 — Service Mode Fixes

First release on top of the accepted baseline, v0.8.1.0.

These fixes apply when MystTiq runs as an installed Windows service or Linux systemd service. They don't affect the
Desktop's own background service.

- **Servers on a custom game port now work in service mode.** Service mode always waited for port 8211. A server on
  any other port was reported as "failed to start", and the service then shut itself down.
- **Only one watcher per crash.** The service and its built-in management API both watched the same server, so a
  single crash could be restarted twice. Only the service watches it now.
- **Crash alerts in service mode.** Crashes, restarts and give-ups now send the same notifications, and follow the same
  mute settings, as in the Desktop. The restart window and the give-up are remembered across restarts.
- **"Back up" after the OS restarts the service.** Service mode can stop after too many crashes, and Windows or
  systemd then starts it again. Once the server is ready again, MystTiq now says so and unpins the "server is DOWN"
  notice. Repeated give-ups no longer leave several DOWN notices pinned.
- Checked with two new logic-harness scenarios and a new end-to-end service-mode smoke test on the published build.
  The smoke uses a stand-in PalServer on a custom port. Plus the full test gate.
