# v0.2.15.7 — Unified Runtime State Architecture

## Status
Release candidate. Official baseline remains v0.2.15.6 until compile and runtime validation complete.

## Purpose
Replace fragmented runtime-loaded ownership with one session-aware source of truth shared by MOD inventory and all consumers of that inventory.

## Implementation
- Added `RuntimeStateService` and immutable `RuntimeStateSnapshot`.
- New PalServer sessions establish an input boundary at the current UE4SS log length before startup reconciliation.
- Only runtime evidence written after that boundary is eligible to mark a MOD loaded for the new session.
- Positive current-session evidence remains latched through later scans and UE4SS log rotation/truncation.
- Server exit clears session runtime evidence.
- `ModScannerService` observes the runtime service and applies its shared snapshot instead of assigning `LoadedByUe4ss` from a single resolver snapshot.
- Removed the MOD Library's private `sessionRuntimeLoadedAliases` state and its UI-side reconciliation method.
- MOD Runtime diagnostics expose the current runtime session ID, state revision, loaded alias count, and last observation time.

## Compatibility
No configuration-file format changes. No MOD files are moved, enabled, disabled, deleted, or rewritten by the runtime-state service.


## FIX1 — Compile hotfix
The first v0.2.15.7 compile exposed one stale identifier left by the runtime-state constructor migration and one unused nested verifier field. FIX1 changes no runtime architecture or UI behavior.

- `ModService(AppSettings, Ue4ssRuntimeResolver)` now chains through the declared `ue4ssResolver` parameter.
- Removed the unused `GenericModVerifier.runtimeState` field that produced CS8618/CS0169 warnings.
- Added a regression-harness check for the constructor chain.

Compile acceptance remains `Build.ps1 Clean`, `Validate`, and `All`, followed by the v0.2.15.7 logic harness and runtime acceptance tests.

## FIX2 — Current-session runtime reacquisition
Runtime testing showed the first unified-state implementation could remain **Not Loaded** and leave Dashboard health at **Runtime Unverified** when UE4SS recreated/replaced its log during startup. A byte offset alone could not identify that replacement if the new file had already grown beyond the old baseline.

FIX2 keeps the unified architecture and hardens its input boundary:
- capture safe pre-start baselines for all discovered UE4SS logs;
- track each log cursor with creation identity plus byte offset;
- read a newly created/replaced current-session log from byte zero;
- observe all `UE4SS*.log` candidates rather than one resolver-selected log;
- synchronize positive shared runtime evidence into stale Dashboard **Runtime Unverified** rows;
- make **REFRESH INFO** a local/runtime refresh only, leaving browser searches exclusively on **SEARCH ONLINE**.

No MOD file state is changed by these corrections. Historical log bytes that existed before the PalServer session boundary remain excluded from positive current-session load evidence.
