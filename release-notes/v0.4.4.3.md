# MystTiq v0.4.4.3 — Local Sidecar Auto-Connect & Runtime Acceptance Fix

## Status
Release candidate. Official promoted baseline remains v0.4.3.1 until the complete build, logic, regression, Windows/Linux packaging, runtime-smoke and acceptance gates pass.

## Runtime defects corrected
- Removed the Linux-only restriction from `mysttiq-server api-run`; the local management API now composes a Windows lifecycle implementation on Windows and the existing Linux implementation on Linux.
- Added Windows PalServer process/session inspection and lifecycle start/stop/restart support in Core.
- Added platform-aware headless configuration defaults and absolute-path validation for Windows and Linux.
- The Avalonia desktop publish now includes a matching self-contained `headless` sidecar directory.
- The desktop now bootstraps the local headless API when a local PalServer installation is discovered but no persistent management API is reachable. The GUI still calls the API for lifecycle/configuration/monitoring operations; it does not own PalServer operations.
- The local sidecar is not tied to the GUI window lifetime, so closing the GUI does not implicitly terminate the management API or PalServer.
- Legacy `settings-v2.1.json` is used only for installation discovery and is never passed to the schema-v2 headless configuration loader.

## GUI consistency
- Page activation now refreshes the backing ViewModel/API data for Configuration, Backups, Console/Activity, Inspector, Players/Guilds/Bases, MODs, Doctor and Diagnostics instead of waiting for a separate manual refresh.
- Standardized top-level navigation groups and expanded child rows to a 44-pixel navigation row standard with zero expanded-item gap/indent.
- Preserved the shared Avalonia styling path for Windows and Linux.

## Test additions
- `Test-v0.4.4.3-Logic.ps1` adds Windows headless composition, sidecar packaging/bootstrap, platform-aware configuration and standardized navigation checks.
- `Test-v0.4.4.3-RuntimeSmoke.ps1` launches the packaged Windows sidecar on an isolated test port and verifies `/healthz`, aggregate status polling, editable configuration and server-distribution endpoints.
- Linux acceptance and production-readiness scripts are version-matched to v0.4.4.3.

## v0.4.4.3 acceptance focus
- A local loopback sidecar advertising `authentication=false` is selected before LAN candidates and connected automatically.
- LAN/remote services never inherit the local trust rule and continue through bearer-token/certificate validation.
- The packaging test validates the real self-contained sidecar publish commands.

## Candidate harness/clean correction
- Corrected v0.4.4.3 logic assertions that accidentally still expected v0.4.4.2 in the authoritative version, README, roadmap and testing-command checks.
- `Build.ps1 Clean` now stops only auto-launched MystTiq development processes running from this repository's `artifacts` tree, then removes artifacts with terminating error handling. PalServer and installed services outside the development artifacts tree are not stopped.
- Clean now throws if the artifacts directory survives cleanup, preventing a misleading `Clean complete` followed by repository-hygiene validation failures.
