# v0.6.4.0 — Troubleshooting & Diagnostics Platform

See `docs/architecture/v0.6.4.0-troubleshooting-diagnostics-platform.md` for the full contract writeup and deferred list.

## Unified Doctor/Environment diagnostics

New `HeadlessDiagnosticsService` unifies `HeadlessDoctorService` and `HeadlessEnvironmentChecklistService` (both kept unchanged, composition not rewrite) into one `DiagnosticFinding` list, de-duplicating the 3 facts both independently checked. Verified live: each fact appears exactly once with correct rollup math.

## Real Overall Health

The Dashboard's health badge previously computed independently from raw lifecycle status, reflecting neither Doctor nor Environment findings. It now derives from the unified report — `ServerHealthState`, an enum built in v0.6.0.0 and never consumed until now, is finally real.

## Fix Automatically & Recheck

Real, working fixes for backup-root creation and SteamCMD/PalServer install (reusing the existing distribution-update route); everything else stays honestly gated. Per-check Recheck re-runs just the owning source and returns the one updated finding.

## Local-PC diagnostics

New, entirely client-side: a staged DNS → TCP → TLS → HTTP probe against the selected connection profile, replacing a single opaque exception message with a specific, staged diagnosis. Plus .NET runtime and local disk space checks. Confirmed via research this is genuinely new — the existing network diagnostics only ever checked the server's own inbound state.

## Verification

- `scripts/Test-v0.6.4.0-Logic.ps1 -RunBuild`: 20 contract-presence/regression checks, the frozen v0.6.3.0 regression gate, `Build.ps1 Build -Configuration Release`, and the full v0.5.1.5 runtime smoke suite — all green.
- Manual, against a real isolated instance: confirmed the 3 overlapping facts merge into single findings with correct math; deleted the backup root and confirmed Fix Automatically genuinely recreated it; confirmed Fix on SteamCMD attempted a real install and reported an honest failure; confirmed Fix on a non-fixable finding (UE4SS) returned its real "not supported" reason rather than a silent no-op; confirmed Recheck correctly reflects a fix that just landed.

Promotion requires clean validation, logic, Windows desktop and headless builds, and Windows runtime smoke. Linux verification remains an open gap carried forward from v0.6.2.0/v0.6.3.0.
