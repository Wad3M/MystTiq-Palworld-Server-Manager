# MystTiq v0.6.6.0 — Player Registry, Activity Intelligence & World Explorer 2

## Highlights

- **A real persistent Player Registry.** `HeadlessPlayerRegistryService` tracks first/last seen, total sessions, cumulative tracked playtime, and real Steam ID/Player UID mapping for every player MystTiq has ever observed — captured directly from live Palworld REST data that was previously seen on every poll and never persisted.
- **Join/leave history.** Every presence transition is recorded as a bounded, persisted event (`GET /api/v1/players/registry/events`), with playtime accrual capped per observation tick so a large gap between polls (a MystTiq restart, nobody connected) can never be misattributed as playtime.
- **No new background timer.** The registry samples on the same `/status/poll` cadence `HeadlessHistoricalMetricsService` already established in v0.6.1.0 for CPU/RAM/player-count history — one consistent pattern, not a second one.
- **Abandoned-base detection**, derived cheaply from the existing guild explorer's orphaned-guild data.

## Upgrade notes

- No configuration schema change — an existing v3 `mysttiq.json` loads unchanged.
- New, additive routes: `GET /api/v1/players/registry`, `GET /api/v1/players/registry/events`.
- `GET /api/v1/world/players-guilds` gains an additive `abandonedBaseIds` field; existing consumers that ignore unknown fields are unaffected.
