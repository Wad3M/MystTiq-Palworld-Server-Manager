# v1.0.7.0 — Errors Stay Visible, Nothing Is Lost

The first release from the outside quality review (roadmap items Q-1, Q-2, Q-3 and Q-5).

## Fixed: a damaged saved list could wipe your accounts

MystTiq keeps its own lists in small files: user accounts, API tokens, automation rules, kits, alert and anti-cheat
rules, notification channels, the Discord bot, the whitelist, temporary bans, teleport points, player notes and the
player history, among others. If one of those files could not be read (cut short by a power cut, for example), MystTiq
used to start with that list empty, and the next change saved the empty list over the file. Tested on v1.0.6.1: three
accounts, a damaged `users.json`, a restart, and one new account left only that one.

Now:
- **Every save keeps the file it replaces** as a last good copy beside it (`.last-good`).
- **A file that cannot be read is copied aside** (`.unreadable-` and the time) and never overwritten unseen.
- **The last good copy is loaded** when there is one, and you get a warning saying so.
- **With no good copy, changes to that list are refused**, with the reason, so nothing is written over it. You get a
  pinned alert with an **Open Repair** button. It opens Server Doctor, where that list is marked; its fix starts the list
  empty, keeping the unreadable file beside it. If you have a good copy, put it back instead and restart the MystTiq
  service.
- Logs MystTiq rebuilds by itself (run histories, events) just start empty and say so.

Kits are not given and temporary bans are not applied while their lists are refused, so a kit is never given twice and
a ban never loses its end. The unique-names guard stands down rather than hand names to whoever joins first.

## Fixed: an error could close the app without a trace

- **Errors are recorded and shown.** An error nobody caught used to close the desktop app and leave nothing behind. It is
  now written to `%LOCALAPPDATA%\MystTiq\crashes` and shown in a red banner on every page, and the app stays open where
  it can. The service writes such errors to its own output and to the activity log.
- **Background work is tracked.** Work the service starts and does not wait for (address checks, backup world days, the
  world clock, Discord, outside notifications, update checks) used to drop its errors. It now logs a failure once,
  stops at shutdown, and says what is still running.
- **An automation rule never runs twice at once.** A rule still running when it comes due again is recorded as Skipped.

## Smaller fixes

- A file another program holds for a moment is retried; anything else (a missing folder, a full disk) fails at once
  instead of after 2.5 s. When the server's state file stays held, the error says what to check.
- The Launcher's Default preset description no longer mentions a diagnostic log (Default adds no start options since
  v1.0.6.1).

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.6.1

Back up your server data and configuration, then extract into a new application folder (or use **Update** on the MystTiq row of the Update Center once this release is published). Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Nothing to convert: the first save of each list starts its last good copy. If the Dashboard says the local service is older, click **Update Service To This Version**. Coming from an older version, also read the notes of the versions in between.

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
