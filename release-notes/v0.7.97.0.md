# v0.7.97.0 — Crash Analyzer: Known Causes, Fixes, and No More Repeats

Third of the "enhancements to features we already have". The headless Crash Analyzer was a keyword counter.

- Findings now come from a catalog of 12 known failure signatures (missing runtime library, out of memory,
  stack overflow, access violation, disk full, port in use, save read/write failure, shutdown failure, hang,
  UE4SS or mod script error, Steam init, fatal engine error). Each says what it usually means and what to try.
- Fixed false findings: the old needle for out-of-memory also matched "room" and "zoom", and any line that
  merely mentioned UE4SS was flagged. On a healthy server's real log the old logic would have raised a
  warning on 130 lines; the new analyzer reports none.
- MystTiq's own "process exited with code ..." lines are now understood: access violation, stack overflow,
  missing DLL, fatal failure, and Linux 137/139/134. Exit code 0 and -1 mean nothing.
- Installed mods named in the evidence are listed (as a lead, not proof) and put first in the isolation plan.
- Findings are marked NEW or already reported, so running Analyze again on the same logs does not re-raise
  old lines; a fresh crash makes only its own finding new. First and last seen come from the log timestamps.
- The Crash Analyzer page shows the selected finding's cause, fixes, mods, timing and evidence.
- Another server's crash findings no longer linger after a tab switch.
- Reports saved before this version still load. The first analysis after upgrading marks everything new.
- Not verified: how the page renders (no GUI automation), and the fix text against a real Palworld crash.
