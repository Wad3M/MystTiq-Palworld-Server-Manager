# v1.0.0.2 — Unique Player Names

## Players

- **Each player name belongs to one account.** A name belongs to the first player seen using it. Upper and lower case
  count as the same name, so `Wade`, `wade` and `WADE` are one name. A player who joins with a name that belongs to someone
  else is turned away, and you get a notification saying who it was and whose name they used.
- On the Players page, the new **Unique player names** card lists every name and who owns it. You can:
  - reserve a name for a player's Steam ID before they join, for example your own;
  - block a name for everyone (leave the Steam ID empty), for example "Admin";
  - release a name so the next player to use it owns it;
  - choose whether a player using someone else's name is kicked or only reported;
  - see the players turned away recently.
- The players MystTiq already knows keep their names: the first time this version runs, each name goes to the player who
  used it first.
- Palworld only reports a player's name once they are in the world, so a player turned away has already made a character
  with that name. Delete that character on the Players page, and they can make a new one with another name.

## Fixed

- **Save** buttons on admin cards (for example **Save Whitelist**) could stay greyed out after MystTiq connected, until the
  app was restarted. They now become available again as soon as MystTiq has finished loading.

## Downloads

Use **Windows-x64.zip** for the self-contained Avalonia desktop and its matching headless service. Extract the whole folder and run `MystTiq.Desktop.exe`; retain `headless` alongside it. **FullSource.zip** is the developer source package. Check downloaded ZIPs against `SHA256SUMS.txt`.

## Upgrading from v1.0.0.1 or v1.0.0.0

Back up your server data and configuration, then extract into a new application folder. Keep the existing service/configuration/data locations and the matching `headless` folder; verify your connection and language choice before resuming administration. Unique names are on as soon as this version runs. Coming from v1.0.0.0, also read the [v1.0.0.1 notes](v1.0.0.1.md).

Back up server data before upgrading. Keep application files separate from server data; closing the desktop does not stop a managed server until you choose Exit from the tray.
