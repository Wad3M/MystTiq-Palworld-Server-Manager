# MystTiq v0.4.6.2 — PalServer Window Suppression & Live Dashboard Parity

Official baseline: v0.4.5.1.

This revision closes the local GUI-to-headless management-session gap that prevented Start Server from reaching the lifecycle endpoint even when a process answered on `127.0.0.1:8213`.

## Key changes

- `/healthz` now reports backend identity, API contract version, application version, platform, authentication and TLS state.
- Desktop connection establishment validates that handshake and then uses the single aggregate `/api/v1/status/poll` endpoint for the authoritative initial sample.
- GUI-owned sidecars start with `--desktop-sidecar`, which forces loopback-only, unauthenticated and non-TLS local mode. Remote/LAN API security remains unchanged.
- If the configured loopback endpoint is occupied by an older or incompatible process, the desktop launches its packaged sidecar on a private free loopback port and connects to that exact endpoint.
- Lifecycle post-operation refresh also uses the aggregate polling contract.
- Default PalServer launch arguments now match the established v0.2 Windows launcher and include `-log -logformat=text`; custom headless configuration still takes precedence.
- Error text includes the actual endpoint and backend-session detail so Start Server failures are actionable.
- The v0.2.16.4 parity audit is carried forward as `docs/GUI_PARITY_v0.4.6.2.md`.

Promotion requires the full clean/validate/logic/build/runtime gate plus manual acceptance that the GUI reaches Connected and Start Server invokes the Windows lifecycle path.


### Console redirection

On Windows, MystTiq starts PalServer without Unreal's separate `-log` window. The default launch uses `-stdout -FullStdOutLogOutput -logformat=text`; stdout/stderr are captured by the lifecycle service and surfaced through the Live Console page.
