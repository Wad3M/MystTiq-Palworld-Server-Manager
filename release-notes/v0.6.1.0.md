# v0.6.1.0 — Advanced Administration, Automation & Analytics Platform

Merges what the grouped roadmap originally split across three separate milestones (Guardian backups, Automation/RBAC, Analytics) into one pass, at the user's explicit direction — the roadmap's own "Sizing note" flagged this as roughly 4x v0.6.0.0's size and instructed a real, working slice of each area rather than everything at full depth. See `docs/architecture/v0.6.1.0-advanced-administration-automation.md` for the full contract writeup and per-area deferred list.

## Automation engine — the app's first background loop

- New `MystTiq.Core/Automation/` contracts: `AutomationRule`, `AutomationTrigger` (`DailyTime`/`Interval`, with jitter), `AutomationCondition`, `AutomationAction` (`CreateBackup`/`StartServer`/`StopServer`/`RestartServer`/`SendNotification`/`SendRconCommand`), `AutomationRunRecord` (`Scheduled`/`Running`/`Completed`/`Failed`/`Missed`/`Skipped`/`Cancelled`).
- `HeadlessAutomationService` runs the one and only background loop in the app — a `PeriodicTimer` on a 15s tick, started/stopped alongside the API host itself. Overdue rules (host was asleep) record `Missed` and reschedule rather than firing very late.
- `StopServer`/`RestartServer` actions can broadcast RCON warning-countdown announcements before acting.

## A real gap found and fixed: lifecycle routes now use the OperationCoordinator

The manual `/api/v1/server/start|stop|restart|force-stop` routes previously guarded themselves with only a private semaphore — never the `OperationCoordinator` introduced in v0.6.0.0, meaning a restart could race an in-flight World Transaction/Guild/Base Apply undetected. Retrofitted onto the coordinator with new resource keys `"lifecycle"` (Stop) and `"lifecycle"+"world-mutation"` (Start/Restart), removing the now-redundant local semaphore entirely.

## Backup classes

`BackupClass { Manual, Scheduled, Emergency, Safety }`, persisted via a classification manifest. Unclassified/legacy backups default to `Manual`. Retention pruning now defaults to `Scheduled`-only — Manual/Emergency/Safety backups are protected from routine cleanup unless an admin explicitly opts them in.

## RBAC — minimal, fully backward-compatible

`MystTiqRole`/`MystTiqPrincipal` in `MystTiq.Core/Security/`, enforced via a new `RequireRole` Minimal API endpoint filter. **The existing single shared bearer token keeps working completely unchanged** — it resolves to a full-access `LegacyOwner` principal before the new RBAC principal store is even consulted, and when authentication is disabled (today's default) every request still resolves to `LegacyOwner`. New named principals (Viewer/Operator/Admin/Owner, with an optional expiry for temporary guest grants) are additive. Includes an in-memory auth-abuse lockout guard.

## Analytics — Alert Center, disk-space prediction, honest graph gaps

`HeadlessAlertCenterService` evaluates on the automation loop's tick: sustained-high-CPU/memory thresholds, low-disk-space, and a real linear disk-space-exhaustion projection — all routed through the existing Notification Center (`HeadlessNotificationService.Create`), not a parallel pipeline. Historical metrics now surface gap and restart markers so an offline period no longer draws as a straight line on the Desktop chart.

## Notification routing

A real, working `Webhook` channel (POST + retry-once) alongside typed `Discord`/`Email` stubs that log "not implemented" rather than silently dropping, plus reusable notification templates consumed by the automation `SendNotification` action.

## Advanced administration

`PlayerFlag` (Watchlisted/Banned/Trusted) annotation on player metadata — data only in this pass, not auto-enforced.

## Desktop

Three new pages under System — Automation, Alert Center, Security — following the existing page/DTO/API-client conventions. `WhoAmI` disables buttons the current principal's role can't use.
